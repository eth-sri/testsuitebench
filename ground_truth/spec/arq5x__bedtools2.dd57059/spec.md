# Executable behavioral specification

The required artifact is one command-line program named `executable`. It is a multicall genomic-interval utility: the first argument selects a subcommand and the remaining arguments are that subcommand's options. Unless a section says otherwise, successful text commands exit 0, write tab-separated records terminated by `\n` to standard output, and write no diagnostic. Errors exit nonzero and write an informative diagnostic to standard error. All behavior below is normative.

## Spec 1

Command dispatch and basic interface. Running `executable`, `executable --help`, or `executable -h` must print a successful top-level help message containing the literal phrases `bedtools is a powerful toolset for genome arithmetic`, `Usage:     bedtools <subcommand>`, and the names `intersect`, `merge`, `subtract`, and `coverage`. `executable --version` must succeed and print a line containing `bedtools` and a version. An unknown subcommand must fail and produce a nonempty diagnostic. Implement these subcommands and aliases exactly as named in later sections: `intersect`, `closest`, `coverage`, `genomecov`, `merge`, `map`, `subtract`, `slop`, `shift`, `complement`, `flank`, `sort`, `cluster`, `spacing`, `makewindows`, `multiinter`, `unionbedg`, `annotate`, `getfasta`, `maskfasta`, `nuc`, `groupby`, `jaccard`, `fisher`, `reldist`, `random`, `sample`, `shuffle`, `split`, `expand`, `bamtobed`, `bed12tobed6`, `bedtobam`, `bamtofastq`, `pairtobed`, `pairtopair`, `window`, `multicov`, `igv`, `links`, `summary`, and `tag`.

## Spec 2

Coordinate and record model. BED input is tab-separated with at least three columns: chromosome, zero-based start, and exclusive end. A positive overlap exists exactly when `max(startA,startB) < min(endA,endB)`; touching endpoints do not overlap. Its length is `min(endA,endB)-max(startA,startB)`. Coordinates and arithmetic must support ordinary decimal integer tokens at signed 64-bit scale without 32-bit overflow. Acceptance of scientific notation in BED coordinates is command-specific. `sort` rejects a start of `1e10` with `Unexpected file format.  Please use tab-delimited BED, GFF, or VCF. Perhaps you have non-integer starts or ends at line 1?`, whereas `merge` accepts `chr1\t8e02\t830`, interprets the start as 800, and emits `chr1\t800\t830`. A genome file is tab-separated chromosome and nonnegative length; its line order defines chromosome order. BED6 has name, score, and strand in columns 4, 5, and 6. Valid strand field values include `+`, `-`, and `*`, although individual stranded operations can treat `*` as unknown. BED12 has block count in column 10 and comma-separated block sizes and relative starts in columns 11 and 12.

GFF/GTF is nine tab-separated fields with one-based inclusive start/end in columns 4/5 and is internally `[start-1,end)`. VCF uses chromosome and one-based POS; its internal start is `POS-1`. A normal VCF span has `length(REF)`. For a symbolic structural allele, scan the semicolon-delimited INFO entries from left to right and use the first recognized `SVLEN` or `END`. An `END=n` entry gives `[POS-1,n)`. An `SVLEN` entry gives a span of its absolute value; for a comma-separated list, use the value having the greatest absolute magnitude. Consequently, `SVLEN=-389,-4611;END=253195` at POS 252806 spans 4,611 bases and the later END does not override it, whereas an END appearing before SVLEN does take precedence. Thus a record ending at 51 and one starting at one-based POS 52 are merely adjacent. Whenever an operation promises the original record, preserve every original field rather than converting GFF/VCF to BED. Commands whose declared output is BED use zero-based BED geometry; format-preserving output keeps the source coordinate convention.

SAM/BAM/CRAM alignment spans consume CIGAR `M`, `=`, `X`, `D`, and `N`; POS is one-based and FLAG 16 means minus strand. BAM and CRAM output must be valid binary, not SAM text. BAM input may be streamed through stdin and may lack textual `@` headers. CRAM must work both with an externally configured reference and when its records can be decoded without one.

## Spec 3

Input, headers, validation, and ordering. Wherever a filename is accepted, plain text and gzip-compressed content are accepted, including concatenated gzip members and mixtures of compressed/uncompressed files, except that an ordinary gzip-compressed `getfasta -fi` FASTA is rejected as specified in Spec 25. `-`, `stdin`, and an omitted primary `-i` on commands that permit implicit input mean standard input. Empty files are valid and yield the command's natural empty/zero result. Accept CRLF records. Data records within one delimited text input must have a uniform field count. For `sort`, trailing empty fields are discarded rather than counted: the lone stdin record `chr1\t0\t2\t` succeeds with status 0, produces `chr1\t0\t2`, and writes no diagnostic.

Lines beginning `#`, `track`, `browser`, and a recognized column header are metadata rather than intervals; normally suppress them, while `-header` copies the primary/A input header unchanged before results. For `intersect`, a textual VCF must have recognized VCF header metadata before its data records; a syntactically VCF-shaped eight-column record alone is not enough for format detection. A canonical header consisting of `##fileformat=VCFv4.2` followed by `#CHROM\tPOS\tID\tREF\tALT\tQUAL\tFILTER\tINFO` is recognized. Without that header, both `chr1\t6\tv\tAAAA\tT\t.\t.\t.` and `chr1\t101\tid\tN\t<DEL>\t.\t.\tSVLEN=-10,-20;END=105` used as A cause `intersect` to exit 1 with no stdout; stderr begins `Error: unable to open file or unable to determine types for file PATH`. With the canonical header, the former record intersected by BED `chr1\t7\t12` exits 0 and emits exactly `chr1\t6\tv\tAAAA\tT\t.\t.\t.`. The latter under `-c` against BED records `chr1\t104\t105\tnear` and `chr1\t119\t120\tfar` exits 0 and emits exactly `chr1\t101\tid\tN\t<DEL>\t.\t.\tSVLEN=-10,-20;END=105\t2`.

Reject negative BED coordinates, start greater than end, nonnumeric coordinates, and space-delimited pseudo-BED. `sort -i -` fails with status 1 and no stdout for each of these malformed first records, but its exact diagnostic depends on the defect: `chr1\t-1\t2` and `chr1\tx\t2` produce `Unexpected file format.  Please use tab-delimited BED, GFF, or VCF. Perhaps you have non-integer starts or ends at line 1?`; `chr1\t5\t2` produces `Error: malformed BED entry at line 1. Start was greater than end. Exiting.`; and `chr1 0 2` produces `It looks as though you have less than 3 columns at line 1 in file -.  Are you sure your files are tab-delimited?`. There is separate validation behavior for `merge -i -`. Given `chr1\t.\t2` or the space-delimited `chr1 1 2`, it fails with status 1, no stdout, and a stderr first line exactly `Error: unable to open file or unable to determine types for file -`. If a valid first record is followed by either a negative-coordinate record or one whose start exceeds its end, `merge` instead exits 1 with no stdout and writes exactly `Error: Invalid record in file -. Record is ` followed on the next line by the offending record. Thus the respective two-line diagnostics end in `chr1\t-1\t10` and `chr1\t10\t5`. For `sort -i PATH`, a one-line file containing `not an interval` fails with status 1, no stdout, and `It looks as though you have less than 3 columns at line 1 in file PATH.  Are you sure your files are tab-delimited?`. A missing file fails and names the path; specifically, `intersect -a PATH -b B -sorted` exits 1 with no stdout and stderr exactly `Error: Unable to open file PATH. Exiting.` when PATH does not exist. `merge` uses wording containing `Unable to open file`.

Options taking fractions validate their documented range `(0,1]`; counts/lengths must be sensible positive integers where required. On commands that expose `-iobuf`, accepted input-buffer sizes are positive values at least 8 bytes, optionally suffixed `K`, `M`, or `G`, including `2G`; buffer size cannot change output. Invalid `-iobuf` uses these exact final stderr lines and exits 1 with no stdout: a bare option gives `***** ERROR: -iobuf option given, but size of input buffer not specified. *****`; an unsupported suffix, as in `20L`, gives `***** ERROR: Unrecognized memory buffer size suffix 'L' given. *****`; a value below 8 gives `***** ERROR: specified buffer size is too small. *****`; and a nonnumeric portion, as in `beerM`, gives `***** ERROR: argument passed to -iobuf is not numeric. *****`. `sort` is an exception and does not expose this option: `sort -i A -iobuf 2G` exits 1 with no stdout and reports both `*****ERROR: Unrecognized parameter: -iobuf *****` and `*****ERROR: Unrecognized parameter: 2G *****` before its usage text.

Commands using `-sorted`, and commands such as `closest` that inherently require sorted input, normally verify nondecreasing chromosome/start order within every stream. There is a match-only `intersect` short circuit: `intersect -a A -b B -sorted -g GENOME` with no reporting-mode option and an empty B exits 0 with empty stdout and stderr without validating A's order. In particular, A records `chr2\t0\t1` then `chr1\t0\t1`, an empty B, and a genome ordered `chr1` then `chr2` produce no different-sort-order error. Otherwise, with `-g`, genome order is authoritative. Without it, infer chromosome order from streams but reject mutually inconsistent orders, including lexical-versus-natural contradictions and contradictions exposed by chromosomes present in only one file. A coordinate/start or chromosome decrease within one stream exits 1 with no stdout and writes exactly `Error: Sorted input specified, but the file FILE has the following out of order record`, followed on the next line by the offending record. If `-g GENOME` instead reveals that a stream's chromosome order differs from the genome file, the first line is exactly `Error: Sorted input specified, but the file FILE has the following record with a different sort order than the genomeFile GENOME`, again followed by the offending record.

Chromosome-order conflicts use different legacy diagnostics and select the offending file/record as follows. When two streams establish conflicting chromosome orders, diagnose the numerically ordered stream rather than whichever stream happened to be A: both `closest -a alpha_all.bed -b num_all.bed` and its A/B reversal fail with exactly `ERROR: chromosome sort ordering for file num_all.bed is inconsistent with other files. Record was:` followed by `chr10\t10\t20`; the `alpha_missing.bed`/`num_missing.bed` pair analogously names `num_missing.bed` and `chr11\t10\t20`. `closest -a sq1.bed -b sdb1.bed` names `sq1.bed` and `chr12\t10\t20`. The same selection applies to `intersect -sorted`.

When no consistent order can be inferred and a stream is not lexical, the exact diagnostic is:

```text
ERROR: Sort order was unspecified, and file FILE is not sorted lexicographically.
       Please rerun with the -g option for a genome file.
       See documentation for details.
```

For `closest -a q1a_num.bed -b db1_num.bed db2_numBackwards.bed`, `FILE` is `q1a_num.bed`; after inserting `db2_num.bed` before a final `db3_numBackwards.bed`, `FILE` is `db3_numBackwards.bed`. These chromosome-order errors exit with status 1 and produce no stdout. Inconsistent `chr` prefixes and leading-zero names such as `chr01` produce warnings; zeros after an underscore are ordinary names.

## Spec 4

Shared overlap modifiers. On overlap-oriented commands, `-s` requires equal recognized strands and `-S` requires opposite recognized strands. Only `+` and `-` participate in these comparisons: `*` does not satisfy either modifier, including a `*`/`*` pair under `-s`. Missing or unknown strand data likewise cannot satisfy them. `-f x` requires overlap/effective-A-length at least x; `-F y` analogously applies to B. With both, the default is AND and `-e` changes this to OR. `-r` makes `-f` reciprocal, requiring the same threshold against both A and B. Threshold equality passes.

`-split` changes a BED12 or spliced alignment into its blocks for overlap qualification and overlap-base totals. For BED12, blocks are `[start+blockStart,start+blockStart+blockSize)`. For alignments, `N` separates blocks; the special `bamtobed -splitD` also separates at `D`. Unless explicitly requested, a BED12 record is one outer-span interval. Except for the grouped `intersect -split` fraction rules, legacy unsorted hit ordering in Spec 5, and the command-specific ordering in Specs 8 and 24, qualifying results preserve stable input order; where every A/B pair is emitted, A is the outer order and B is the inner order.

## Spec 5

`intersect -a A -b B...` basic reporting. Each qualifying A/B pair is a result. For BED A, default text output replaces A's first three columns by intersection geometry while retaining A's remaining columns. For GFF A, replace its one-based inclusive columns 4/5 by the clipped geometry and retain its other fields. VCF cannot represent arbitrary clipping, so its default match output is the original VCF record. `-wa` prints original A per hit. `-wb` appends the full original B (and without `-wa`, its prefix is the clipped/format-preserving A result); `-wa -wb` prints full A then full B. `-wo` prints full A, full B, and overlap bases, for matches only. `-u` prints each A once if it has any match; `-v` prints each A once if it has none; `-c` prints each A plus its total number of matching B records, including zero.

For `intersect`, a supplied `-f` value outside `(0,1]`, including `0.0` or `1.0001`, fails nonzero; the final stderr line is exactly `***** ERROR: -f must be in the range (0.0, 1.0]. *****`.

`-wao` prints full A, full B, and overlap bases for every hit and exactly one null row for an unmatched A with overlap `0`. `-loj` behaves similarly but omits the overlap column. A null B has the same number of columns as real B: chromosome/text fields `.`, coordinate and numeric fields `-1`, and strand `.`. The canonical BED3 null is `.\t-1\t-1`. Overlap totals under `-split` are the union of blockwise overlap within that A/B pair, not the outer-span overlap. Zero-width records never create a positive overlap. All these modes retain A records in A input order.

`intersect -split` applies `-f` and `-F` after collecting all block-positive candidate B records for one A, rather than independently to each A/B pair. Let U be the union length of all blockwise intersections for that A. For `-f`, divide U by the sum of A block lengths. For `-F`, divide U by the sum of the block lengths of every candidate B record; this denominator is a sum across candidates, not one B at a time. Qualification accepts or rejects the candidate set as a whole. If it passes, pair-reporting modes emit every candidate with that pair's own blockwise overlap total. Thus a two-block A with block lengths 10 and 20, hit completely by two different 100-base B records, passes `-f 0.7` and emits both the 10- and 20-base hit rows, but fails `-F 0.20` because its grouped B fraction is `30/200`; a single candidate overlapping 20 of one 100-base B passes `-F 0.20`. Under `-wao`, a rejected candidate set yields its null row; `-u` uses the same grouped decision.

Without `-sorted` or `-sortout`, `intersect` emits B hits in legacy UCSC-bin traversal order: finer-bin records precede records in broader enclosing bins, with input order retained within a bin. This can differ from global B input order for nested records.

`intersect` has a legacy zero-width exception: internally treat BED `[p,p)` as `[p-1,p+1)` only for finding candidate hits, then restore `[p,p)` on output and report overlap length 0. It therefore matches an ordinary interval whose closed boundary range contains p, and `-wao` prints every such zero-overlap hit rather than a single null row.

## Spec 6

`intersect` multiple databases, formats, and sorted execution. Each filename following `-b` is a separate database. Pair-reporting modes place a database identifier between A and B when there is more than one B: default is one-based file number, `-names name...` substitutes aliases, and `-filenames` uses the supplied paths. With multiple B files, `-C` emits, for every A and every B file, `A`, database identifier, and that file's hit count. With exactly one B file it instead emits exactly one row per A containing only `A` and the hit count, with no database-identifier column. `-sortout` orders an A record's combined B hits by genomic position. Otherwise database order is stable, while hits within an unsorted database follow the legacy bin traversal in Spec 5. Alias counts must match database counts.

VCF and GFF inputs use Spec 2 geometry while whole-record modes reproduce their source fields. `-sorted` produces the same results as ordinary execution on valid sorted input and enforces Spec 3. Empty A produces no rows; modes such as `-v`, `-c`, `-C`, `-loj`, and `-wao` still produce their defined row for each A when B has no records.

If A is BAM, the default output is BAM: retain each qualifying alignment once (or each nonmatching alignment with `-v`) with header/fields intact. `-ubam` is valid uncompressed BAM. `-bed` selects textual BED12. In the ordinary clipped reporting mode, its chromosome/start/end are the A/B intersection geometry rather than the alignment's outer bounds; its thick start/end remain the alignment's outer bounds, and its comma-terminated block-size/relative-start lists remain those of the uncut alignment. The other fields are the `/1`- or `/2`-decorated query name defined in Spec 35, MAPQ, strand, RGB `0,0,0`, and block count. Thus an alignment at `[10,14)` intersected by `[11,12)` begins `chr1\t11\t12` while its thick bounds are `10\t14`. Pair reporters append B/count/overlap after these 12 fields. Unmapped alignments cannot positively intersect. Under `-v -bed`, retain the reference name stored in the BAM record rather than forcing the chromosome field to `.`; the remaining BED12 geometry uses null sentinels. For the unmapped mate stored against `chr1` with name `FCC1MK2ACXX:1:1212:13841:9775#/2`, the exact row is `chr1\t-1\t-1\tFCC1MK2ACXX:1:1212:13841:9775#/2\t0\t.\t-1\t-1\t-1\t0,0,0\t0\t.\t.`. BAM `-wao` without textual conversion is invalid and fails with `ERROR: writeAllOverlap option is not valid with BAM query input`. BAM may also be B. Equivalent CRAM input produces the same clipped text geometry and selected records.

The legacy option `-abam PATH` is accepted as an exact BAM-declaring alias for `-a PATH`, including `-abam -` for BAM on standard input. It supports the same `-split`, `-v`, `-c`, `-wo`, and `-bed` combinations. Without `-bed`, its output is BAM; for example a matching `three_blocks` alignment remains a BAM record, while `-v` produces no alignment for that match, and streamed `-v` preserves an unmapped nonmatching alignment.

An unrecognized intersect option has a usage diagnostic whose final stderr line is exactly `***** ERROR: Unrecognized parameter: OPTION *****`; for example this line contains `-wrongArg` verbatim. It exits 1 and produces no stdout.

## Spec 7

`closest -a A -b B...` candidate selection. Inputs are coordinate-sorted. Candidates must be on the same chromosome and pass `-s`, `-S`, and `-N` (different BED column-4 names) when present. Overlaps have distance zero and outrank nonoverlaps. Otherwise distance magnitude is one plus the open gap: a B with `B.end==A.start` has distance 1, as does one with `B.start==A.end`; use `A.start-B.end+1` to the left and `B.start-A.end+1` to the right. With no candidate, output A followed by a null B of the appropriate width.

Default output is original A plus original B and returns all candidates tied at the minimum distance. `-io` discards overlaps. `-iu` and `-id` discard upstream and downstream candidates respectively, using the directional convention selected by `-D`. `-t all|first|last` selects all tied candidates, the first, or the last in input order. `-k K` takes the first K candidates ordered by increasing absolute distance, then, under `-t all`, retains every additional candidate tied with the Kth candidate; it can therefore emit more than K rows. `first`/`last` resolve rather than expand each boundary tie. A null closest B follows the typed null convention of Spec 5: chromosome and textual fields are `.`, start/end and numeric fields are `-1`, and strand is `.`. A BED6 B therefore has null suffix `.\t-1\t-1\t.\t-1\t.`. A five-column B whose fifth field is textual instead has `.\t-1\t-1\t.\t.`.

## Spec 8

`closest` distance output and multi-database behavior. `-d` appends nonnegative distance. `-D ref|a|b` appends signed distance: overlap is 0; `ref` makes left/upstream negative and right/downstream positive; `a` reverses that sign for a minus-strand A; `b` orients by B such that a left B is positive when B is `+` and negative when B is `-`, while a right B is negative when B is `+` and positive when B is `-`. Directional tie output is upstream before downstream in the selected orientation. Consequently, for a minus-strand A tied between a genomic-left and genomic-right B, `-D a` emits the right B with `-1` first and the left B with `1` second. The appended null distance is `-1`.

With multiple B files, identify the database just before B as in Spec 6. Default `-mdb each` finds the closest result independently in every database; `-mdb all` finds the global closest across all databases. If an A chromosome has no candidate in any database, however, emit exactly one combined null row rather than one null per database, and use `.` as the database identifier; for five-column A and B records its suffix is `.\t.\t-1\t-1\t.\t.`. `-names` and `-filenames` control identifiers. Apply tie policy within the resulting candidate set. Under `-mdb all`, tied overlaps from different databases are emitted by B genomic position rather than database argument order. Thus the reverse-ordered database arguments `islands.bed tfbs.bed shores.bed` yield the tied rows in `shores.bed`, `tfbs.bed`, `islands.bed` order; with the nonoverlapping `islands.2.bed`, the two zero-distance rows are `shores.bed` then `tfbs.bed`. Support BED, GFF, VCF (including structural spans), BAM B records, `-split`, `-header`, very large coordinates, gzip, stdin, and the sorted-order errors of Spec 3.

## Spec 9

`coverage -a A -b B` reports for every A. Default columns are original A followed by: number of distinct qualifying B records (or qualifying B blocks under `-split`), number of A bases covered by the union of those overlaps, effective A length, and covered fraction formatted with exactly seven digits after the decimal. Overlapping unsplit B records each count but their bases are unioned. Under `-split`, each overlapping block counts separately, so one three-block alignment wholly intersecting A reports count `3`, while its covered bases remain the union of the blocks. `-counts` appends only this count. `-mean` appends arithmetic mean depth over A bases with seven decimals. `-d` emits one row per A base, adding a one-based offset within A and depth. `-hist` emits per A, for every observed depth including zero, `A, depth, bases-at-depth, A-length, fraction` and then aggregate rows `all, depth, bases, total-bases, fraction`; depth order is ascending and fractions have seven decimals.

All coverage mean and fraction divisions use IEEE-754 single-precision arithmetic before formatting to seven decimals, not exact or double-precision division. Consequently a depth sum of 66 over length 50 prints `1.3200001`, 154/50 prints `3.0799999`, and the aggregate histogram fraction 7/19 prints `0.3684210`.

`-counts`, `-d`, `-mean`, and `-hist` are mutually exclusive; combining them fails with `***** ERROR: -counts, -d, -mean, and -hist are all mutually exclusive options. *****`. Apply shared overlap/strand/fraction modifiers, `-split`, `-sorted`, and `-header`. Splitting B makes only its blocks contribute to depth. The legacy `-abam BAM -b B` treats BAM as A; when text is requested it uses the standard alignment-to-BED representation.

## Spec 10

`genomecov` accepts either sorted BED via `-i` plus `-g genome`, or sorted alignments via `-ibam` (chromosome sizes come from the alignment header). Default output is a depth histogram: for each chromosome, then for `genome`, emit `name, depth, base-count, total-length, fraction`; include zero depth and use compact ordinary decimal formatting. `-bg` instead emits maximal adjacent BEDGraph runs of constant positive depth. `-bga` includes zero-depth runs and chromosomes with no records. `-d` prints every genome position as `chrom, one-based-position, depth`; `-dz` prints only positive-depth positions and uses zero-based positions.

Coverage is clipped to chromosome bounds. `-split` honors BED12 blocks and alignment skips. CIGAR deletions do not cover deleted reference bases. `-pc` counts a proper read pair once across its outer fragment. `-fs N` gives each read a N-base fragment from its five-prime end (rightward on `+`, leftward on `-`), clipped to the chromosome. Empty BAM/CRAM still emits zero-depth histograms based on header contigs. BED/BAM/CRAM with equivalent intervals must give equivalent coverage.

## Spec 11

`merge -i INPUT` requires coordinate-sorted input and emits BED3 unions. Overlapping and book-ended intervals merge by default. `-d D` also bridges gaps of at most D; a negative D instead requires an actual overlap of at least `abs(D)`. Chains extend through the current component's maximum end. `-s` creates separate components for `+` and `-` and silently omits records whose strand is neither, including `.` and `*`; this omission succeeds rather than rejecting the input. `-S +` or `-S -` keeps and merges only that strand; any other value fails with `***** ERROR: -S option must be followed by + or -. *****`. Large BED, GFF, VCF including symbolic spans, BAM, gzip streams, and custom chromosome ordering are supported. BAM merge geometry is the alignment's reference span and ordinary output is BED3.

Stranded merge of VCF is unsupported: `-s` with VCF emits `***** ERROR: stranded merge not supported for VCF file PATH. *****` (the legacy program may still use exit status 0 for this diagnostic). Non-stranded VCF/GFF merge output remains BED3.

`-c columns -o operations` appends aggregate values over every source record in a merged component. One column may pair with many operations, one operation may pair with many columns, or equal-length lists pair positionally; other cardinalities fail. Output aggregates in the requested expansion order. `-delim text` changes list separators and `-prec n` controls numeric significant digits. Deprecated `-n` and `-nms` exit 1; their exact final stderr lines are respectively `***** ERROR: -n option is deprecated. Please see the documentation for the -c and -o column operation options. *****` and `***** ERROR: -nms option is deprecated. Please see the documentation for the -c and -o column operation options. *****`.

For BAM input, merge aggregation columns 1 through 11 use this legacy logical view, not raw SAM rendering: 1 is QNAME decorated with `/1` or `/2` from FLAG 64/128; 2 is unavailable FLAGS; 3 is RNAME; 4 is zero-based alignment start (SAM POS minus one); 5 is MAPQ; 6 is CIGAR with each operation printed before its length (`100M` becomes `M100`, and `3S97M` becomes `S3M97`); 7 is RNEXT with `=` expanded to RNAME and `*` rendered `.`; 8 is PNEXT converted to zero-based when positive; 9 is TLEN; 10 is SEQ; and 11 is QUAL. Consequently a missing mate reference aggregated from column 7 is `.`, and column-4 or column-8 means use those zero-based values. Requesting column 2 writes `***** ERROR: Requested column 2 of a BAM file, which is the Flags field.`; requesting a column above 11 writes `***** ERROR: Requested column N, but database file PATH only has fields 1 - 11.`. These two legacy errors produce no stdout but exit with status 0.

## Spec 12

Aggregation semantics shared by `merge`, `map`, and `groupby`. Support `sum`, `count`, `count_distinct`, `mean`, `median`, `min`, `max`, `absmin`, `absmax`, `mode`, `antimode`, `collapse`, `distinct`, `stdev`, `sstdev`, `first`, and `last`. `collapse` joins all values in encounter order including duplicates; `distinct` joins each distinct textual value once in lexicographic order. For encountered values `-5,2,-2,5`, `collapse` is `-5,2,-2,5` and `distinct` is `-2,-5,2,5`. `mode` chooses the most frequent and `antimode` the least frequent; a frequency tie selects the lexicographically smallest textual value, independent of encounter order (for `-5,2,-2,5`, both produce `-2`). `stdev` is population standard deviation and `sstdev` sample standard deviation. `sstdev` with fewer than two contributing numeric values returns the command's null marker; for `map`, one contributing value therefore produces `.` rather than `nan`. `absmin`/`absmax` choose by absolute numeric magnitude.

Numeric operations parse signed integers, decimals, and scientific notation. If any contributing value in one-based column COLUMN is nonnumeric for a numeric operation, return the command's null value rather than silently coercing it and emit one warning for that result. VALUE in that warning is the last nonnumeric contributing value encountered, and the exact stderr line is ` ***** WARNING: Non numeric value VALUE in COLUMN.` (including its leading space); thus merging `x` then `y` in column 4 reports `y`. Preserve raw textual digits for nonnumeric/list operations even beyond 53-bit precision. `absmin` and `absmax` return the selected nonnegative absolute magnitude, not the original signed value; for example values including `-6` can produce `6` under `absmax`. Emit exact integral results as integers when their digit count fits the precision. Otherwise use C `%g`-style general significant-digit formatting: default precision is 10 and `-prec n` changes it to n, choosing decimal or scientific notation accordingly (for example 5,344,172 at precision 5 is `5.3442e+06`). A custom `-delim` is used verbatim.

## Spec 13

`map -a A -b B` prints each original A followed by aggregates of columns from qualifying overlapping B records. Default is `-c 5 -o sum`. GFF/VCF fields remain addressable as their original columns. A BAM B is addressable as logical SAM fields, including optional fields, while interval matching uses the alignment span. Map's legacy validation diagnostics produce no stdout but exit with status 0. ## Spec 14

`subtract -a A -b B...` removes qualifying B-covered portions from each A. Default output is every remaining positive-length fragment in genomic order, with only A's first three fields changed and every trailing A field preserved. First union all qualifying B portions, so overlapping B intervals never duplicate fragments. With `-A`, discard the whole A when any single qualifying B overlaps it. With `-N`, discard the whole A only when the combined qualifying overlap strictly exceeds the `-f` fraction; equality does not pass for this option. Thus two disjoint three-base overlaps on a ten-base A leave A unchanged under `-N -f 0.6`, but discard it under `-N -f 0.59`. Otherwise emit A unchanged when it has no match.

Apply the shared strand/fraction/reciprocal/either/split rules and support multiple B files, gzip/stdin, large coordinates, VCF/GFF geometry, `-sorted`, `-g`, and `-header`. Touching intervals subtract nothing. An overlap at a single real base removes that base and may create two fragments.

## Spec 15

`slop -i A -g genome` adjusts interval edges while preserving all fields. `-b x` uses x on both sides; otherwise `-l L -r R` is required. Normally output `[start-L,end+R)`. Negative amounts shrink. With `-pct`, multiply each amount by the original interval length and truncate toward zero. With `-s`, swap the logical left/right amounts for minus-strand records. Clip output to `[0,chromLength]`.

If negative slop crosses the two endpoints, order the computed endpoints so start is smaller. If clipping would place an interval completely left or right of the chromosome, emit the one-base boundary sentinel `[0,1)` or `[length-1,length)` respectively. Do not overflow on huge coordinates. Missing chromosomes/genome arguments and malformed inputs fail.

## Spec 16

`shift -i A -g genome` translates intervals, preserving all fields. `-s amount` applies to all records; alternatively `-p plusAmount -m minusAmount` selects by strand. With `-pct`, multiply shift by original interval length in the command's floating-point arithmetic and round the product down toward negative infinity. This differs from truncation for negative products: a length-10 interval shifted by `-0.2` receives displacement `-3` and `[30,40)` becomes `[27,37)`. Add the selected displacement to both endpoints, then clip each endpoint to the chromosome. Unlike slop, partial clipping may shorten the interval (for example `[5,10)` shifted +2 in a length-10 chromosome becomes `[7,10)`). A result completely beyond a boundary becomes `[0,1)` or `[length-1,length)`. Support decimal, negative, and large shifts and validate required options.

## Spec 17

## Spec 18

`flank -i A -g genome` emits up to two flanks per input record, in genomic left-then-right order, preserving all fields but replacing coordinates. `-b x` sets both widths; `-l L -r R` sets them separately. ## Spec 19

## Spec 20

## Spec 21

## Spec 22

## Spec 30

`fisher -a A -b B -g genome` counts feature overlap and prints a labeled report followed by Fisher exact-test values. Let `a` and `b` be input record counts and `x` the number of qualifying A/B overlap pairs. Estimate possible intervals as `n=floor(totalGenomeLength/(meanA+meanB))`, where each mean uses estimator length `end-start+1` (deliberately inclusive only for this estimate). The legacy displayed table reuses pair count `x` in both margins: `[[x,a-x],[b-x,n-a-b+x]]`. In particular, when one B overlaps two A records and `a=b=x=2`, `n=4`, the bottom row is `0` and `2`. `-m` first merges intervals in each input before counts/means. Apply strand and overlap fraction options.

Output this exact layout, replacing brace expressions and preserving spacing:

```text
# Number of query intervals: {a}
# Number of db intervals: {b}
# Number of overlaps: {x}
# Number of possible intervals (estimated): {n}
# phyper({x} - 1, {a}, {n} - {a}, {b}, lower.tail=F)
# Contingency Table Of Counts
#_________________________________________
#           |  in -b       | not in -b    |
#     in -a | {x:<13}| {a-x:<13}|
# not in -a | {b-x:<13}| {n-a-b+x:<13}|
#_________________________________________
# p-values for fisher's exact test
left\tright\ttwo-tail\tratio
{left}\t{right}\t{two-tail}\t{ratio}
```

Here `:<13` means left-align the value in a 13-character field. `left=P(X<=x)` and `right=P(X>=x)` for the hypergeometric distribution with population n and margins a,b; two-tail is the sum of table probabilities no greater than the observed table probability. The displayed ratio is `(x*(n-a-b+x))/((a-x)*(b-x))`. Format each probability with `%g`-style five-significant-digit output (`0.0053476` has five significant digits), but format a finite ratio with exactly three digits after the decimal point, so the issue-954 result is `5.905`. Emit `inf` or `-nan` for the corresponding ratio edge cases.

## Spec 31

`reldist -a A -b B` uses integer interval midpoints, `floor((start+end)/2)`. Sort all B midpoints per chromosome. ## Spec 33

Ignoring entry and moving on.`. Accept stdin/gzip and preserve record order for invocations that can place their records.

The suffix is synthesized from the mate flag even though the stored BAM query name is bare. Reconstruct original read orientation: for FLAG 16 reverse-complement stored alignment sequence and reverse qualities. Preserve ambiguous bases. Records lacking FLAG 1 are silently skipped; malformed paired data or missing required output arguments may produce diagnostics rather than malformed FASTQ.

## Spec 38

`pairtobed -a BEDPE -b B` uses BEDPE end 1 (`cols 1-3`, strand 9) and end 2 (`cols 4-6`, strand 10). For each end, collect B hits satisfying shared strand/fraction rules. Default/`-type either` qualifies when either end hits; `both` when both hit; `xor` when exactly one hits; `neither` when neither hits; `notboth` when fewer than both hit. Positive types emit original A plus each distinct matching B, in end and B input order; negative/no-hit results emit A alone when there is no B row to append. Multiple hits produce multiple rows. Minimal six-column BEDPE is valid.

`ispan` tests B against the inner interval between same-chromosome, nonoverlapping mates; `ospan` tests the full outer span. `notispan`/`notospan` emit A when that span has no B match. Cross-chromosome pairs have no inner/outer span. Touching is no overlap, one shared base is. `-f` applies to the relevant BEDPE end/span length. `-s` requires B strand equal to the relevant end; `-S` opposite. Missing A or B exits 1 with no stdout and a usage diagnostic containing `*****ERROR: Need -a and -b files.`. An invalid `-type` likewise exits 1 and contains the uppercase line `*****ERROR: Request "either" or "both" or "neither" or "xor" or "notboth" or "ispan" or "ospan" or "notispan" or "notospan"`.

## Spec 39

`pairtopair -a A.bedpe -b B.bedpe` compares pairs using both direct end correspondence and the crossed correspondence. Default/`-type both` requires both ends in one correspondence to overlap; `either` requires at least one; `neither` requires none; `notboth` requires fewer than both. Positive matches output A followed by B for every qualifying pair. Negative modes output A alone as appropriate. Default matching enforces corresponding endpoint strands; `-is` ignores strands. `-rdn` additionally requires different BEDPE names (column 7).

`-f x` requires the overlap fraction for every endpoint used by the type. `-slop N` symmetrically expands both A endpoints for matching. With `-ss`, slop is directional: expand the end of a plus-strand endpoint and the start of a minus-strand endpoint. Output original, unexpanded A. Missing A or B exits 1 with no stdout and a usage diagnostic containing `*****ERROR: Need -a and -b files.`. An invalid `-type` exits 1 and contains the uppercase line `*****ERROR: Request "both","neither","either",or "notboth"`. Handle empty input, large coordinates, multiple matches, adjacency, and direct/crossed ordering deterministically.

## Spec 40

`window -a A -b B` expands A only for searching and emits original A plus original B for each hit. Default expansion is 1,000 bases on each genomic side. `-w N` sets both, while `-l L -r R` sets sides independently; `-sw` swaps left/right for minus-strand A. `-sm` and `-Sm` require same/opposite strands. `-u` emits A once if any B lies in the window, `-v` once if none, and `-c` appends count. Search windows clip at zero; original A coordinates never change. Accept gzip, stdin, empty inputs, and headers.

## Spec 41

`multicov -bed A -bams B1.bam B2.bam ...` appends one alignment count per BAM to every original A record. BAMs are coordinate-sorted and indexed. Count each mapped alignment whose span overlaps A; `-split` counts only alignment-block overlaps. `-s`/`-S` require same/opposite orientation and `-f` sets minimum A fraction covered by an individual alignment. Apply normal duplicate/quality filtering options when supplied (`-D` includes duplicates, `-F` includes failed-QC, `-q N` minimum MAPQ). Empty BAM gives zero; multiple BAM columns follow command order.

## Spec 42

`igv -i BED` writes an IGV batch script. First line is `snapshotDirectory PATH`, default `./`; `-path P` changes it. `-sess FILE` then writes `load FILE`. For each BED record write `goto chrom:start-slop-end+slop` without clipping a negative expanded start, optionally `sort TYPE`, optionally `collapse` when `-clps` is present, then `snapshot filename`. For example, `[5,10)` with `-slop 7` writes `goto chr1:-2-17`. Filename uses original `chrom_start_end`, adds `_name` under `-name`, adds `_slopN` when slop is nonzero, and ends in `.png` by default or the exact `-img png|eps|svg` extension. `-sort` accepts only `base`, `position`, `strand`, `quality`, `sample`, or `readGroup`. Negative slop fails with `Slop must be >= 0`; invalid sort fails with `Invalid sort option`. With `-name`, an empty BED column 4 exits 1 after writing the initial `snapshotDirectory ./` line and stderr is exactly `Error: You requested that filenames be based upon the name field.  However, it appears to be empty. Exiting!`. Accept stdin.

## Spec 43

`links -i BED` emits the following literal HTML skeleton (the `\t` escapes denote literal tab characters), substituting the supplied input argument into TITLE, then one ROW per interval and one EXTRA per BED field after column 3. The `<h3>` text is literally `stdin` even for a named input; href has no quotes.

```text
<html>
\t<body>
<title>TITLE</title>
<br>Firefox users: Press and hold the "apple" or "alt" key and click link to open in new tab.
<p style="font-family:courier">
<table border="0" align="justify"
<h3>BED Entries from: stdin </h3>
<tr>
\t<td>
\t\t<a href=URL>TEXT</a>
\t</td>
EXTRA
</tr>
...
</table>
</p>
\t</body>
</html>
```

Each EXTRA is `\t<td>\nVALUE\n\t</td>`. URL is `BASE&position=chrom:start-end`; default BASE is `http://genome.ucsc.edu/cgi-bin/hgTracks?org=human&db=hg18`, and `-base`, `-org`, and `-db` replace those components. TEXT is `chrom:start+1-end` (one-based display start). BED3/4/5/6 and stdin work.

`summary -i BED -g genome` emits header `chrom\tchrom_length\tnum_ivls\ttotal_ivl_bp\tchrom_frac_genome\tfrac_all_ivls\tfrac_all_bp\tmin\tmax\tmean`. For each genome chromosome in order report length, interval count, sum of `end-start`, chromosome fraction of genome, fraction of all intervals, fraction of all interval bases, and min/max/mean interval length. Use nine decimal places for fractions/mean on chromosome rows; a nonempty chromosome row has one trailing tab before newline. An empty chromosome uses `-1\t-1\t-1` with no trailing tab. Finish with `all` totals, three fraction fields literally `1.0`, and global min/max/mean with nine decimals. For completely empty input, use zero totals, still use the three `1.0` overall fractions, and use legacy overall min/max/mean `9223372036854775807\t0\t-nan`. Missing `-g` exits 1 with no stdout and a usage diagnostic containing the exact line `***** ERROR: no -g genome file provided. *****`.

## Spec 44

`tag -i BAM -files B1 ...` copies every BAM alignment and header to valid BAM stdout, adding a string auxiliary tag only when it overlaps an annotation. Default tag key is `YB`; `-tag X` and `-tag XY` accept one- and two-character custom tag keys. A longer key exits 1 with no BAM output and a usage diagnostic containing the exact line `*****ERROR: Custom tags should be at most two characters per the SAM specification. `. Exactly one labeling mode is required: `-labels L1...` stores the matching file label; `-names` stores overlapping BED column-4 names; `-scores` stores column-5 values as strings; `-intervals` stores a descriptive string containing label, `chrom:start-end`, name, score, and strand. Multiple matching annotations are represented deterministically without losing matches.

Do not add an empty tag to nonmatching reads. `-s`, `-S`, and `-f` use Specs 4/2 against the alignment span; threshold equality passes. Label count must match file count. Validation reports all independently missing required option groups before usage text. Supplying only `-i` exits 1 with no stdout and reports both exact lines, in this order: `*****ERROR: Need -i, -files`, then `*****ERROR: Need -labels or -names or -scores`. Combining `-labels` with `-names` exits 1 with no stdout and reports `*****ERROR: Use -labels or -names, not both.`; combining `-scores` with `-names` similarly reports `*****ERROR: Use -scores or -names, not both.`. Missing annotation files, other simultaneous labeling modes, simultaneous `-s -S`, or malformed tag names fail with an informative diagnostic.
