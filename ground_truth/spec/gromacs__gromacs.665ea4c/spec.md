# Executable specification

The required artifact is one executable file named `executable`. It is a deterministic, command-line molecular simulation and trajectory-analysis program. The words “must fail” below mean a nonzero process status and a diagnostic on standard error; “must succeed” means status zero.

## Spec 1

`executable` is a multicall command driver. Its filesystem invocation is `executable [global-options] command [command-options]`, but its user-facing help deliberately uses the upstream `gmx` program name in synopsis lines. It must implement these command names: `analyze`, `anaeig`, `angle`, `awh`, `bar`, `bundle`, `check`, `chi`, `cluster`, `clustsize`, `confrms`, `convert-tpr`, `convert-trj`, `covar`, `current`, `density`, `densmap`, `dielectric`, `dipoles`, `disre`, `dos`, `dssp`, `dump`, `dyecoupl`, `editconf`, `eneconv`, `enemat`, `energy`, `filter`, `genconf`, `genion`, `genrestr`, `grompp`, `gyrate`, `gyrate-legacy`, `h2order`, `hbond`, `helix`, `helixorient`, `hydorder`, `densorder`, `lie`, `make_edi`, `make_ndx`, `mdmat`, `mindist`, `msd`, `nmeig`, `nmens`, `nmr`, `nmtraj`, `order`, `pdb2gmx`, `polystat`, `potential`, `principal`, `rama`, `rdf`, `rms`, `rmsdist`, `rmsf`, `rotacf`, `rotmat`, `saltbr`, `sasa`, `sham`, `sigeps`, `solvate`, `sorient`, `spatial`, `spol`, `tcaf`, `traj`, `trjcat`, `trjconv`, `trjorder`, `vanhove`, `velacc`, `wham`, `wheel`, and `xpm2ps`. `mdrun` need only be recognized and provide command help.

Options are single-dash, case-sensitive names unless written with two dashes. Boolean options accept the conventional negated spelling `-noNAME`. An explicit output path must be honored exactly, including paths in another directory. Outputs from separate invocations must not depend on stale files. When `GMX_MAXBACKUP=-1`, do not create numbered backup files.

## Spec 2

All commands share strict option validation. Unknown options, missing option values, an invalid enum value, a file of a disallowed extension, an inaccessible required file, or an impossible combination must fail before analysis. Command-line parsing failures, including inaccessible files named by explicit input options, use an `Error in user input:` heading, then `Invalid command-line options`, identify each affected option with the exact block heading `In command-line option -NAME`, and report every simultaneously invalid explicit input in command-line option order rather than stopping after the first. For each missing explicit file, the option block contains these sentences in order: `File 'PATH' does not exist or is not accessible.`, `The file could not be opened.`, and `Reason: No such file or directory`; when the failed operation is `fopen`, the next line is `(call to fopen() returned error code 2)`. This parser form applies to explicit `-f` inputs of `genconf`, `eneconv`, `energy`, `gyrate-legacy`, `grompp`, `lie`, `mdmat`, `msd`, `rms`, `sasa`, and `velacc`, to `editconf`, and to explicit `wham`/`bar` list or data inputs as well as the other commands. Thus, for example, `enemat -f nonexistent.edr -groups groups.dat` reports the `-f`/`nonexistent.edr` block followed by the `-groups`/`groups.dat` block, and each block ends in that error-code line. A missing default required input uses `Error in user input:` followed by `Invalid input values`, identifies the option with `In option NAME` (without a dash), and uses the exact sentence form `Required option was not provided, and the default file 'BASE' does not exist or is not accessible.`. Its extension list is introduced by the exact text `The following extensions were tried to complete the file name:`. Later file-reading failures use their command-specific `System I/O error:` or `Fatal error:` heading. Do not silently reinterpret malformed binary or text input.

Analysis commands that need an atom group print available groups, read a numeric or named selection from standard input, and report `Selected N: 'name'` on standard output. An invalid selection must fail with `No such group`/`Cannot read from input`. Multiple prompts consume selections in documented order. A selected group must contain the needed complete atoms, residues, or molecules; partial molecules and wrong tuple sizes are errors where the calculation requires whole entities. When `current` is invoked with no arguments, the missing-default diagnostic contains both `In option f` and `In option s` blocks, in that order, for the attempted `traj` and `topol` defaults; it does not stop after reporting the missing trajectory.

The common `-b`, `-e`, and `-dt` options select frames inclusively by time and sampling interval. Empty valid ranges produce empty data outputs when meaningful; commands that require data must instead explain that no frames were found. Progress diagnostics use `Reading frame`, final diagnostics use `Last frame`, and energy readers similarly report the last energy frame. `-xvg xmgrace`, `xmgr`, and `none` are accepted; invalid values fail.

## Spec 3

The executable interoperates with the supplied molecular file types. It must read and, where requested, write:

- GRO text structures: title, atom count, fixed-field residue number/name, atom name/number, coordinates in nm, optional velocities, then a 3- or 9-component box.
- PDB structures: standard `ATOM`/`HETATM`, `MODEL`, `TER`, `CRYST1`, and `ENDMDL` records; coordinates are Angstrom on disk and nm internally. Preserve names, residues, chains, and atom ordering unless an option changes them.
- G96 text structures; NDX files containing `[ group name ]` followed by one-based atom numbers; MDP key/value parameter files; topology TOP/ITP section syntax and `#include` processing.
- TPR run-input files, EDR energy files, TRR full-precision trajectories (coordinates, boxes and optional velocities/forces), XTC compressed-coordinate trajectories, checkpoint files, Hessian matrices, and eigenvector trajectories in the corresponding GROMACS binary encodings. Detect format from content/extension as appropriate and preserve all representable metadata on conversion.

Numerical graph output is XVG. Unless `-xvg none`, it begins with `#` provenance comments and `@` directives for title, axis labels, type, and legends, followed by whitespace-separated finite numeric columns. In particular, an XVG written by `rms -o` contains the exact provenance line `# Created by:`. The deliberate exception is `analyze -av`: its average file is plain numeric data without `#` or `@` metadata even in the default XVG mode. `-xvg none` suppresses `#` and `@` metadata only for outputs that otherwise have them. One command-specific exception is `current -mj`: under `-xvg none` it suppresses the normal metadata but retains the exact column-header prefix `# time` (the full header is `# time\t x\t y \t z \t average of M_J^2 \t std.dev`). Matrix output is valid XPM beginning `/* XPM */`, containing title/x-label/y-label metadata, a color map, and `static char *gromacs_xpm[]`; dimensions and row widths must agree. EPS output is syntactically valid PostScript. Floating output must be stable and sufficiently precise for values to be compared at about 1e-5 relative tolerance; high-precision modes emit additional significant digits.

## Spec 4

All geometry uses nm, ps, atomic mass units, elementary charge, degrees unless radians are explicitly selected, and periodic minimum-image distances when PBC is enabled. Reconstruct molecules made whole before center-of-mass, fitting, or molecular-dipole calculations when requested. A center of mass is `sum(m_i r_i)/sum(m_i)`; a center of geometry uses equal weights. RMSD is the square root of the mean squared displacement after any selected least-squares rotational/translational fit. Radius of gyration is `sqrt(sum(w_i |r_i-r_c|^2)/sum(w_i))`. Inertia tensors are mass-weighted, symmetric, diagonalized, and their eigenvectors orthonormal; axes and eigenvalues have deterministic ordering/sign conventions.

Histogram bins are half-open except the last, use the requested width/range, and normalization integrates to the appropriate count or probability. Correlation at lag `t` averages all origins that possess that lag and is normalized at lag zero only when requested. Derivatives, integrations, FFTs and covariance eigenproblems must be calculated from input values, not fabricated. Selections distinguish atom positions, residue centers, and molecule centers. Time, axis, bin count, normalization, PBC, fitting, weighting and group choices must materially affect results. Empty bins must yield defined zero values rather than NaN/Inf unless a command explicitly reports an undefined conversion.

## Spec 5

With no arguments, `-h`, or `help`, print general help to standard output and succeed. For all three forms, standard output starts with `SYNOPSIS`, contains no `GROMACS` identification/banner, includes the legacy synopsis `gmx [-[no]h] [-[no]quiet] [-[no]version] [-[no]copyright]`, and has the exact subheading `Other options:`. With no arguments or with `-h`, the decorative line containing `:-) GROMACS - executable` is instead on standard error; the `help` form does not emit that banner. The options display contains the exact line `-[no]h                     (no)`, followed by the description `Print help and quit`; the `-[no]quiet` description is exactly `Do not print common startup info or quotes`, and the `-[no]copyright` description is exactly `Print copyright information on startup`. The topic list is introduced by the exact line `Additional help is available on the following topics:` and contains the exact row substring `commands    List of available commands`. Unlike command help, general help has no `DESCRIPTION` heading: it proceeds from `SYNOPSIS` to `OPTIONS`. It also contains a command list grouped under headings such as analysis/file conversion/simulation preparation and the exact help-request instruction `To access the help, use 'gmx help <topic>'.`. `help commands` succeeds, starts with `LIST OF AVAILABLE COMMANDS`, contains the exact usage line `Usage: gmx [<options>] <command> [<args>]`, includes the aligned row `energy               Writes energies to xvg files and display averages`, and ends its command list with the exact sentence `For help on a command, use 'gmx help <command>'.`; `help selections` succeeds, starts with `SELECTION SYNTAX AND USAGE`, contains both `Selections are used to select atoms/molecules/residues for analysis` and `each selection evaluates to a set of positions`, explains that `selections can be dynamic`, contains the exact line `Available subtopics:`, and includes the exact subtopic row `arithmetic   Arithmetic expressions in selections`; `help COMMAND` prints that command's help. `-help` is not a valid global synonym and fails under `Error in user input:` followed by `Invalid command-line options` and `Unknown command-line option -help`; its diagnostic also contains `src/gromacs/commandline/cmdlineparser.cpp`. An unknown command fails under `Error in user input:`, contains `src/gromacs/commandline/cmdlinemodulemanager.cpp`, reports `'NAME' is not a GROMACS command.`, and includes `https://manual.gromacs.org/current/user-guide/run-time-errors.html`. An unknown help topic prints `No help available for 'TOPIC'` on standard error and exits with status 2.

`-version` and `--version` succeed and identify `GROMACS` and the version as `2027.0-dev` (a longer build suffix may follow), plus precision, memory model, MPI, OpenMP, GPU, SIMD, FFT, compiler and build information. `-quiet` suppresses banner and closing-quote output that would otherwise be written to standard error, but it does not remove requested version content: `-quiet -version` succeeds with empty standard error and standard output still begins with the decorative `:-) GROMACS - executable` line. With `-quiet` alone, the general-help text, including `Additional help is available on the following topics:`, remains on standard output while both standard streams contain no banner or closing quote. Conversely, `-noquiet` writes the ordinary banner, invocation details, and closing quote to standard error; its invocation-details block contains the exact line `Executable:   /workspace/executable`. `-noquiet help` succeeds with standard output beginning at `SYNOPSIS` and containing no `GROMACS` banner; its standard error instead contains the decorative `:-) GROMACS - gmx help` line and the closing quote. `-copyright` writes `Copyright 1991-2027 The GROMACS Authors.` and the license/contributor material to standard error, including `GROMACS is free software; you can redistribute it and/or modify it` and the exact consecutive text `under the terms of the GNU Lesser General Public License` and `as published by the Free Software Foundation; either version 2.1`, then writes general help to standard output. Every command's `-h` succeeds, identifies the command using its `gmx COMMAND` branding, has the literal headings `SYNOPSIS`, `DESCRIPTION`, and `OPTIONS`, and documents its accepted input/output extensions and options. Boolean option pairs are displayed in the compact form `-[no]NAME`; for example, `help sham` shows `-[no]time`, which covers both `-time` and `-notime` rather than printing the negated spelling separately. In contrast, command-level `--help` is not a help alias: for every command in Spec 1 it exits with status 1, writes nothing to standard output, and reports on standard error under the command's `GROMACS - gmx COMMAND` banner, `Error in user input:`, `Invalid command-line options`, and `Unknown command-line option --help`. In particular, `help energy` and `energy -h` begin with `SYNOPSIS`, contain `gmx energy [-f [<.edr>]] [-f2 [<.edr>]] [-s [<.tpr>]]`, contain the exact sentence opening `gmx energy extracts energy components from an energy file`, contain `Average, RMSD, and drift are calculated`, and contain the exact headings `OPTIONS`, `Options to specify input files:`, `Options to specify output files:`, and `Other options:`. `lie -h` likewise contains the literal `OPTIONS` heading. `rmsdist -h` labels `-f` as `Trajectory` and `-s` as `Structure+mass(db)`; `help mdrun` contains `gmx mdrun [-s [<.tpr>]]`, the exact sentence opening `gmx mdrun is the main computational chemistry engine within GROMACS`, and the phrase `Molecular Dynamics simulations`; `convert-tpr -h` contains `gmx convert-tpr` and the phrase `by modifying the number of steps`; `convert-trj -h` contains the exact sentence opening `gmx convert-trj converts trajectory files between different formats.`; `genconf -h` contains the synopsis `gmx genconf [-f [<.gro/.g96/...>]]` and the phrase `multiplies a given coordinate file`; `disre -h` describes each of `-ds/-da/-dn/-dm/-dr` as an `xvgr/xmgr file`; `dump -h` describes `-f` as a trajectory file and says `gmx dump reads a run input file (.tpr), a trajectory`; the help contains `gmx convert-trj` and `gmx disre`; and `check -h` begins its description with `gmx check reads a trajectory`.

The version report also contains a field beginning exactly `Executable:`. In `help commands`, command names are followed by aligned descriptions; its `anaeig` row contains the exact text `anaeig               Analyze eigenvectors/normal modes`. The `velacc -h` description contains `momentum autocorrelation function`, and the `xpm2ps -h` description contains the literal term `XPixelMap`. The `check -h` description contains the sentence beginning `The program can compare two run input (.tpr) files` and the exact sentence opening `Similarly a pair of trajectory files can be compared (using the -f2 option),`.

The remaining exact general-help text is also part of the interface. ## Spec 6

`check` inspects one supplied TPR, trajectory, energy, structure, or index input. The `-c STRUCT` form is the structure-input flag, checks a coordinate file, and succeeds with `-vdwfac`, `-bonlo`, and `-bonhi`; those values control the reported close-contact test. This test is announced on standard error by a line beginning exactly `Checking for atoms closer than`. For a GRO without velocity columns it prints `coordinates found` and `velocities  absent`. For trajectories it reports format, atom count, frame count, start/end times, timestep, coordinate precision, box presence, and whether velocities/forces occur. The coordinate-precision diagnostic uses the capitalized form `Precision VALUE (nm)`; an XTC stored at the ordinary precision used by the supplied fixture prints exactly `Precision 0.001 (nm)`. Reading a single-precision TRR first prints `trr version: GMX_trn_file (single precision)` on standard error. Its trajectory frame table on standard error has the exact header `Item        #frames Timestep (ps)`. With a TPR it additionally checks atom-count consistency and bonds using configurable `-tol`, `-abstol`, `-vdwfac`, `-bonlo`, and `-bonhi`; `-rmsd` controls coordinate comparison mode. Multiple-frame summaries must be accurate. `-f`/`-f2`, `-e`/`-e2`, and `-s1`/`-s2` comparisons report equality or quantitative differences. Valid TRR data must be recognized as full precision.

`dump` renders binary files as stable, human-readable structured text: `-s` TPR includes header, input record/integrator, topology, atoms, interactions and force-field parameters; `-e` EDR includes frame times and named energy values; `-f` TRR/XTC includes frame metadata, boxes and coordinates at stored precision; `-cp` dumps checkpoint state; `-mtx` dumps matrices; `-p` dumps topology-like input. Dumping a TRR with `-f` writes `trr version: GMX_trn_file` followed by its precision to standard error. `-nr` includes numeric indices and `-nonr` omits them. If several inputs are supplied, TPR precedence is deterministic. With no input it succeeds without printing usage and writes a standard-error banner containing `GROMACS - gmx dump`, a `Command line:` block, and `GROMACS reminds you:`. A missing named input must fail. Passing an XTC to `dump -s` fails under `Error in user input:` and `Invalid command-line options`, identifies `In command-line option -s`, says the file `cannot be used for this option`, then `Only the following extensions are possible:` and `.tpr`.

## Spec 7

`convert-tpr -s INPUT -o OUTPUT` reads a run input and writes a valid run input while preserving topology and state. Exactly one of or a compatible combination of `-extend Δt`, `-until t`, and `-nsteps n` changes the planned run length: extend adds the requested physical time, until sets the absolute ending time, and nsteps directly sets the remaining step count; `-nsteps -1` means unlimited. Zero extension leaves the length unchanged. Combined operations have deterministic command-line precedence and the standard-output summary begins its old and new run sections with the exact labels `Input file:` and `Output file:`, respectively, before stating step and end-time information. `-generate_velocities`, `-velocity_temp`, and `-velocity_seed` generate Maxwell-distributed velocities reproducibly from the seed at the requested temperature. Missing input fails. Output format is detectable as TPR and can subsequently be read by `check`/`dump`.

## Spec 8

`convert-trj -f INPUT -o OUTPUT` converts XTC/TRR trajectories based on output extension. Preserve atom count, selected frames, boxes, times and coordinates; TRR-to-XTC discards fields XTC cannot store, while XTC-to-TRR creates a valid coordinate-only TRR. `-b/-e/-dt` filter frames. `-precision N` controls XTC coordinate quantization. `-starttime t` resets the first output timestamp and shifts subsequent times; `-timestep dt` replaces time spacing; both together use the new start and spacing. `-tu ns` expresses input option times/output reporting in ns while stored times remain consistent. The default-enabled `-rmpbc` makes molecules whole for each frame; its accepted boolean negation `-normpbc` disables that operation. `-vel never` suppresses velocities. Atom selection is accepted through `-select <selection>`, and `convert-trj -h` displays that option and argument form. Converting to the same format is valid. If the requested beginning time is beyond the available frames, the command fails rather than writing a zero-frame trajectory; for `-b 100 -e 200` on a trajectory ending before 100, the fatal diagnostic is `Specified frame (time 100.000000) doesn't exist or file corrupt/inconsistent.` Report converted/read frame counts and preserve times exactly enough for `check`.

The frame diagnostics are the legacy GROMACS ones on standard error. Reading a TRR prints `trr version: GMX_trn_file` (followed by its precision). A frame excluded by `-dt` is reported with `Skipping frame`, and successful completion reports `Analyzed N frames`. These diagnostics describe input processing, not a separate invented conversion count. A converted three-frame file retimed with `-starttime -1 -timestep 2` is subsequently reported by `check` at times -1, 1 and 3 ps; its first progress line contains the exact time field `time   -1.000`.

## Spec 9

Trajectory utilities behave as follows. `traj -f TRAJ -s STRUCT -ox X -ov V` extracts selected coordinates and velocities as XVG, optionally `-com` and with group selection. Requesting `-ov` from an XTC fails under `Fatal error:` with the two-line sentence `Cannot extract velocities or forces since your input XTC file does not contain` / `them.`. `trjconv` converts trajectory/structure formats, filters with `-b/-e/-dt/-skip`, centers with `-center`, and applies requested PBC treatment; PBC transformations requiring topology fail without `-s`. Output extension determines GRO/XTC/TRR/PDB form, and GRO output is announced on standard error by a line beginning exactly `Will write gro:`. `trjcat -f files... -o out` concatenates in time order and resolves overlap deterministically. Equal adjacent start times are marked in its standard-error file summary with `WARNING: same Start time as previous`. With `-settime`, it reads new starting times from stdin after writing the exact prompt `Enter the new start time (ps) for each file.` to standard error.

`analyze -f XVG` ignores metadata, understands multiple series (including y columns and sets separated by `&`), and prints count, average, standard deviation, error and regression statistics. Its statistics table labels successive series exactly `SS1`, `SS2`, and so on; a five-point series therefore has an `SS1` row. For each N-point series the displayed standard deviation is the population value `sqrt(sum((y-average)^2)/N)`, while the `std. dev./sqrt(n-1)` error column is that standard deviation divided by `sqrt(N-1)`. Thus input values 1 through 5 print average `3.000000e+00`, standard deviation `1.414214e+00`, and error `7.071068e-01`; two six-point y columns containing 1 through 6 and twice those values print the respective triples `(3.500000e+00, 1.707825e+00, 7.637626e-01)` and `(7.000000e+00, 3.415650e+00, 1.527525e+00)`. With `-regression`, standard output contains the exact preamble `Minimizing residual chi2 = Sum_i w_i [f(x_i) - y_i]2` before the fitted coefficients; a perfect linear fit reports the exact aligned lines `Chi2                    = 0` and `S (Sqrt(Chi2/(n-2))     = 0`. `-dist` writes distributions, `-av` writes the average series described below, `-ee` estimates errors, `-regression` prints a linear fit, and `-ac` writes an autocorrelation using `-fitfn` when supplied. `-ac` is an optional-output-path option: bare `-ac` succeeds and writes `autocorr.xvg`, while a following pathname overrides that default. For simultaneous y columns, `-av` takes their pointwise mean; rows `0 1 2`, `1 2 4`, and `2 3 6` therefore produce exactly ` 0 1.5`, ` 1 3`, and ` 2 4.5`. In contrast, for `0 0; 1 2; 2 4` followed by `&` and `0 2; 1 4; 2 6`, `-av` writes exactly ` 0 0`, ` 1 2`, and ` 2 4`, including the one leading space on each row; it does not take a pointwise mean of the ampersand-separated sets. The `-av` destination contains only its numeric rows, with no blank, `#`, or `@` header lines; a six-point input produces exactly six nonempty output lines. A requested fit requires an output destination. All produced series have correct columns, monotone coordinates and values computed from the input.

Without an explicit autocorrelation length, `analyze -ac` writes `ceil(N/2)` lag rows for an N-point series. Thus the five input rows `0 1`, `1 2`, `2 3`, `3 4`, and `4 5` produce exactly three numeric rows, with `(time, value)` equal to `(0.000, 1.00000)`, `(1.000, 0.50000)`, and `(2.000, -0.16667)`.

## Spec 10

`eneconv -f EDR... -o OUTPUT` reads one or more energy streams and writes one valid EDR retaining every energy term and frame metadata. It filters inclusively with `-b/-e`, samples by `-dt`, and applies one offset per input through interactive input or `-offset`. Concatenated frames are chronological; overlap and duplicate boundary times are resolved consistently, and `-nosort` preserves explicit input order. One, two, three, and repeated identical inputs work. Negative start times are allowed. On standard error it names each input in `Opened BASENAME as single precision energy file`, prints `Summary of files and start times used:`, lists every input basename and selected start time, and announces the first included frame of each written segment as `Continue writing frames from t=T, step=S`. A nonempty successful result ends with `Wrote N frames`; this uses the literal plural `frames` even when `N` is 1. A backward range (`b > e`) succeeds, creates a valid output containing no data frames, and prints `No frames written.` on standard error, the same outcome as a valid range containing no frames; neither case invents data. No `-f` inputs fails with the missing-default form from Spec 2 and identifies `In option f`; any explicitly missing input fails with the explicit-file form. Output in another directory is honored.

## Spec 11

`editconf -f INPUT -o OUTPUT` converts GRO/PDB/G96 structures and preserves coordinates, names and residue identity unless transformed. Its structure-writing path omits input GRO velocity columns for the `-resnr`-only path; thus renumbering the supplied two-atom velocity-bearing GRO with `-resnr 10` writes residues 10 and 11 without velocity columns. GRO velocity fields that are all zero are likewise classified as absent: the supplied two-atom input prints `No velocities found`, and both `-rotate 90 0 0` and combined `-rotate 0 0 90 -translate 1 1 0` write atom rows without velocity columns. Recognized nonzero velocities instead print `Velocities found`; translation leaves those velocity vectors unchanged, while rotation rotates them by the same rotation applied to coordinates. Inputs without velocities print `No velocities found`. `-translate x y z`, `-rotate ax ay az` (degrees about x, then y, then z), and `-scale sx sy sz` transform coordinates and box consistently; negative scale mirrors. When translation and rotation are combined, translation is applied first and the translated coordinates are then rotated. `-center x y z` places the geometric center at that point; `-c` centers in the box. `-box x y z` sets general box lengths, but `-box L` is also valid with `-bt cubic`, `dodecahedron`, or `octahedron` and uses `L` for all three displayed box-vector lengths. The resulting displayed angles are respectively `90.00  90.00  90.00`, `60.00  60.00  90.00`, and `70.53 109.47  70.53`. `-d d` makes clearance around the solute, and `-bt cubic|triclinic|dodecahedron|octahedron` constructs that box shape. `-angles a b g` sets triclinic angles. `-noc` disables automatic centering. `-resnr N` renumbers residues beginning at N. Invalid `-bt invalid_box` fails with `Invalid value: invalid_box.` followed by `Allowed values: triclinic, cubic, dodecahedron, octahedron.`. Omitting `-o` writes the default `out.gro`, succeeds, and for the supplied single-atom fixture prints the consecutive lines `Read 1 atoms` and `Volume: 27 nm^3, corresponds to roughly 12100 electrons`.

When `-box 5 5 5` sets the box and automatic centering remains enabled, standard output contains the exact lines `new center      :  2.500  2.500  2.500 (nm)` and `new box volume  : 125.00               (nm^3)`. Dodecahedron and octahedron construction use the exact standard-output lines `new box angles  :  60.00  60.00  90.00 (degrees)` and `new box angles  :  70.53 109.47  70.53 (degrees)`, respectively. A translation announces the transformed atom count and compact vector on standard output: the supplied one-atom `-translate 0.5 0.5 0.5` case prints `Translating 1 atoms (out of 1) by 0.5 0.5 0.5 nm`, and the supplied two-atom `-rotate 0 0 90 -translate 1 1 0` case prints `Translating 2 atoms (out of 2) by 1 1 0 nm`. Centering the supplied single atom with `-c` prints the exact indented line `    shift       :  0.500  0.500  0.500 (nm)`.

The canonical GRO writer uses a five-character atom-count field, fixed-width atom records with coordinates to three decimal places (and velocities, when retained, to four), and orthorhombic box components in ten-character fields with five decimal places. It preserves IEEE signed zero produced by a transform. Thus the supplied two-atom negative-x mirror ends in these exact lines:

```text
    2
    1Ar      Ar    1  -0.000   0.000   0.000
    2Ar      Ar    2  -1.000   0.000   0.000
  -3.00000   3.00000   3.00000
```

Converting the supplied two-atom PDB to GRO produces atom lines `    1ALA      C    1   1.000   1.000   1.000` and `    1ALA      N    2   1.200   1.000   1.000`, followed by `   3.00000   3.00000   3.00000`. A requested 5 nm orthorhombic box likewise ends with exactly `   5.00000   5.00000   5.00000`. The canonical G96 writer uses the section sequence `TITLE`, title, `END`, `POSITION`, records, `END`, `BOX`, records, `END`; for the supplied single argon its position and box records are exactly `    1 Ar    Ar         1    1.000000000    1.000000000    1.000000000` and `    3.000000000    3.000000000    3.000000000`. Scaling the supplied 125-atom argon box by 1.1 prints `new box volume  :  62.17` on standard output.

Additional transformation diagnostics are exact. Scaling the supplied 3 nm single-atom box by `-scale 2 2 2` prints `new box volume  : 216.00               (nm^3)`. Centering that atom with `-c` prints `new center      :  1.500  1.500  1.500 (nm)`. Mirroring the supplied 3 nm two-atom box with `-scale -1 1 1` prints `new box volume  : -27.00               (nm^3)`. The combined `-rotate 0 0 90 -translate 1 1 0` invocation prints `Rotating 0, 0, 90 degrees around the X, Y and Z axis respectively` after its translation announcement.

## Spec 12

`genconf -f INPUT -o OUTPUT -nbox nx ny nz` replicates a structure on a 3-D lattice.
