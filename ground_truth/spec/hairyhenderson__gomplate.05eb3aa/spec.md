# Clarified executable specification

The required artifact is a runnable file named exactly `executable`. It is a command-line template renderer with gomplate-compatible behavior as defined below. “Error” means a non-zero exit status unless a more exact status is stated. All text is UTF-8 unless a byte-oriented function is explicitly described. Functions accept their last argument from a template pipeline, so `x | f a` is equivalent to `f a x`. Names are case-sensitive. External programs named after `--`, plugin commands, DNS, HTTP endpoints, and cloud metadata endpoints are supplied by the harness and are not implementations required inside `executable`.

## Spec 1

The command has one rendering mode and no positional subcommands. With no input option it reads a template from standard input and writes the rendered bytes to standard output. Successful runs exit 0 and normally write nothing to standard error. `-V/--verbose` preserves normal output but emits nonempty progress diagnostics on stderr. Unknown flags, positional words before `--`, malformed options, incompatible options, template parse failures, and execution failures are errors. A positional word errors as `unknown command "WORD"`. Template/runtime failures are reported on standard error as a single JSON log object containing at least `"level":"ERROR"` and an `"err"` string with the underlying diagnostic. A template parse failure's `err` chain contains `parse template`. Rendering is streamed: bytes rendered before a runtime failure remain on standard output. For example, with `USER` unset, `-i 'Hello, {{ .Env.USER }}'` exits nonzero but writes `Hello, ` before reporting the missing key. Argument-parser errors may instead use the usage/error form described in Spec 2.

The renderer never adds a newline. A rendering whose entire final result consists only of whitespace is suppressed to zero bytes, whether that whitespace came from literal template text or from an action. For example, standard input containing exactly `   \n\t\n   ` exits 0 with empty stdout, and rendering only `{{ include "w" }}` for a source containing `   \n\t\n   \n` likewise exits 0 with empty stdout. The same `include` between non-whitespace markers preserves all ten source bytes. Otherwise literal input bytes, including blank input, long lines, CRLF, Unicode, and a final newline, are preserved except where template actions replace them. Multiple independent invocations do not retain variables, templates, data-source definitions, caches, configuration, or environment changes from prior invocations.

## Spec 2

`--version` and `-v` print exactly `gomplate version 0.0.0\n` and exit 0. `--help` (and `-h`) exits 0, uses stdout only, contains no `Available Commands:` block, and prints exactly:

```text
Process text files with Go templates

Usage:
  gomplate [flags]

Flags:
  -d, --datasource datasource        datasource in alias=URL form. Specify multiple times to add multiple sources.
  -H, --datasource-header header     HTTP header field in 'alias=Name: value' form to be provided on HTTP-based data sources. Multiples can be set.
  -c, --context datasource           pre-load a datasource into the context, in alias=URL form. Use the special alias `.` to set the root context.
      --plugin strings               plug in an external command as a function in name=path form. Can be specified multiple times
  -f, --file file                    Template file to process. Omit to use standard input, or use --in or --input-dir (default [-])
  -i, --in string                    Template string to process (alternative to --file and --input-dir)
      --input-dir directory          directory which is examined recursively for templates (alternative to --file and --in)
      --exclude strings              glob of files to not parse
      --exclude-processing strings   glob of files to be copied without parsing
      --include strings              glob of files to parse
  -o, --out file                     output file name. Omit to use standard output. (default [-])
  -t, --template strings             Additional template file(s)
      --output-dir directory         directory to store the processed templates. Only used for --input-dir (default ".")
      --output-map string            Template string to map the input file to an output path
      --chmod string                 set the mode for output file(s). Omit to inherit from input file(s)
      --exec-pipe                    pipe the output to the post-run exec command
      --left-delim delimiter         override the default left-delimiter [$GOMPLATE_LEFT_DELIM] (default "{{")
      --right-delim delimiter        override the default right-delimiter [$GOMPLATE_RIGHT_DELIM] (default "}}")
      --missing-key string           Control the behavior during execution if a map is indexed with a key that is not present in the map. error (default) - return an error, zero - fallback to zero value, default/invalid - print <no value> (default "error")
      --experimental                 enable experimental features [$GOMPLATE_EXPERIMENTAL]
  -V, --verbose                      output extra information about what gomplate is doing
      --config string                config file (overridden by commandline flags) (default ".gomplate.yaml")
  -h, --help                         help for gomplate
  -v, --version                      version for gomplate
```

An unknown flag exits 1 and writes the usage to stdout. For `--unknown-argument`, stderr contains both `Error: unknown flag: --unknown-argument` and a second diagnostic beginning `ERROR  err="unknown flag: --unknown-argument"`. This validation still occurs when `--help` is also present. Every value-taking option errors if its value is omitted; the message identifies the flag and says that it needs an argument, and usage is shown. Repeatable options consume one value per occurrence.

## Spec 3

`-i/--in STRING` renders the supplied string and does not consume stdin. `-f/--file FILE` reads a template file; `-f -` means stdin. `-o/--out FILE` writes the result there; `-o -` means stdout. Both separated and equals-attached option values work, including the short form `-o=-`, which writes to stdout. `-f` and `-o` may repeat: their counts must match and corresponding positions are paired. Parent directories for output files are created. An input file's permission bits are inherited by its output unless `--chmod OCTAL` overrides them. Invalid modes error with an `err` chain containing `failed to gather templates for rendering: strconv.ParseUint`; this includes `9999`, `notanumber`, `-1`, and `999`. In particular, `--chmod 999 -i x` reports `strconv.ParseUint: parsing "0999": invalid syntax`. A file whose newly rendered content is byte-for-byte identical is not rewritten, preserving its modification time; changed content is replaced. When the output path is a symbolic link to a regular file, rendering follows the link and replaces the target's content while leaving the symbolic link itself intact; writing `via symlink` through such a link makes its target contain exactly `via symlink`.

Inline input and file input are mutually exclusive. `--input-dir` is mutually exclusive with both, and `--output-dir`/`--output-map` are directory-mode options mutually exclusive with `--out` and with one another. These mutual-exclusion checks take priority over the requirement that a directory output option have `--input-dir`: consequently `--output-map . --out param` and `--output-dir . --out param` report the mutual exclusion. Their `err` chains begin `failed to validate config: only one of these options is supported at a time` and identify the conflicting configuration names. Specifically, the respective pairs are reported as `'in', 'inputFiles'`, `'in', 'inputDir'`, `'inputFiles', 'inputDir'`, `'outputFiles', 'outputDir'`, and `'outputFiles', 'outputMap'`. Supplying an output directory/map without an input directory is an error whose `err` chain contains `failed to validate config: these options must be set together`; an output directory alone identifies the pair as `'outputDir', 'inputDir'`. A count mismatch's `err` chain begins `failed to validate config` and reports both actual counts. In particular, two inputs with one output report `must provide same number of 'outputFiles' (1) as 'in' or 'inputFiles' (2) options`; the implicit single stdin input with two outputs reports the corresponding counts as `(2)` and `(1)`.

An output file is opened lazily when the renderer first writes a result byte. This determines precedence between a directory-valued output and a later execution failure: a file beginning with `{{ .Env.USER }}` when `USER` is absent reaches and reports the missing-key execution error before opening the output, whereas `Hello {{ .Env.USER }}` first attempts to write `Hello ` and therefore reports the directory-opening error before evaluating the missing key. Either failure retains the `renderTemplate: failed to render template` wrapper. A successfully evaluated datasource result likewise reaches output opening before completion.

Opening an output path that is a directory has an `err` chain of the form `renderTemplate: failed to render template TEMPLATE: open OPENED: is a directory`, where `TEMPLATE` is `<arg>` for inline input and the input filename for file input. A single-component output name is reported unchanged, including a Unicode name or a symlink to a directory. For a nested output such as `level1/level2/level3`, the opened component is reported as `open level3: is a directory`. Thus inline output to `dir_out` has exactly `renderTemplate: failed to render template <arg>: open dir_out: is a directory`, while a second file/output pair using input `input2.tmpl` and directory `output2_is_dir` has `renderTemplate: failed to render template input2.tmpl: open output2_is_dir: is a directory`.

If the final rendered result has zero bytes—including an empty template file, an action that renders empty, or an all-whitespace result suppressed under Spec 1—the run exits 0 but does not create an absent requested output file. If `-f -` is listed twice with two output files, stdin is consumed only for the first: the run succeeds, creates the first output, and does not create a second output for the already exhausted stream.

## Spec 4

`--input-dir DIR` recursively processes regular files under `DIR`. Without an output option it writes under the current directory; `--output-dir DIR` instead preserves each selected file's relative path below that directory. It creates parent directories and preserves input permissions unless `--chmod` is set. Source errors identify the failing path.

Selection uses slash-separated, input-root-relative gitignore-style globs. Repeated `--include` patterns form a union and imply that nonmatching files are excluded. Repeated `--exclude` patterns remove matches. The two sets combine, invalid patterns error, and per-directory `.gomplateignore` files add ignore rules; an explicit `--include` match can re-include a path named by an ignore-file rule. Such a re-included ignored path is copied byte-for-byte rather than rendered: with `.gomplateignore` containing `sub/b.t`, input `sub/b.t` containing `B={{3}}`, and includes `sub/b.t` and `.gomplateignore`, both output files are created unchanged and the former still contains `B={{3}}`. An invalid `--include` or `--exclude` pattern `[` has an `err` chain containing `ignore matching failed` and `makePatterns`; the corresponding invalid `--exclude-processing` pattern contains the implementation's exact spelling `passthough matching failed` and also `makePatterns`. A `.gomplateignore` control file is an ordinary selection candidate rather than an automatically copied control file. It is copied unchanged when selected, but is omitted when `--include` patterns do not match it. Thus `--include '*.t' --include 'sub/*.t'` does not copy `.gomplateignore`; adding `--include '.gomplateignore'` does. A matching rule in the file can exclude the control file itself: a `.gomplateignore` containing `.gomplateignore` omits itself, and a rule `*` omits it along with every other path that is not explicitly re-included. `--exclude-processing PATTERN` selects files to copy byte-for-byte instead of parsing, while retaining their path and mode. Template directories supplied with `--template` do not recursively load nested directories.

A nonexistent input directory fails before rendering. In particular, `--input-dir /nonexistent_dir` exits 1 with empty stdout and an `err` chain containing `failed to gather templates for rendering: walkDir` and `no such file or directory`.

`--output-map TEMPLATE` is evaluated once per selected input. Its dot contains `.in`, the relative input path, and `.ctx`, the original root context. It has the normal function/template environment. Leading and trailing whitespace in the mapped result is removed and the remainder is the output path. Template syntax/evaluation failures or invalid mapped paths are errors. An output-map parse failure, such as use of an undefined `invalid_func`, has an `err` chain containing `outFileNamer` before the nested template diagnostic.

## Spec 5

Configuration is YAML (JSON documents are valid YAML and must work). The implicit config is `.gomplate.yaml` in the current directory: absence of that implicit file is ignored, while a missing explicitly named file is an error containing `config file requested, but couldn't be opened`. `--config FILE` selects another file; `--config=` disables config discovery. `GOMPLATE_CONFIG` selects a config unless a command-line `--config` is present, and an explicitly set empty `GOMPLATE_CONFIG` disables config discovery just like `--config=`. Thus an invalid `.gomplate.yaml` is ignored and `GOMPLATE_CONFIG='' --in foo` exits 0 with exactly `foo` on stdout. Invalid YAML/config types produce an error naming the file; its text contains `parsing config file` and `YAML decoding failed`. A YAML syntax error also contains `syntax may be invalid` and retains the parser cause: an unclosed flow sequence reports `did not find expected ',' or ']'`, while an extra mapping colon reports `mapping values are not allowed in this context`.

Precedence for every setting is command line over configuration over environment over built-in default. Supported config keys are `in`, `inputFiles`, `outputFiles` (and scalar `out`), `inputDir`, `outputDir`, `outputMap`, `chmod`, `leftDelim`, `rightDelim`, `missingKey`, `datasources`, `context`, `templates`, `excludes`, `excludeProcessing`, `plugins`, `pluginTimeout`, `postExec`, `execPipe`, and `experimental`. Singular values and sequences/maps are interpreted like their corresponding CLI options. Datasource map entries may be URL strings or objects containing `url` and `header`. In contrast, both `context` and `templates` map entries must use the structured object form rather than a bare URL/path string. For example, bare entries `context: {c: /foo/context.json}` and `templates: {extra: /foo/extra.t}` are configuration decoding errors containing `cannot unmarshal !!str` and `into config.raw`; the corresponding entries with nested `url` fields are accepted. Plugins may be command strings or objects containing `cmd`, `args`, `pipe`, and `timeout`.

The relevant environment settings are `GOMPLATE_LEFT_DELIM`, `GOMPLATE_RIGHT_DELIM`, `GOMPLATE_CONFIG`, `GOMPLATE_EXPERIMENTAL`, `GOMPLATE_PLUGIN_TIMEOUT`, and `GOMPLATE_TYPE_PARAM`. Both `GOMPLATE_EXPERIMENTAL=true` and `GOMPLATE_EXPERIMENTAL=1` enable experimental functions; `false` leaves them disabled. An unrecognized value is ignored rather than producing a Boolean-parse error. In particular, `GOMPLATE_EXPERIMENTAL=perhaps` with inline input `x` exits 0 and renders `x`. With the value `1`, the experimental CIDR functions in Spec 32 execute normally and reach their ordinary success or argument-validation behavior. Plugin timeouts are duration strings. In particular, `GOMPLATE_PLUGIN_TIMEOUT=invalid` fails before rendering with text containing `GOMPLATE_PLUGIN_TIMEOUT set to invalid value "invalid"`.

## Spec 6

Templates implement Go `text/template` semantics. Actions use `{{` and `}}`; `{{-` trims preceding whitespace and `-}}` trims following whitespace. `{{/* ... */}}` is a non-nesting comment. Literals include decimal/base-prefixed integers, floating point, booleans, `nil`, double-quoted escaped strings, and raw backtick strings. `.` is current data, `$` is root, `.name` accesses a map key or exported field/method, chains are allowed, and parentheses group pipelines. `$x := pipeline` declares and `$x = pipeline` assigns, with lexical control-structure scope.

A pipeline is commands separated by `|`; the value from the left becomes the final argument of the next function. Supported actions are `if`/`else if`/`else`/`end`, `with`/`else`, `range` with zero, one, or two variables and an `else` arm for empty input, `break`, `continue`, `define`, `template`, and `block`. In a two-variable range, values are key/index then element. Map iteration is deterministic in sorted key order for orderable scalar keys. Empty means false, numeric zero, empty string/list/map, or nil.

Built-ins are `and`, `or`, `not`, `len`, `index`, `print`, `printf`, `println`, `html`, `js`, `urlquery`, and comparisons `eq`, `ne`, `lt`, `le`, `gt`, `ge`. `and`/`or` short-circuit and return an operand. Printing and formatting follow Go-style formatting (`%s`, `%q`, `%d`, `%v`, `%T`, width/precision, etc.). `html`, `js`, and `urlquery` escape for their named contexts. Undefined functions, malformed actions, invalid comparisons, bad argument counts/types, and failed field/key evaluations error. An unclosed range such as `{{ range .Items }}value` has an `err` chain beginning `renderTemplate: parse template <arg>` and ending in `unexpected EOF`.

## Spec 7

Native rendering uses Go-like text forms: booleans are `true`/`false`, a list is `[a b]`, a map is `map[k:v]`, and nil is `<no value>`. `index` can successively index lists, maps, and strings; a string index returns its byte value. The global `slice` name is Go's slicing built-in, not a collection constructor. Heterogeneous lists are constructed with `coll.Slice`; `coll.GoSlice` is the namespaced slicing function specified later.

The initial root behaves as an empty map for direct rendering/iteration, while a synthetic `.Env` field exposes a map of all process environment variables. Thus `{{.}}` on the unpopulated root renders `map[]`, but `.Env.NAME` remains available. Direct missing map keys error by default. In particular, `{{ .NonExistent }}` has an `err` chain containing both `renderTemplate: failed to render template <arg>` and `map has no entry for key "NonExistent"`. `--missing-key` accepts exactly `error`, `zero`, `default`, or `invalid` (lowercase). `error` fails; `zero` returns the map element type's zero value; `default` and `invalid` render `<no value>`. A missing string-valued environment key therefore renders empty in zero mode. Invalid choices such as `ERROR`, `random`, and `nope` error with an `err` chain containing `failed to validate config`, `not allowed value for the 'missing-key' flag`, and the exact case-sensitive enumeration `Allowed values: ,error,zero,default,invalid`. Specifically, `--missing-key invalid_value` contains `not allowed value for the 'missing-key' flag: invalid_value`. A fallback function cannot intercept a key lookup that already failed in `error` mode.

`--left-delim`/`--right-delim` replace the action delimiters, leaving literal `{{...}}` untouched. Their environment/config counterparts follow Spec 5 precedence. The empty delimiter value is accepted where the CLI parser accepts an explicitly empty value.

## Spec 8

`-t/--template SPEC` loads extra named templates and repeats. `name=PATH` gives an explicit name; a bare file uses its path-derived name. When `PATH` is a directory, each immediate regular file with basename `B` is registered under the joined path derived from the directory specification, not under `B` alone. For a bare directory argument this name is `PATH/B` using the supplied path spelling, so an absolute `PATH` produces an absolute template name; `tmpl.Exec "plain"` does not find `PATH/plain`, while `tmpl.Exec "PATH/plain"` does. For an explicitly named directory, `-t mydir=mydir` makes `mydir/part1.tmpl` and `mydir/part2.tmpl` available under exactly those names. Immediate files are loaded but subdirectories are not traversed, so `-t nd=nd` registers `nd/top.tmpl` while ignoring `nd/sub/...`. A file may also contain `define` blocks. Duplicate/overridden definitions follow template-set semantics; missing files and syntax errors fail before output. A missing template file has an `err` chain containing `parse nested templates` and lowercase `no such file or directory`. Invalid syntax in a loaded file has both the plural wrapper `parse nested templates` and the per-file wrapper `parse nested template`, followed by the parser cause such as `unexpected EOF`.

The `tmpl` namespace provides `tmpl.Exec name [data]`, executing an already loaded named template (default data is current dot); and `tmpl.Inline`, which supports both inline text execution and the named form `tmpl.Inline name text [data]`. The named form parses, registers, and immediately executes the text under `name`, so `{{ tmpl.Inline "T" "{{.}}" 15 }}{{ template "T" 10 }}` renders `1510`. It also provides `tmpl.Path`, the current input filename, and `tmpl.PathDir`, its directory. Global alias `tpl` means `tmpl.Inline`. Template actions and `tmpl.Exec` can call definitions from `--template` files. Recursive inline execution, Unicode names/content, and nesting are supported; missing template names and inline parse/runtime errors fail. In particular, `{{ tmpl.Exec "Nope" }}` reports `template "Nope" not defined` after the normal execution wrappers.

## Spec 9

`--plugin name=path` registers an external executable as a template function and repeats. A value with no equals sign, such as `--plugin name`, exits 1: stdout begins with the normal `Usage:` block, and stderr contains `Error: plugin requires both name and path` followed by the JSON error log. Empty components do not use that validation path. `--plugin '=path' -i x` exits 2 with empty stdout and stderr beginning `panic: function name "" is not a valid identifier`, followed by a blank line and a Go stack trace. `--plugin 'name=' -i x` instead exits 0, writes exactly `x` to stdout, and writes nothing to stderr; the empty-path definition is accepted when the function is not called. A registered plugin may deliberately shadow a built-in global function. Template arguments are converted to strings. In ordinary mode configured prefix arguments followed by template arguments are supplied as argv and the plugin's stdout becomes the function result. With plugin `pipe: true`, the final template argument is sent to stdin instead, after configured argv. Plugin stderr is forwarded. A non-zero exit, launch failure, or timeout is a template error. A non-zero exit from a plugin named `errfunc` is wrapped with `error calling errfunc`; if the process exits 5, the chain contains `exit status 5`. A timeout configured globally, by either config or `GOMPLATE_PLUGIN_TIMEOUT`, reports `plugin timed out after` followed by the elapsed duration and cause. The default timeout is 5 seconds, overridden globally by config/environment and per plugin by its object `timeout`.

Arguments after a standalone `--` are a post-render command, even when the command name begins with `-`. It runs only if all rendering succeeded. A post-render command's non-zero status is reported but is not propagated numerically: if it exits 9, the renderer exits 1 and its diagnostic contains `exit status 9`. A launch failure's diagnostic contains `exec:` followed by the command error. Without `--exec-pipe`, normal outputs are written first and the command inherits standard streams; for example a supplied `cat output` may print that file. With `--exec-pipe`, rendered output is piped to the supplied command's stdin and the command's stdout is the command's result; a post-render command is required and file output settings do not capture the rendered bytes. Using `--exec-pipe` without that command errors with `execPipe may only be used with a postExec command`.

## Spec 10

`-d/--datasource alias=URL` defines a lazily read data source; `-c/--context alias=URL` eagerly reads one into the root at `.alias`. Context alias `.` replaces the root with the decoded value. Repeat definitions coexist. An empty definition such as `-d d=` does not register `d`; subsequently reading it errors with `undefined datasource 'd'`. Plain local filenames in the current directory may omit `alias=` and infer the alias from the filename stem; ambiguous paths such as a subdirectory path require an explicit alias. In particular, `-d subdir/file.json` errors with `invalid argument (subdir/file.json): must provide an alias with files not in working directory`. `-H/--datasource-header alias=Name: value` attaches repeatable headers to an HTTP source; a missing `=` or `:` is an error. For the missing-equals value `test`, the diagnostic contains `invalid datasource-header option 'test'`; for `test=InvalidHeader`, it contains `invalid HTTP Header format 'InvalidHeader'`.

`datasource source [path...]` (global alias `ds`) loads and decodes a source, with optional path/query arguments appended appropriately. `source` may be a registered alias or a URL supplied directly in the call. For example, `ds "env:FOO"` and a source registered as `-d test=env:FOO` both read `FOO`; `env:NAME` is shorthand for the `env:///NAME` form. A direct HTTP(S) URL performs the same HEAD/GET, content decoding, and URL/query-selected format decoding as a registered HTTP source, including the media-type rules in Specs 11 and 12. Against a text/plain HTTP response whose body is `{"value":7}`, direct `ds` of a URL ending in `?type=json` exits 1 with empty stdout and an error containing `data of type "json" not yet supported`; changing the query to `?type=application/json` exits 0 and renders `7` when the template selects `.value`. `include alias [path...]` returns the source's exact raw bytes as text, subject to the final all-whitespace suppression in Spec 1. `datasourceExists alias` reports whether it is defined without requiring successful I/O. `datasourceReachable alias` attempts reachability and returns a boolean rather than failing for an unreachable source. `listDatasources` returns defined aliases in stable order. `defineDatasource alias URL` adds a source at template execution time and returns an empty value. Undefined aliases error with `undefined datasource 'ALIAS'`; a call `ds "mydata"` has an `err` chain containing both `renderTemplate: failed to render template <arg>` and `undefined datasource 'mydata'`. The undefined-source diagnostic also prefixes the URL parse cause when an unregistered alias such as `http://[invalid` cannot be parsed. Other malformed definitions error. `foo::bar` is interpreted as a URL using the unavailable `foo` scheme, not as a local filename; when a source declared as `bad=foo::bar` is read, its diagnostic contains `couldn't read datasource 'bad'`. Values are cached by complete source identity plus requested path/query, so repeated reads are stable within a run.

## Spec 11

File sources accept relative paths, absolute paths, and `file://` URLs. Relative paths are resolved from the process working directory. A file's parser is inferred from its extension; a directory source produces the sorted names of its immediate entries. Missing/unreadable paths error. Symlinks behave like operating-system file access. Because `--context` is eager, `-c data=/nonexistent.json` fails before rendering with an `err` chain containing `couldn't read datasource 'data'`; malformed structured context fails with `unable to unmarshal` while retaining the format parser's cause. In particular, YAML context text `key: [value` reports `yaml: line 1: did not find expected ',' or ']'`. A lazy `--datasource` is instead read during template execution, so `-d data=/nonexistent.json -i '{{ ds "data" }}'` has an `err` chain containing both `renderTemplate: failed to render template <arg>` and `couldn't read datasource 'data'`.

Recognized structured formats are JSON (`.json`), YAML (`.yaml`, `.yml`), TOML (`.toml`), CSV (`.csv`), dotenv (`.env`), and CUE; other content is plain text. A URL query `?type=...` overrides all inferred types, but its value is interpreted as a media type rather than as a filename-extension label. The query parameter name defaults to `type` and is replaced by `GOMPLATE_TYPE_PARAM`; its URL-decoded value, including `+` behavior, selects the type. Thus, with `data.txt` containing `{"v":5}`, `-d 'q=data.txt?type=json' -i '{{(ds "q").v}}'` exits 1 with empty stdout and an error containing `data of type "json" not yet supported`, whereas replacing the query value with `application/json` exits 0 and renders exactly `5`. For HTTP sources without that explicit override, the response MIME `Content-Type` selects the parser: `application/json` is decoded as JSON even for an extensionless URL or one ending in `.txt`. Failure to decode malformed structured content has an `err` chain containing `unable to unmarshal`.

A missing file read through a named datasource has an `err` chain containing both `couldn't read datasource 'ALIAS'` and lowercase `no such file or directory`. Reading a missing direct `file:///...` datasource also contains lowercase `no such file or directory`.

`stdin:///path` exposes stdin as a virtual source. Validation differs between a path embedded in the registered URL and a path argument appended to a root source. A named source registered as `stdin:///../invalid` is rejected with an error containing both the complete URL `stdin:///../invalid` and `open ../invalid: invalid argument`; `stdin:///./file` similarly reports `open ./file: invalid argument`. In contrast, after registering `-d 's=stdin:///'`, both `printf x | executable -d 's=stdin:///' -i '{{include "s" "../invalid"}}'` and the same invocation with path `./file` exit 0, render exactly `x`, and write nothing to stderr. The empty/root path, `.`, ordinary relative paths (including nested and long names), and these traversal-like path arguments therefore work for a root registration. Binary, Unicode, empty, whitespace-only, multiline, and CRLF content is byte-preserved. This source can be used while the actual template comes from `-i`. Caching includes the requested path: repeated reads of the same path return the cached bytes, but distinct accepted paths consume the shared stdin stream independently. Consequently, with stdin bytes `61 0d 0a 00`, `{{include "s" "nested/name"}}|{{include "s" "."}}` renders bytes `61 0d 0a 00 7c`, while two reads of `nested/name` render `61 0d 0a 00 7c 61 0d 0a 00`.

## Spec 12

`env:///NAME` reads environment data. A set variable wins even if empty. If it is unset and `NAME_FILE` is set nonempty, that file is read and surrounding whitespace bytes are trimmed; arbitrary remaining bytes, including invalid UTF-8 and NUL, are preserved. For example, fallback-file bytes `61 62 63 ff 00 78 79 7a 0a` produce stdout bytes `61 62 63 ff 00 78 79 7a`. A nonexistent fallback file errors with lowercase `no such file or directory`. An empty `NAME_FILE` is treated as absent, so if neither source supplies a value, reading the source errors with `file does not exist`. Parent/absolute path escapes are rejected and their normalized source text is retained in the error chain: reading a named `env:///../invalid` source includes `env:///../invalid` and `open ../invalid: invalid argument`, while `env:////absolute/path` includes `absolute/path` and ends with `file does not exist`. Normal type selection still applies.

HTTP(S) sources perform the required HEAD/GET requests, follow normal URL path/query resolution, apply configured headers, decode `gzip` content encoding, and parse by explicit query type before MIME or URL inference. Without an explicit type query, MIME does trigger structured parsing: an extensionless response with `Content-Type: application/json` is decoded to a map, including when its body uses `Content-Encoding: gzip`. This applies equally to a source declared by `defineDatasource`; for example, accessing a decoded `headers.Foo` field can render `bar`, and a gzipped JSON response can expose the request's `Accept-Encoding` value `gzip`. An explicit `?type=text/plain` overrides `Content-Type: application/json` and leaves the body a string, while `?type=application/json` overrides `Content-Type: text/plain` and decodes the body. The shorter query value `?type=json` is not a JSON selector: when `g` is a gzipped JSON source containing `{"value":7}` and `j` is a text/plain source with that same body, `{{include "g"}}|{{(ds "j").value}}` with `j` queried as `?type=json` exits 1 after writing exactly `{"value":7}|` and reports `data of type "json" not yet supported`. Querying `j` as `?type=application/json` instead exits 0, writes exactly `{"value":7}|7`, and emits no stderr. `include` returns the decoded response body exactly. Reachability reflects endpoint status without crashing.

A `merge:source1|source2|...` URL requires at least two already resolvable component URLs/aliases, each decoding to a map. A one-part merge errors with `need at least 2 datasources to merge`. It recursively merges nested maps. Earlier sources have precedence over later ones at conflicts while disjoint keys are retained. JSON, YAML, and TOML maps may be mixed. A component that is neither registered nor a parseable URL errors with `unknown datasource`; failure to open a component has an `opening merge part` wrapper. A component that decodes to a non-map errors with `merge: can only merge maps`; for example a JSON array first component reports that phrase after identifying its `[]interface {}` data type. Other undefined components and malformed input error.

## Spec 13

The `data` parsers, each also available through the shown lowercase global alias, are:

- `data.JSON`/`json`: decode one JSON value; `data.JSONArray`/`jsonArray`: decode a JSON array.
- `data.YAML`/`yaml`: decode the first YAML document into maps/lists/scalars; `data.YAMLArray`/`yamlArray`: require an array. YAML anchors and aliases work, numeric map keys are recursively stringified, and an empty document is an empty map.
- `data.TOML`/`toml`: decode TOML tables, arrays, dates/scalars, and nesting.
- `data.CUE`/`cue`: evaluate a CUE value, including integers, floats, booleans, null, lists, objects, byte literals, constraints with concrete defaults, and nested values. A value need not be fully concrete: the invocation ``{{cue `{a: int}`}}`` succeeds and renders `map[a:<nil>]`.
- `data.CSV`/`csv [delimiter] input`: return a list of rows, each a list of strings. A leading exactly-one-character string is recognized as the optional delimiter. A longer string is instead input, not an invalid delimiter: ``{{csv "::" `a`}}`` succeeds and renders `[[::] [a]]`.
- `data.CSVByRow`/`csvByRow [delimiter [headers]] input`: return one map per data row; absent explicit headers, the first row supplies names. Explicit headers are a delimiter-separated string.
- `data.CSVByColumn`/`csvByColumn [delimiter [headers]] input`: return a map from each header to its column list.

CSV honors quoted fields, embedded separators/newlines, CRLF, Unicode, and empty fields. Inconsistent field counts and malformed quoting error with row/line context. All parsers accept pipeline input as their last argument. Wrong top-level shape, malformed syntax, trailing invalid data, or wrong argument type/count errors.

Dotenv data recognizes blank/comment lines, optional `export`, `KEY=value`, quoted values, escapes, empty values, and equals signs inside values. It produces a string map.

Parser failures retain their format-specific wrapper and underlying diagnostic. In particular, `-i '{{ data.YAML "key: value\n  bad_indent: value" }}'` exits 1 and its `err` string is exactly `renderTemplate: failed to render template <arg>: template: <arg>:1:7: executing "<arg>" at <data.YAML>: error calling YAML: yaml: line 2: mapping values are not allowed in this context`. Likewise, `-i '{{ data.CUE "{invalid" }}'` exits 1 with `err` exactly `renderTemplate: failed to render template <arg>: template: <arg>:1:7: executing "<arg>" at <data.CUE>: error calling CUE: unable to process CUE: expected '}', found 'EOF'`.

## Spec 14

Serializers are inverses of the corresponding structured formats:

- `data.ToJSON`/`toJSON value` emits compact JSON. `data.ToJSONPretty`/`toJSONPretty [indent] value` emits indented JSON, defaulting to two spaces, with deterministic key handling and a trailing newline only as produced by the serializer.
- `data.ToYAML`/`toYAML` emits block YAML (`key: value`, sequence entries with `-`) deterministically; non-ASCII characters may use YAML escapes such as `\U0001F30D`.
- `data.ToTOML`/`toTOML` emits valid TOML tables/scalars.
- `data.ToCSV`/`toCSV [delimiter]` requires a two-dimensional sequence, quotes fields as needed, and uses CRLF row terminators. The delimiter must be one character.
- `data.ToCUE`/`toCUE` emits valid concrete CUE.

They preserve nulls, booleans, numbers, Unicode, nested lists/maps, and empty structures to the extent the target format supports them. Unsupported values or shapes, invalid delimiters, and cyclic/unserializable data error.

`data.ToCUE` uses native CUE struct presentation rather than JSON presentation: `dict "name" "test" "value" 42 | data.ToCUE` renders a braced, multiline struct containing the unquoted fields `name:  "test"` and `value: 42`. `coll.Slice "a" "b" | data.ToCSV` exits 1 with an `err` chain containing `error calling ToCSV: can't parse ToCSV input - must be a two-dimensional array (like [][]string or [][]any) (was []interface {})`. With the valid two-dimensional input `coll.Slice (coll.Slice "a" "b")`, passing numeric delimiter `123` exits 1 and the chain contains `error calling ToCSV: can't parse ToCSV delimiter (123) - must be string (is a int)`.

## Spec 15

The basic collection functions (also available through the lowercase global aliases documented here where stated) are:

- `coll.Dict`/`dict key value ...` creates a string-keyed map, stringifying keys; an unmatched final key gets an empty value. Zero arguments makes an empty map.
- `coll.Slice value ...` creates a heterogeneous list and accepts zero or more values. It has no global alias.
- `coll.Has collection item`/`has` tests list membership or map-key presence, but `item` must be a string. `{{has (coll.Slice "1" "2") "2"}}|{{has (dict "x" 1) "x"}}` exits 0 and renders `true|true`. `{{has (coll.Slice 1 2) 2}}|{{has (dict "x" 1) "x"}}` instead exits 1 with empty stdout and an error ending `executing "<arg>" at <2>: expected string; found 2`.
- `coll.Keys map ...`/`keys` and `coll.Values map ...`/`values` concatenate each map's values in sorted-key order, preserving the order of map arguments.
- `coll.Append value list`/`append` and `coll.Prepend value list`/`prepend` return new lists without mutating the source.
- `coll.Uniq list`/`uniq` keeps first occurrences in stable order; `coll.Reverse`/`reverse` returns reversed input.
- `coll.Flatten [depth] list`/`flatten` recursively flattens nested lists; omitted depth means fully, while a nonnegative depth limits nesting removed.
- `coll.Sort [key] list`/`sort` sorts homogeneous numbers or strings ascending and can sort maps by `key`; unsupported/mixed input is returned unchanged rather than corrupted.

`coll.Index index... collection` performs strict successive indexing. List/string indices are zero-based integers; string indices expose bytes. Map indices are keys. Any negative index, non-integer sequence index, missing map key, index at/after length, or indexing a scalar errors. Encountering nil while following a multi-index chain reports `index of nil pointer`, while using nil itself to index a slice/array reports `cannot index slice/array with nil`. A missing string key `nonexistent` reports `map has no key nonexistent`; using an integer to index a string-keyed map reports `value has type int; should be string`.

Global `slice item [low [high [max]]]` is Go's zero-based, half-open slicing built-in. It requires at least the item argument, works on arrays/slices and strings, and does not construct lists. Its error chain includes `error calling slice`. Slicing an integer or boolean reports respectively `can't slice item of type int` or `can't slice item of type bool`; a map reports `can't slice item of type map[string]interface {}`. A string with three indices reports `cannot 3-index slice a string`. A negative bound reports `index out of range: -1`, and a third bound of 10 beyond capacity reports `index out of range: 10`.

`coll.GoSlice item [low [high [max]]]` uses Go's zero-based half-open slicing. Omitted bounds use zero/length. Strings are sliced by bytes and do not accept a third index. Empty slices are valid; negative bounds, too many indices, low greater than high, bounds beyond length/capacity, or nonslice input error. Its exact bound diagnostics include `invalid slice index: 2 > 1` when low 2 exceeds high 1, `index out of range: 5` when a bound is 5 beyond the available range, and `invalid slice index: 4 > 3` when high 4 exceeds max 3. Supplying four slice indexes reports `too many slice indexes: 4`. Each appears after the template/function wrappers, including `error calling GoSlice`.

## Spec 16

Collection map operations are:

- `coll.Merge map...`/`merge` recursively combines maps from left to right while preserving the first/leftmost value at any conflict. Inputs are not unexpectedly aliased or destroyed.
- `coll.Pick key... map` returns only named existing keys; `coll.Omit key... map` returns all but those keys.
- `coll.Set key value map`/`set` sets the key and returns the same map; `coll.Unset key map`/`unset` deletes it and returns the map. Nested values can be further operated upon normally.

Map key ordering is deterministic wherever rendered as keys/values or serialized. Collection equality operations work for comparable scalar values and robustly handle nested/uncomparable values without a process panic. Membership through `coll.Has`/`has` is the string-item operation specified in Spec 15; comparable non-string scalars are not accepted as its item argument. Wrong types and missing required arguments cause template errors.

## Spec 17

`coll.JQ expression input` (global `jq`) evaluates jq-style filters on already decoded data; a string input remains a string rather than being implicitly JSON-decoded. One produced value is returned directly, no results yield an empty list, and multiple results are returned as a list. It supports property/index access, optional and negative indices, array slices, `.[]`, pipes and commas, constructors, `select`, `map`, `map_values`, recursive descent `..`, comparisons/arithmetic including `%`, object `+`, alternative `//`, `if ... then ... else ... end`, and the tested helpers `keys`, `to_entries`, `sort`, `length`, `add`, `ascii_upcase`, `split`, `type`, `flatten`, `unique`, `group_by`, `min`, `max`, `has`, `contains`, `reverse`, `join`, `first`, and `last`. Syntax and type/runtime errors fail template execution. A syntax failure's chain contains `jq parsing expression`; specifically, expression `[invalid syntax` reports `jq parsing expression "[invalid syntax": unexpected token "syntax"`. A type/runtime failure's chain contains `jq execution`. Specifically, applying expression `.foo` to `(coll.Slice 1 2)` exits 1 with empty stdout and a chain ending `jq execution: expected an object but got: array ([1,2])`.

`coll.JSONPath expression input` (global `jsonpath`) evaluates JSONPath over decoded maps/lists. It supports root `$`, dotted and bracketed fields, array indices, wildcards, nested selectors, predicates, and recursive descent `$..field`. A single recursive match is returned directly; multiple recursive matches are returned as a list in document order (for example `$..b` over two nested `b` fields has length 2). Invalid paths and incompatible operations error.

## Spec 18

Environment helpers are `env.Getenv name [default]` (global `getenv`), `env.HasEnv name`, `env.Env` (a snapshot string map), and `env.ExpandEnv string`. `Getenv` uses its optional default when the resolved value is empty as well as when it is absent; for example, an explicitly empty `EMPTY_TEST_VAR` makes `env.Getenv "EMPTY_TEST_VAR" "default"` render `default`. When `NAME` is unset or empty but `NAME_FILE` names a file, `Getenv` reads that file and trims surrounding whitespace. `HasEnv` remains true for empty variables. `ExpandEnv` substitutes `$NAME` and `${NAME}` using the process environment and replaces missing variables with empty text. Unicode, equals signs, and multiline values are preserved.

`conv.Default fallback value` (global `default`) returns fallback when value is nil, false, numeric zero, or an empty string/list/map; otherwise value. `conv.Join collection separator` (global `join`) stringifies and joins list/array elements, producing empty for an empty collection and erroring on scalars. Thus `conv.Join (coll.Slice "a" "b" "c") ","` renders `a,b,c`, the same call with an empty separator renders `abc`, joining the typed string slice returned by `strings.Split "," "1,2,3"` with `"-"` renders `1-2-3`, and joining the one-element collection `[only]` renders `only`. Passing a scalar collection errors with `input to Join must be an array`. `conv.URL string` (global `urlParse`) returns a URL object exposing at least `Scheme`, `Host`, `Hostname`, `Port`, `Path`, `RawQuery`, `Fragment`, and parsed query access; malformed escapes error.

## Spec 19

`conv.ToBool` maps boolean true to true; numeric value exactly 1 to true; and case-insensitive strings `1`, `1.0`, `t`, `true`, and `yes` to true. False, zero, other numbers (including 42), empty strings, `y`, `on`, other false-like/unrecognized strings, nil, maps, and lists are false. Neither `conv.Bool` nor a global `bool` function exists: `conv.Bool true` fails at execution with `can't evaluate field Bool in type interface {}`, while `bool true` fails while parsing with `function "bool" not defined`. `conv.ToBools value...` applies the conversion independently to zero or more variadic arguments and returns their list: no arguments render `[]`, and `conv.ToBools true 1 "yes" false 0 "no"` renders `[true true true false false false]`.

`conv.ToInt`/`conv.ToInt64` accept booleans, numeric values, and numeric strings. Strings may contain comma grouping, sign, base prefixes (`0x`, `0o`, `0b`), legacy leading-zero octal, decimal fractions, and scientific notation; fractional values truncate toward zero. Invalid values error. In particular, converting the map `dict "a" 1` with `conv.ToInt64` reports `could not convert map[a:1] to int64`, and a bad element in `conv.ToInts` or `conv.ToInt64s` reports `could not convert`. The textual maximum uint64 is a reference-compatible overflow exception: `conv.ToInt64 "18446744073709551615"` succeeds and renders `-9223372036854775808`. `conv.ToInts value...` and `conv.ToInt64s value...` convert each variadic argument and return a list. Each accepts zero arguments and then renders `[]`; with arguments `1 2.5 "3"`, either renders `[1 2 3]`. A list passed as the sole argument is treated as one conversion input and errors rather than being flattened. `conv.ToFloat64` similarly converts booleans/numbers/strings (including prefixed and leading-zero integers) and preserves fraction/scientific values; converting `dict "a" 1` reports `could not convert map[a:1] to float64`. `conv.ToFloat64s value...` is likewise variadic and accepts zero arguments, rendering `[]`; inputs `1 2.5 "3.5"` render `[1 2.5 3.5]`, while a bad element reports `could not convert`.

`conv.ParseInt text base bits`, `conv.ParseUint text base bits`, and `conv.ParseFloat text bits` perform strict sized parsing; base zero honors prefixes. `conv.Atoi text` is strict decimal integer parsing. Invalid base, bit size, sign for unsigned, syntax, overflow conditions outside the underlying numeric type, and wrong arguments error. `ParseFloat` accepts floating-point special values: in particular, `conv.ParseFloat "NaN" 64` exits 0 and renders `NaN`. Invalid textual input to `ParseInt` or `ParseUint` has an error chain containing `error calling ParseInt` or `error calling ParseUint`, respectively, and `invalid syntax`. Invalid textual input to `Atoi` contains both `error calling Atoi` and `invalid syntax`.

`conv.ToString` maps nil to literal `nil`, byte arrays to their decoded byte string, strings unchanged, and other values to their native printable form. `conv.ToStrings value...` applies that conversion to each variadic argument and accepts zero arguments, rendering `[]`; `conv.ToStrings 1 2.5 true "text"` renders `[1 2.5 true text]`, and `conv.ToStrings "hello" nil "world"` renders `[hello nil world]`. A collection supplied as one argument is treated as one value rather than flattened, so `conv.ToStrings (coll.Slice 1 2.5 "text")` renders `[[1 2.5 text]]`.

## Spec 20

String functions always accept their primary input last and preserve Unicode unless a byte limitation is stated:

- `strings.Contains needle input`, `HasPrefix prefix input`, and `HasSuffix suffix input` are case-sensitive.
- `strings.Split separator input` preserves empty pieces. `strings.SplitN separator n input` follows Go split-count semantics (negative all, zero empty list, positive at most n pieces).
- `strings.ToLower`/global `toLower`, `ToUpper`/`toUpper`, and `Title`/`title` perform Unicode-aware casing.
- `strings.Trim cutset`, `TrimLeft cutset`, `TrimRight cutset`, `TrimPrefix prefix`, `TrimSuffix suffix`, and `TrimSpace`/`trimSpace` have their conventional Go meanings.
- `strings.ReplaceAll old new input`/`replaceAll`, `Repeat count input`, `RuneCount input`, and `SkipLines count input` do exactly those operations. Repeat rejects a negative count and reports `negative count N`, including `negative count -1` for count -1. SkipLines removes the first count newline-delimited lines, with zero unchanged and excessive count producing empty.
- `strings.Quote`/`quote` returns a Go-style double-quoted escaped literal. `strings.Squote`/`squote` uses a SQL-style single-quoted form in which an embedded single quote is doubled, so `squote "a'b"` renders `'a''b'`. `strings.ShellQuote`/`shellQuote` returns one POSIX-shell-safe word, escaping embedded single quotes.

`strings.Indent [count] [indent] input` (global `indent`) prefixes each nonempty line and leaves empty lines unprefixed, including empty lines inside the value and a trailing blank line. Thus indenting `a\n\nb` by two spaces produces `  a\n\n  b`. With only a number, the unit is one space; with only a string, it is used once; with both, the string is repeated `count` times. Empty input stays empty. `strings.Trunc count input` uses byte counts rather than Unicode code points for positive counts and can split UTF-8: `strings.Trunc 2 "a雪🌍"` emits bytes `61 e9`. Negative counts leave the input unchanged: `strings.Trunc -2 "abcdef"` renders `abcdef`, and both `strings.Trunc -2 "a雪🌍"` and `strings.Trunc -4 "a雪🌍"` emit the full original byte sequence `61 e9 9b aa f0 9f 8c 8d`. It does not pad. `strings.Abbrev [offset] width input` truncates to exactly the requested maximum with `...`: width 10 maps `This is a long sentence` to `This is...`, and offset 5/width 15 maps `This is a much longer sentence` to `...is a much...`; short inputs are unchanged.

## Spec 21

Higher string transforms are deterministic. `strings.Slug` lowercases, transliterates accented Latin letters, replaces punctuation/whitespace runs with `-`, trims separators, and spells `@` as `at`; for example `Hellö, Wôrld! Free @ last` becomes `hello-world-free-at-last`. `strings.CamelCase`, `SnakeCase`, and `KebabCase` remove punctuation/spacing into their named forms while retaining non-ASCII letters. Required examples include `CamelCase "hello_world_test" == "helloworldtest"`, and both `SnakeCase "HelloWorldTest"` and `KebabCase "HelloWorldTest"` produce `Helloworldtest`; `Hellö, Wôrld! Free @ last...` produces respectively `HellöWôrldFreeLast`, `Hellö_wôrld_free_last`, and `Hellö-wôrld-free-last`.

`strings.WordWrap width input` wraps at whitespace without breaking a word longer than the width, preserves paragraph/newline structure, removes wrap-point spaces, and never adds trailing spaces. URLs and other long unbroken tokens remain whole. A zero or negative width returns the input unchanged (`strings.WordWrap 0 "x"` and `strings.WordWrap -1 "x"` both render `x`); invalid width types error.

## Spec 22

Regular expressions use Go/RE2 syntax and UTF-8 text. `regexp.Match expression input` is boolean. `regexp.Find` returns the leftmost match or empty string. `regexp.FindAll expression [n] input` returns nonoverlapping matches; negative n means all and zero means an empty list. `regexp.QuoteMeta` escapes every regexp metacharacter.

`regexp.Replace expression replacement input` replaces all matches and expands `$1`, `${1}`, `$name`, and `${name}` capture references. `regexp.ReplaceLiteral` performs the same matching but treats `$` and backslashes in replacement literally. `regexp.Split expression [n] input` follows Go regexp split limits: zero gives an empty list, negative gives all, and positive gives at most n substrings. Empty matches, Unicode, anchors, classes, alternation, groups, and named groups supported by RE2 work. Invalid patterns, invalid argument counts, and non-string patterns error rather than crashing.

Every invalid-pattern error retains the called function's wrapper. Thus invalid calls to `regexp.Find`, `regexp.FindAll`, `regexp.Replace`, `regexp.ReplaceLiteral`, and `regexp.Split` respectively contain `error calling Find`, `error calling FindAll`, `error calling Replace`, `error calling ReplaceLiteral`, and `error calling Split`, followed by the RE2 parse cause. `Match`, `Replace`, `ReplaceLiteral`, and `Split` also put `error compiling expression` between those layers; `Find` and `FindAll` do not. For `regexp.Match "[" "text"`, the underlying cause contains `error parsing regexp: missing closing ]`. Likewise, `regexp.Find "[" "text"` contains both `error calling Find` and `error parsing regexp: missing closing ]`, while `regexp.Find "*" "text"` contains both `error calling Find` and `error parsing regexp: missing argument to repetition operator`. The same function-wrapper rules apply to malformed named captures, missing brackets or parentheses, unexpected parentheses, and invalid repetition operators.

## Spec 23

Math functions accept integers, floats, booleans where conversion permits, and numeric strings including grouping commas, scientific notation, base-prefixed integers, and the special floating-point strings `+Inf`, `-Inf`, and `NaN`. Max/min use Go floating-point special-value behavior; in particular `math.Max -0 "+Inf" "NaN"` returns `+Inf`. A nonnumeric value errors with conversion context containing the offending value; for example `math.Round "foo"` contains `could not convert "foo" to float64`.

`math.Add`/global `add` and `math.Mul`/`mul` are variadic; `math.Sub`/`sub`, `math.Div`/`div`, and `math.Rem`/`rem` take two operands. Division has numeric division semantics, prints an exact integer without `.0` when integral, and division/remainder by zero errors; `math.Div 10 0` has an error chain containing `division by 0`, while `math.Rem 5 0` contains `runtime error: integer divide by zero`. Remainder has the dividend's sign. `math.Abs`, `Ceil`, `Floor`, and `Round` (halves away from zero) work on negative and positive values. Integer input to `math.Abs` produces the concrete dynamic type `int64`, so `printf "%T" (math.Abs -5)` renders `int64`. `math.Pow`/`pow` returns an `int64` result for integer base/exponent, so `printf "%T" (math.Pow 2 3)` renders `int64`; a negative integer exponent truncates to 0, float bases produce float results, and `0^0` is 1. `math.Max` and `math.Min` accept multiple values. If any candidate is a float, the selected result is promoted to `float64`: `printf "%T:%v" (math.Max 2 1.5) (math.Max 2 1.5)` renders `float64:2`, and the corresponding `math.Min` result is `float64:1.5`.

`math.IsInt`, `math.IsFloat`, and `math.IsNum` report whether a value is recognizable in that category; prefixed integer strings count as integers and ordinary decimal/exponent strings as floats/numbers. Unlike arithmetic conversion, classification does not accept comma grouping: `math.IsNum "1,000"` renders `false`.

For invalid operands, `math.Abs "invalid"` and either invalid operand of `math.Pow` have an error chain containing `expected a number` followed by the quoted conversion cause `could not convert "invalid" to float64`. Each of `math.Floor "invalid"`, `math.Round "invalid"`, and `math.Ceil "invalid"` contains `n must be a number` as well as that conversion cause. `math.Add 1 "invalid"` and `math.Mul 1 "invalid"` contain `expected number inputs`. `math.Sub`, `math.Rem`, `math.Max`, and `math.Min` contain `expected a number` and the quoted offending input when any operand is invalid, including a later variadic operand of `Max` or `Min`; for the string `"invalid"`, their conversion cause contains `could not convert "invalid" to int64: strconv.ParseFloat: parsing "invalid": invalid syntax`.

`math.Seq`/`seq` takes `end`, `start end`, or `start end step`, and returns an inclusive integer sequence. Default start is 1 and default direction moves toward end. A positive supplied step is negated when needed for descending order, so `seq -5 -10 2` is `[-5 -7 -9]` and `seq 10 0 2` is `[10 8 6 4 2 0]`. It stops before crossing an unaligned end, equal endpoints yield one value, and step zero yields an empty list. A nonnumeric start, end, or step reports `expected a number` followed by its conversion cause; this applies respectively to `seq "invalid" 5`, `seq 1 "invalid"`, and `seq 1 5 "invalid"`. Bad arity reports `expected 1, 2, or 3 arguments, got N`, where `N` is the supplied count; this reports `got 0` for no arguments and `got 4` for four arguments.

## Spec 24

Time parsing/formatting uses Go reference-time layouts. Constants exposed in `time` include `ANSIC`, `UnixDate`, `RubyDate`, `RFC822`, `RFC822Z`, `RFC850`, `RFC1123`, `RFC1123Z`, `RFC3339`, `RFC3339Nano`, `Kitchen`, `Stamp`, `StampMilli`, `StampMicro`, and `StampNano`, with their standard Go layout strings.

`time.Parse layout value` parses in UTC when the value lacks a zone. `time.ParseLocal` uses the process local zone. `time.ParseInLocation layout zone value` loads the named IANA/UTC location. `time.Unix seconds [nanoseconds]` accepts integers or strings, including base-prefixed seconds and decimal-seconds strings. Its decimal parser adds the unsigned fractional digits to the signed integral portion: `time.Unix "-0.5"` therefore produces `1970-01-01T00:00:00.5Z`, while `time.Unix "-1.5"` produces `1969-12-31T23:59:59.5Z`. Fractional digits after the ninth are accepted and discarded, so both `time.Unix "1.1234567890"` and `time.Unix "1.12345678901"` produce `1970-01-01 00:00:01.123456789 +0000 UTC`. Multiple dots, invalid digits, and range overflow error. In particular, `time.Unix "1.2.3"` exits 1 with empty stdout and a cause ending `can not parse '1.2.3' as a number - too many decimal points`. `time.ParseDuration` recognizes signed combinations of `ns`, `us`/`µs`, `ms`, `s`, `m`, and `h`.

`time.Now` returns the current instant; `time.Since instant` and `time.Until instant` return durations. There is no namespace function `time.Format`: attempting `time.Format "2006/01/02" instant` fails with `can't evaluate field Format in type interface {}`. Formatting is instead the time value's `instant.Format layout` method. Unit constructors `time.Nanosecond`, `Microsecond`, `Millisecond`, `Second`, `Minute`, and `Hour` multiply a numeric count and reject nonnumeric values. `time.ZoneName` and `time.ZoneOffset` return the effective zone name and seconds east of UTC.

A time value exposes `Format`, `UTC`, `Local`, `In`, `Add`, `AddDate`, `Sub`, `Before`, `After`, `Equal`, `Year`, `Month`, `Day`, `Hour`, `Minute`, `Second`, `Nanosecond`, `Weekday`, `Truncate`, `Round`, `IsZero`, `Location`, and `String` with Go time semantics. A duration exposes its canonical string plus `Hours`, `Minutes`, `Seconds`, `Milliseconds`, `Microseconds`, `Nanoseconds`, `Round`, and `Truncate`. Bad layouts, locations, durations, receiver types, or arguments error.

Template-call failures retain the called time function's wrapper. Invalid input to `time.Parse`, `time.ParseInLocation`, `time.Unix`, or `time.ParseDuration` has an `err` chain containing respectively `error calling Parse`, `error calling ParseInLocation`, `error calling Unix`, or `error calling ParseDuration`. Invalid numeric input to each unit constructor similarly contains the corresponding wrapper: `error calling Nanosecond`, `error calling Microsecond`, `error calling Millisecond`, `error calling Second`, `error calling Minute`, or `error calling Hour`. Each unit-constructor conversion failure also contains `expected a number` before its conversion cause; this applies, for example, to `time.Nanosecond "not-a-number"`, `time.Microsecond "invalid"`, `time.Millisecond "xyz"`, `time.Second "bad"`, `time.Minute "wrong"`, and `time.Hour "invalid"`.

## Spec 25

Random results use a nondeterministic, concurrency-safe random source and must vary across repeated calls/runs rather than returning fixtures. `random.ASCII count` returns exactly count printable ASCII characters (code points 32 through 126); `random.Alpha count` only ASCII letters; and `random.AlphaNum count` only ASCII letters/digits. Count zero returns empty for these three and negative/bad counts error. For a nonnumeric string count, each error starts with its function wrapper and then `count must be an integer`. Concretely, the JSON `err` strings for `random.ASCII "not_a_number"`, `random.Alpha "invalid"`, and `random.AlphaNum "bad"` are respectively exactly:

- `renderTemplate: failed to render template <arg>: template: <arg>:1:8: executing "<arg>" at <random.ASCII>: error calling ASCII: count must be an integer: could not convert "not_a_number" to int64: strconv.ParseFloat: parsing "not_a_number": invalid syntax`
- `renderTemplate: failed to render template <arg>: template: <arg>:1:8: executing "<arg>" at <random.Alpha>: error calling Alpha: count must be an integer: could not convert "invalid" to int64: strconv.ParseFloat: parsing "invalid": invalid syntax`
- `renderTemplate: failed to render template <arg>: template: <arg>:1:8: executing "<arg>" at <random.AlphaNum>: error calling AlphaNum: count must be an integer: could not convert "bad" to int64: strconv.ParseFloat: parsing "bad": invalid syntax`

`random.String count [regex | lower upper]` returns exactly count Unicode characters. Its default per-character set is `[a-zA-Z0-9_.-]`. One optional argument is an RE2 character expression restricting candidates; two optional arguments are inclusive lower/upper code-point bounds. Bounds may be single-character strings, decimal numbers, or base-prefixed numbers, and only printable code points are selected. Thus the three-argument call `random.String 30 "a" "z"` produces lowercase letters. A fourth argument is accepted, but a leading empty expression causes following bounds to be ignored: `random.String 50 "" "a" "z"` returns 50 characters from the default set and is not restricted to lowercase. Likewise, `random.String 30 "" 97 122` uses the default set. An invalid `[` expression reports an underlying cause containing `error parsing regexp: missing closing ]`. Empty candidate sets and other bad regex/ranges or invalid scalar bounds error.

The following `random.String` JSON `err` values are exact:

- `random.String "xyz"`: `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.String>: error calling String: count must be an integer: could not convert "xyz" to int64: strconv.ParseFloat: parsing "xyz": invalid syntax`
- `random.String 0`: `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.String>: error calling String: count must be greater than 0`
- `random.String 10 "notnum" 122`: `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.String>: error calling String: lower must be an integer: could not convert "notnum" to int64: strconv.ParseFloat: parsing "notnum": invalid syntax`
- `random.String 10 97 "notnum"`: `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.String>: error calling String: upper must be an integer: could not convert "notnum" to int64: strconv.ParseFloat: parsing "notnum": invalid syntax`

`random.String -1` has the same rendering/function wrappers and ends in `runtime error: makeslice: len out of range`. When both bounds are strings they are interpreted together as code points/base-prefixed integers: `random.String 10 "0xZZZ" "0x7E"` has JSON `err` exactly `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.String>: error calling String: strconv.ParseInt: parsing "0xZZZ": invalid syntax`. Likewise, `random.String 10 "0x20" "notahex"` has JSON `err` exactly `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.String>: error calling String: strconv.ParseInt: parsing "notahex": invalid syntax`.

`random.Item list` returns one actual element of a nonempty array/list, retaining its type; an empty input errors with `expected a non-empty array or slice`, and other values error. For the scalar call `random.Item "not a slice"`, the JSON `err` string is exactly `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.Item>: error calling Item: expected an array or slice, but got a reflect.Value`.

`random.Number [min] [max]` returns an `int64` uniformly within inclusive bounds: no args means 0..100, one arg means 0..arg, and two mean min..max. Equal bounds are valid and return that bound, so `random.Number 2 2` exits 0 and renders `2`. A reversed integer range such as min 10 and max 5 reports `min must not be greater than max (was 10, 5)`. `random.Number "notanum"` treats its sole argument as the maximum and has JSON `err` exactly `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.Number>: error calling Number: max must be a number: could not convert "notanum" to int64: strconv.ParseFloat: parsing "notanum": invalid syntax`. With two arguments, `random.Number "notanum" 10` instead has exact JSON `err` `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.Number>: error calling Number: min must be a number: could not convert "notanum" to int64: strconv.ParseFloat: parsing "notanum": invalid syntax`, while `random.Number 0 "notanum"` has exact JSON `err` `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.Number>: error calling Number: max must be a number: could not convert "notanum" to int64: strconv.ParseFloat: parsing "notanum": invalid syntax`.

`random.Float [min] [max]` similarly returns a `float64` in the half-open range, default 0..<1. Bounds accept normal numeric conversion but their ordering is not validated: equal bounds return that bound (`random.Float 2 2` renders `2`), and reversed bounds such as `random.Float 3 2` also exit 0 and produce a value between 2 and 3. Overflow and bad arity error. `random.Float "notanum" 10` has JSON `err` exactly `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.Float>: error calling Float: min must be a number: could not convert "notanum" to float64: strconv.ParseFloat: parsing "notanum": invalid syntax`; `random.Float 0 "notanum"` instead has JSON `err` exactly `renderTemplate: failed to render template <arg>: template: <arg>:1:9: executing "<arg>" at <random.Float>: error calling Float: max must be a number: could not convert "notanum" to float64: strconv.ParseFloat: parsing "notanum": invalid syntax`.

## Spec 26

`base64.Encode value` returns standard RFC 4648 base64 with `=` padding over the exact UTF-8/string or byte input. `base64.Decode text` accepts standard and URL-safe alphabets and returns bytes that render as their underlying text, but padding required by the encoding cannot be omitted. In particular, `-i '{{base64.Decode "aGVsbG8"}}'` exits 1 with empty stdout and a chain ending `error calling Decode: illegal base64 data at input byte 4`; the padded form `aGVsbG8=` decodes to `hello`. `base64.DecodeBytes` explicitly returns the raw byte sequence. Empty input works; Unicode and arbitrary binary round-trip. Whitespace embedded in encoded data, impossible lengths, and invalid alphabet/padding error. Invalid input whose first bad byte is at offset 3 reports `error calling Decode: illegal base64 data at input byte 3`. Concretely, `-i '{{ "abc!invalidbase64??" | base64.Decode }}'` exits 1 with empty stdout; after replacing the dynamic `time` value by `<TIMESTAMP>`, its stderr line is exactly `{"time":"<TIMESTAMP>","level":"ERROR","msg":"","err":"renderTemplate: failed to render template <arg>: template: <arg>:1:33: executing \"<arg>\" at <base64.Decode>: error calling Decode: illegal base64 data at input byte 3"}`. Likewise `-i '{{ "YWJj ZA==" | base64.Decode }}'` exits 1 with empty stdout and, after timestamp replacement, writes exactly `{"time":"<TIMESTAMP>","level":"ERROR","msg":"","err":"renderTemplate: failed to render template <arg>: template: <arg>:1:23: executing \"<arg>\" at <base64.Decode>: error calling Decode: illegal base64 data at input byte 4"}` to stderr. Byte arrays formatted with `printf "%q"` expose Go-style escapes.

## Spec 27

Hash functions `crypto.SHA1`, `SHA224`, `SHA256`, `SHA384`, `SHA512`, `SHA512_224`, and `SHA512_256` return the conventional lowercase hexadecimal digest of the exact input bytes. Corresponding names ending in `Bytes` return raw digest bytes. Results match the standard hash algorithms for empty, ASCII, Unicode, long, and binary input.

`crypto.Bcrypt [cost] input` returns a valid bcrypt hash in the `$2a$` revision format, using cost 10 by default and accepting 4 through 31; salts make repeated hashes differ. Thus a default-cost result starts with `$2a$10$`, while cost 12 starts with `$2a$12$`. A supplied cost below 4 is silently replaced by the default: `crypto.Bcrypt 3 "x"` succeeds with a `$2a$10$...` hash. A cost above 31 errors; cost 32 reports `crypto/bcrypt: cost 32 is outside allowed inclusive range 4..31`.

`crypto.PBKDF2 password salt iterations keyLength [hash]` returns lowercase hex for standard PBKDF2 and defaults to SHA-1. Uppercase identifiers include the hyphenated `"SHA-1"` and `"SHA-256"` as well as the unhyphenated `"SHA1"`, `"SHA256"`, and `"SHA512"`. In particular, each of `crypto.PBKDF2 "pass" "salt" 1000 32 "SHA1"`, the same call with `"SHA256"`, and the same call with `"SHA512"`, followed by `| len`, exits 0 and renders `64`. Also, `crypto.PBKDF2 "password" "salt" 1 32 "SHA256"` exits 0 and renders `120fb6cffcf8b32c43e7225256c4f837a86548c92ccc35480805987cb70be17b`. Lowercase `"sha1"` and `"sha-1"` error with `no such hash sha1` and `no such hash sha-1`, respectively. SHA-1/224/256/384/512 known-answer vectors match. A nonpositive iteration count is accepted and behaves as one iteration: `crypto.PBKDF2 "p" "s" -1 20`, the same call with iteration 0, and the same call with iteration 1 all render `843c87e7eda3ee2f64a61c8d1f997842651ddad0`. Nonpositive lengths and unknown hashes error.

`crypto.WPAPSK ssid password` implements WPA PBKDF2-HMAC-SHA1 (4096 iterations, 32-byte lowercase hex). It does not enforce the usual lower length limits: an empty SSID and a five-character password are both accepted, so `crypto.WPAPSK "" "short"` exits 0 and renders `2641877e1d5aa5cacc1d1e88bf8b2137b33de9800b1ef0cf94389ee5134e7ec6`. The standard `crypto.WPAPSK "IEEE" "password"` vector exits 0, renders exactly `f42c6fc52df0ebef9ebb4b90b38a5f902e83fe1b135a70e23aed762e9710a12e`, and writes nothing to stderr. The callable namespace form works too.

## Spec 28

The following asymmetric/AES functions are callable only when experimental mode is enabled by `--experimental`, config, or `GOMPLATE_EXPERIMENTAL`; without it, calling one is an execution error containing `experimental function, but experimental mode not enabled`.

`crypto.EncryptAES key [keyBits] plaintext` encrypts with AES-CBC using a random IV prepended to the ciphertext and PKCS#7 padding; keyBits defaults to 256 and accepts 128, 192, or 256. Key text is deterministically padded/truncated to that many bits. `crypto.DecryptAES key [keyBits] ciphertext` reverses it and returns text; `DecryptAESBytes` returns bytes. They handle empty/binary/Unicode/long input, yield differing ciphertext due to random IVs, and reject invalid sizes, truncated input, wrong padding, or wrong types.

`crypto.RSAGenerateKey [bits]` returns a PEM PKCS#1 private key (default 4096, minimum 2048); requesting 1024 bits errors with `RSA key size must be at least 2048 bits`. `crypto.RSADerivePublicKey private` returns a PEM PKIX public key, and malformed private-key text errors with `failed to read key: no key found`. `crypto.RSAEncrypt public plaintext` uses RSA PKCS#1 v1.5 and returns bytes; malformed public-key text produces a diagnostic containing both `failed to read key` and `no key found`. `RSADecrypt`/`RSADecryptBytes private ciphertext` recover text/bytes. RSA size limits and malformed/wrong key forms error.

`crypto.ECDSAGenerateKey [curve]` returns a PEM EC private key for P224, P256 (default), P384, or P521, accepting conventional case/hyphen spellings. `ECDSADerivePublicKey` returns PEM PKIX public data; malformed private-key text errors with `failed to read key: no key found`. Passing it a PKCS#1 RSA private key instead reports `invalid private key: x509: failed to parse private key (use ParsePKCS1PrivateKey instead for this key format)`. An unsupported `P999` curve errors with `unknown curve: P999`. `crypto.Ed25519GenerateKey` returns PEM PKCS#8 private data; `Ed25519GenerateKeyFromSeed encoding seed` accepts exactly 32 decoded bytes in hex or base64 and is deterministic. Encoding `invalid` errors with `invalid encoding given: invalid - only 'hex' or 'base64' are valid options`; malformed hex beginning with `z` errors with `could not decode given seed: encoding/hex: invalid byte: U+007A 'z'`; malformed base64 whose first invalid byte is at offset 3 errors with `could not decode given seed: illegal base64 data at input byte 3`; and a 16-byte decoded seed errors with `generateKeyFromSeed: incorrect seed size - given: 16 wanted 32`. `Ed25519DerivePublicKey` returns PEM public data; malformed private-key text errors with `ed25519DecodeFromPEM: could not decode private key: decode: failed to read key`. Unknown curves/encodings, invalid seed lengths, and malformed keys error.

## Spec 29

`file.Read path` returns exact file bytes; `file.Write path data` creates parent directories, writes strings or bytes, returns an empty value, and preserves an existing file's permission bits. `file.Write` is confined to the current working directory after resolving/cleaning the path: relative paths and absolute paths inside it work, while traversal or an absolute target outside it errors with `not contained by working directory`. `file.Exists` is false for a missing path; `file.IsDir` identifies directories. `file.ReadDir path` returns the immediate entry names as strings, not directory-entry objects, in deterministic name order. Thus a directory containing `file1.txt`, `file2.txt`, and `subdir` renders as `[file1.txt file2.txt subdir]`, and serializing the result to JSON yields `["file1.txt","file2.txt","subdir"]`. `file.Walk path` returns the root and all descendants recursively in deterministic lexical traversal.

`file.Stat path` returns a value exposing at least `Name`, `Size`, `Mode`, `ModTime`, and `IsDir`. Paths can be relative or absolute and Unicode/binary/empty files work. Symbolic links follow normal OS semantics. Reads and stats of missing paths error with an `err` chain containing lowercase `no such file or directory` and useful path text; missing walks and writes to unwritable/directory targets likewise error rather than panicking.

## Spec 30

The `path` namespace always applies slash-separated POSIX path rules; `filepath` applies host filesystem rules (the evaluation host is Unix). Both implement `Base`, `Dir`, `Ext`, `Clean`, `IsAbs`, `Join`, `Match`, and `Split`. Clean of empty is `.`, repeated separators and `.`/`..` normalize lexically, extension is the final suffix, Split returns directory including its trailing separator plus base, and Join cleans the result (an absolute-looking middle component does not discard earlier joined components). Match supports `*`, `?`, and character classes and errors for malformed patterns.

`filepath.Rel base target` computes a lexical relative path. `ToSlash` and `FromSlash` convert separators, and `VolumeName` is empty on Unix for normal paths. All path values are stringified as appropriate and Unicode is retained. `path.Join` and `filepath.Join` are variadic; either one called with zero arguments succeeds and returns the empty string.

## Spec 31

`net.ParseAddr text` returns a canonical IP object; IPv4, IPv6, compression, and IPv4-mapped forms are normalized by its `String` method. In particular, `net.ParseAddr "::ffff:192.168.1.1"` renders exactly `::ffff:192.168.1.1`, retaining the dotted-decimal IPv4 suffix. `net.ParsePrefix CIDR` validates and canonicalizes the address spelling but preserves its host bits: `net.ParsePrefix "192.168.1.42/24"` renders `192.168.1.42/24`. `net.ParseRange range` accepts only an explicit `from-to` range and exposes `From` and `To` endpoints; `net.ParseRange "10.0.0.0/30"` errors with `no hyphen in range "10.0.0.0/30"`. Invalid address bytes, prefixes, masks, reversed ranges, and trailing junk error. Specifically, `net.ParseAddr "not an ip"` has a chain containing `error calling ParseAddr: ParseAddr("not an ip"): unable to parse IP`, `net.ParsePrefix "invalid"` reports `no '/'`, and `net.ParseRange "invalid"` has a chain containing `error calling ParseRange: no hyphen in range "invalid"`.

`net.LookupIP host` returns the first resolved address and `net.LookupIPs host` all unique IPv4 addresses in resolver order, filtering IPv6 results. In the evaluation environment, `net.LookupIPs "localhost"` renders exactly `[127.0.0.1]`. `LookupIPv4` likewise filters IPv4. `net.LookupCNAME` returns the canonical name (normally with trailing dot); `LookupTXT` returns TXT strings. `LookupSRV service proto name` returns the first record and `LookupSRVs` all, each exposing `Priority`, `Weight`, `Port`, and `Target`. These use the host resolver/network supplied by the harness, support localhost and live resolvable names, and produce a template error for an unresolvable/invalid name.

## Spec 32

The CIDR functions are experimental. Without experimental mode their calls error with `experimental function, but experimental mode not enabled`; `GOMPLATE_EXPERIMENTAL=1` enables them as stated in Spec 5. `net.CIDRHost offset prefix` returns the host at a zero-based offset into the entire address block; negative offsets count backward (`-1` is the last address). It accepts prefix strings and the object returned by `ParsePrefix`. Out-of-range offsets error; offset 256 for `192.168.1.0/24` reports `prefix of 24 does not accommodate a host numbered 256`. `net.CIDRNetmask prefix` returns canonical mask text (`255.255.255.0` for IPv4 `/24`, hexadecimal form for IPv6).

`net.CIDRSubnets newBits prefix` splits into every equal subnet created by adding `newBits` to the prefix length, in address order. A negative extension, such as `net.CIDRSubnets -1 "192.168.1.0/24"`, reports `must extend prefix by at least one bit`. If the extension exceeds the address width, the error identifies insufficient space; `net.CIDRSubnets 25 "192.168.1.0/24"` reports `insufficient address space to extend prefix of 24 by 25`. A nonnumeric extension has a chain containing `newbits must be a number: could not convert "notanumber" to int64`.

`net.CIDRSubnetSizes size... prefix` allocates sequential subnets by adding each requested size to the original prefix length, aligned and nonoverlapping. IPv4 and IPv6 work. A size of zero reports `must extend prefix by at least one bit`, and a size above 32 reports `may not extend prefix by more than 32 bits`. Nonnumeric sizes have a chain containing the plural diagnostic `newbits must be numbers: could not convert "notanumber" to int64`. Extending IPv4 `/28` by 8 reports `would extend prefix to 36 bits`; `net.CIDRSubnetSizes 16 "192.168.1.0/24"` reports `would extend prefix to 40 bits, which is too long for an IPv4 address`, and `net.CIDRSubnetSizes 10 "2001:db8::/120"` reports `would extend prefix to 130 bits, which is too long for an IPv6 address`. Requesting three `/25` allocations with `net.CIDRSubnetSizes 1 1 1 "192.168.1.0/24"` reports `not enough remaining address space for a subnet with a prefix of 25 bits after 192.168.1.128/25`.

For invalid prefix text, `net.CIDRHost 1 "invalid"`, `net.CIDRNetmask "invalid"`, `net.CIDRSubnets 1 "invalid"`, and `net.CIDRSubnetSizes 1 "invalid"` each have an error chain containing `netip.ParsePrefix("invalid"): no '/'`. A nonnumeric host offset, as in `net.CIDRHost "notanumber" "192.168.1.0/24"`, has a chain containing `expected a number: could not convert "notanumber" to int64: strconv.ParseFloat: parsing "notanumber": invalid syntax`. Other impossible sizes, address-family mismatches, and insufficient space error.

## Spec 33

The `sockaddr` namespace reflects the evaluation host's actual interfaces. `GetAllInterfaces` returns all interface/address records. `GetDefaultInterfaces`, `GetPrivateInterfaces`, and `GetPublicInterfaces` return the corresponding default-route, RFC-special/private-forwardable, and public-forwardable records. Convenience `GetInterfaceIP selector` and `GetInterfaceIPs selector` require an interface-name regular expression and return one/all matching textual addresses; for example, selector `eth.*` returns an address from a matching interface. Calling `GetInterfaceIP` without its selector errors with `wrong number of args for GetInterfaceIP: want 1 got 0`. `GetPrivateIP(s)` and `GetPublicIP(s)` return one/all matching textual addresses.

An interface record supports attributes including `name`, `address`, `type`, `network`, `port`, `size`, `default`, and flags. `sockaddr.Attr selector record` extracts one as text. An IPv4 record's `type` is exactly `IPv4`, while filtering with `Include "type" "ipv4"` also matches those records. `Include selector value records` and `Exclude` filter on selectors `address`, `flag`, `name`, `network`, `port`, `rfc`, `size`, or `type`. Flags include up/down, loopback, forwardable, global/link-local/interface-local/multicast, broadcast, point-to-point, and unspecified.

`sockaddr.Sort selectors records` accepts comma-separated selectors, with `-` descending and optional `+` ascending; available sort selectors are `address`, `default`, `name`, `port`, `size`, and `type`. `Join selector separator records`, `Limit n records`, `Offset n records`, and `Unique selector records` provide the indicated stable list operations. `sockaddr.Math selector operation records` applies an operation such as `"+2"` to each selected attribute (for example address arithmetic) and preserves the record count. Bad selectors, offsets, operations, and types error; empty interface result sets render/iterate normally.

## Spec 34

`uuid.V4` creates and returns a fresh lowercase RFC-4122 version-4 UUID as a string with correct variant bits; `uuid.V1` likewise returns a valid version-1 UUID as a string. The generated strings do not expose fields or methods: accessing `$u.Version` on a `uuid.V1` result errors with `can't evaluate field Version in type string`. Repeated calls do not collide. `uuid.Nil` is exactly `00000000-0000-0000-0000-000000000000`. `uuid.IsValid` recognizes standard hyphenated, raw 32-hex, `urn:uuid:...`, and brace forms without requiring a specific version. `uuid.Parse` accepts those forms or errors and returns a canonical `uuid.UUID` value exposing `String`, `Version`, and `Variant` (for v4: `VERSION_4` and `RFC4122`) plus applicable UUID inspection methods. Parsing the seven-character input `invalid` errors with `invalid UUID length: 7`.

`semver.Semver input` parses an optional leading `v`, permits an omitted patch, and parses prerelease identifiers and build metadata. The omitted patch is filled with zero, so `semver.Semver "1.2"` succeeds and renders `1.2.0`. It renders canonical form and exposes `Major`, `Minor`, `Patch`, `Prerelease`, `Metadata`, `Original`, `IncMajor`, `IncMinor`, `IncPatch`, and prerelease/metadata setters with semantic-version precedence. For a version already containing a prerelease, `IncPatch` removes the prerelease and metadata without increasing the patch: on `v1.2.3-alpha.1+build.7` it returns `1.2.3`. `semver.CheckConstraint constraint version` supports comparison operators, comma/space conjunction, OR ranges, wildcards, hyphen ranges, tilde, and caret; build metadata does not affect precedence and prereleases obey semver range rules. Invalid versions/constraints error; specifically, `semver.Semver "not-a-version"` and `semver.Semver "invalid"` each report `invalid semantic version`.

## Spec 35

Validation functions have both namespaced names and aliases `assert`, `fail`, `isKind`, `kind`, `required`, and `ternary`:

- `test.Assert [message] value` succeeds when the value is true and returns an empty value; false errors with `assertion failed`, appending `: message` when provided. The optional message must precede the value (the pipeline supplies value last). The reversed two-argument order is not recognized: both `test.Assert true "legacy"` and `test.Assert false "legacy"` error with `at <1>: expected string; found bool`.
- `test.Fail [message]` always errors with `template generation failed`, appending `: message` when present. Two arguments report `wrong number of args: want 0 or 1, got 2`.
- `test.Required [message] value` passes through any nonempty/non-nil value. Empty/nil errors with the message, or `can not render template: a required value was not set` without one.
- `test.Ternary trueValue falseValue condition` uses `conv.ToBool` from Spec 19 and returns the selected value without converting its type.
- `test.Kind value` returns reflection-kind text such as `string`, `bool`, `int`, `float64`, `slice`, `map`, or `invalid`. `test.IsKind kind value` compares it; special kind `number` matches any integer, unsigned, or floating kind.

Optional arguments must follow those signatures. Too many/too few arguments are template errors. In particular, `test.Assert "one" "two" true` exits 1 with an `err` chain containing `error calling Assert: wrong number of args: want 1 or 2, got 3`. Precise dynamic type inspection, where needed, is available through `printf "%T"`.

## Spec 36

`gcp.Meta key [default]` requests a key from the metadata base URL, normally the GCP metadata service but replaced by `GCP_META_ENDPOINT` when set, with the header `Metadata-Flavor: Google`. Surrounding whitespace is trimmed from a successful response: bytes ` value\nline2 ` return `value\nline2`. Calls are not cached; two calls for the same key perform two requests. If metadata is unavailable or the key is absent, the optional default is returned byte-for-byte (including empty, whitespace, multiline, JSON-looking, and boolean-looking strings); without a default it returns empty. Different keys/default calls remain independent.

`GCP_TIMEOUT` is an integer number of milliseconds; unset or 0 uses 500 ms. A malformed value, including surrounding whitespace, aborts with status 2. In particular, the value ` 100 ` produces a panic whose first line is exactly `panic: invalid GCP_TIMEOUT value ' 100 ' - must be an integer: strconv.Atoi: parsing " 100 ": invalid syntax`.

AWS timeout parsing is analogous: a malformed `AWS_TIMEOUT` makes an AWS function fail and includes `invalid AWS_TIMEOUT value 'VALUE'` and an integer requirement, while already rendered stdout remains. The unnamespaced `ec2region` AWS function is available; with `AWS_TIMEOUT=invalid`, `{{ ec2region }}` reaches timeout parsing and reports `invalid AWS_TIMEOUT value 'invalid'`. `aws.EC2Meta key [default]` and its lowercase global alias `ec2meta` return the provided default when metadata is unavailable; with `AWS_TIMEOUT=5`, `ec2meta "x" "d"` renders `d`. `aws.EC2Dynamic key [default]` likewise has lowercase global alias `ec2dynamic`; under the same conditions, `ec2dynamic "x" "e"` renders `e`. `aws.EC2Tags` and its lowercase global alias `ec2tags` return an iterable map (possibly empty); unavailable metadata makes `ec2tags` render `map[]`. `aws.KMSDecrypt` rejects malformed base64 before attempting a service call, with an `err` chain containing `illegal base64 data`. `aws.KMSEncrypt` requires exactly two arguments; `aws.KMSEncrypt "x"` fails before service configuration with `wrong number of args for KMSEncrypt: want 2 got 1`. With both arguments, absence of either `AWS_REGION` or `AWS_DEFAULT_REGION` ultimately errors rather than guessing a region. No live cloud service is assumed; harness endpoints/environment determine availability.
