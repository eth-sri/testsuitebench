# Behavioral specification for `executable`

The required artifact is one directly runnable Unix program named exactly `executable`. The terms “must”, “should”, and “may” are normative in that order. All byte examples are UTF-8 unless explicitly identified as binary. The program is a compatible implementation of the `fzf` 0.68.0 command-line fuzzy finder described below; this document defines the compatibility surface and does not require a particular language or internal architecture. `spec.md` and the four files explicitly named under `reference/` are the normative contract. Other pre-existing documentation in this directory is explanatory only and cannot override this file.

The harness supplies the operating system, shell, terminal, `tmux`, HTTP client, and any terminal-driving utility. Those are not parts of `executable` and their behavior is not specified here.

## Spec 1

`executable` is both a streaming Unix filter and a full-screen terminal selector. It reads candidate records from standard input, searches them using the current query, and writes accepted records to standard output. Arguments may use `--name=value`, `--name value`, and documented short forms. Successful informational modes and successful selections exit 0; a completed batch search with no match exits 1; command-line/configuration errors exit 2. Diagnostics go to standard error and never contaminate standard output. Unknown non-option positional words are errors as well as unknown flags.

Options are parsed completely before an informational mode is dispatched. Consequently an unknown option causes an error even when it occurs before or after `--help`; stdout is empty and stderr contains `unknown option: <argument>`. A standalone `--` does not make a subsequent `--help` cease to be recognized. Repeated options follow command-line order: a later positive/negative form or later mutually exclusive mode wins unless a specific validation rule below says the combination itself is invalid.

The program must handle concurrent independent invocations, ordinary pipes, redirected binary input, a real PTY, and terminal sizes used by the harness. It must not crash, deadlock, or time out on empty input, malformed text/ANSI data, or unbound terminal keys.

## Spec 2

`--version` prints exactly `0.68.0 (5676da4a)\n` to stdout, prints nothing to stderr, and exits 0. `--help` and `-h` print exactly the bytes in `reference/help.txt`, including its final newline, and exit 0 with empty stderr. That reference is part of this specification, not an implementation aid that may be substituted with newly generated documentation.

`--man` exits 0 and produces a nonempty fzf manual. It may invoke the host man-page formatter; if that is unavailable or fails it prints raw groff. Raw output begins with a `.TH fzf` declaration and contains NAME, SYNOPSIS, DESCRIPTION, and OPTIONS sections and describes fzf as a command-line fuzzy finder. Formatted output must still clearly identify fzf and document it at useful length.

## Spec 3

The three shell-integration modes are fixed-output modes. `--bash`, `--zsh`, and `--fish` each exit 0, use stdout only, and emit exactly `reference/bash.txt`, `reference/zsh.txt`, and `reference/fish.txt`, respectively. These files are normative byte streams.

Each stream contains distinct key-binding and completion sections bracketed by `### key-bindings.<shell> ###`, `### end: key-bindings.<shell> ###`, `### completion.<shell> ###`, and `### end: completion.<shell> ###`. The Bash stream uses Bash/Readline constructs such as `READLINE_LINE`; the Zsh stream uses `bindkey` and `zle`; the Fish stream uses Fish `function` and `bind` syntax. These mode flags do not launch the selector.

## Spec 4

In normal input mode, LF terminates a candidate. The final unterminated record is still a candidate. A CR immediately preceding LF remains part of the candidate; CRLF is not normalized to LF. Thus input `one\r\ntwo\nthree\r\nfour` with `--filter= --no-sort` emits exactly `one\r\ntwo\nthree\r\nfour\n`. Leading and consecutive delimiters create empty records, but a delimiter at EOF only terminates the record before it and does not create an additional empty record after it. Thus `a\n` is one candidate, `\na` is an empty candidate followed by `a`, `a\n\nb` has an empty middle candidate, and `\n\n` has exactly two empty candidates. This rule governs every consumer of the candidate stream: filter output, `--tail` retention, interactive match/total counts, and HTTP `totalCount`/`matchCount` must all count the same records and must never count a synthetic empty record after the final LF. Tabs, leading/trailing spaces, whitespace-only records, control bytes, and UTF-8 content are retained. Embedded NUL bytes in normal mode are data rather than record boundaries. Inputs consisting only of delimiters, one-byte input, no bytes, enormous individual records, records crossing 64 KiB/128 KiB boundaries, mixed record sizes, and streams of at least 100,000 records must be processed correctly.

With `--read0`, ASCII NUL is the sole record delimiter: LF and CR are ordinary record content. Leading and consecutive NULs create empty records and a final record without NUL is accepted, but a final NUL does not create an extra empty EOF record. `--print0` changes every output record terminator, including query/key lines where applicable, from LF to NUL. Combining `--read0 --print0` therefore round-trips record boundaries, including multiline records. The negative forms `--no-read0` and `--no-print0` restore newline mode. Filter output always includes a terminator after every emitted record, even when the corresponding input record was unterminated.

Default scoring still applies to NUL-delimited input. In particular, input `normal.txt\0file with spaces.txt\0file\twith\ttabs.txt\0` with `--read0 --filter=txt` emits `normal.txt\nfile\twith\ttabs.txt\nfile with spaces.txt\n`, in that order, and exits 0.

Normally an interactive finder can search while its input is still arriving. `--sync` instead consumes the complete input before starting the initial search/display; in filter mode it likewise guarantees deterministic results after EOF. It composes with `--no-sort`, field selection, and large input.

For input `apple\nbanana\ncherry\ndate\neggplant\nfig\ngrape\n`, `--sync --filter=a` exits 0 and emits exactly `apple\ndate\ngrape\nbanana\neggplant\n`.

## Spec 5

`-f QUERY`, `--filter QUERY`, and `--filter=QUERY` run non-interactively. All input is consumed; subject to input-retention controls such as `--tail` in Spec 9, matching candidates are ordered as specified below and every match among the retained candidates is printed. Exit 0 means at least one match; exit 1 means none. An empty query matches every candidate, including empty records, but entirely empty stdin has no candidates and exits 1. There is no prompt or terminal control output in filter mode, and valid display-only options do not change these batch-output rules.

For example, filtering `apple\nbanana\napricot\ncherry` with `ap` produces `apple\napricot\n`; filtering it with `xyz` produces no bytes and exits 1. Filter mode with `--multi` still emits all matches. It bypasses tmux-popup creation even if `--tmux` is present. It must remain responsive on 100,000 candidates, many matches, long Unicode-heavy data, and individual lines of at least 50,000 bytes.

`--disabled` starts interactive mode with live search disabled, but an explicit batch `--filter` query is still evaluated normally. `--raw` makes nonmatching items available in the interactive list alongside matches; it does not remove matching items or alter accepted record bytes. It is valid with filter mode, whose match and status contract remains authoritative.

## Spec 6

The default matcher is a fuzzy subsequence matcher: each query character must occur in order, but intervening candidate characters are allowed. Exact mode (`-e`/`--exact`) instead requires a contiguous substring; `+e` is its negative short form and restores fuzzy matching. `--algo=v1` and `--algo=v2` select the two supported fuzzy algorithms; both obey the same match/no-match language but may compute different official fzf scores. Any other algorithm is rejected with `invalid algorithm (expected: v1 or v2)`.

Rank fuzzy matches by descending match quality. The ranking must favor exact/contiguous runs, longer consecutive runs, matches at the beginning of a word or path component, camel-case transitions, and earlier/compact match spans over scattered characters. Thus query `oBZ` case-insensitively ranks `fooBarbaz1` ahead of `foo bar baz`; query `fzf` matches `fzf`, `fuzzy-finder`, and `foo/zap/filter.c`, with the more compact/boundary-aligned match first. Empty query retains candidate order unless `--tac` reverses it.

These preferences have score interactions that cannot be inferred by counting gaps alone. In particular, for the two-record input `fuzzy-finder\nfind fuzzy filter\n`, `--filter=fzf` emits `find fuzzy filter\nfuzzy-finder\n`, irrespective of which of those two records came first.

The official score ordering is normative where those qualitative rules alone leave ambiguity. For input `zebra\nyak\nxray\nsnake\nrabbit\nquail\n`, `--filter=a` emits `yak\nxray\nzebra\nsnake\nquail\nrabbit\n`. For input `at8ph7ybcfb539y1\naz0mpbpmzc7z6jlew8tz2tzfjicrldb242rowl\naiozgjhb81wct9180mzhbkyotjpxzbxvlwsg4gy9\nagv5mel61ngtbr10scrsc3lk04t9d1gtfg\nq86kabbjsqcljmakf\nvhhzabghabicad1vij6nfjg45jp9t2flcu9q5\n`, `--filter=abc` emits those records in the order `at8ph7ybcfb539y1`, `az0mpbpmzc7z6jlew8tz2tzfjicrldb242rowl`, `aiozgjhb81wct9180mzhbkyotjpxzbxvlwsg4gy9`, `agv5mel61ngtbr10scrsc3lk04t9d1gtfg`, `vhhzabghabicad1vij6nfjg45jp9t2flcu9q5`, then `q86kabbjsqcljmakf`.

The following ten-record corpus is also normative for the examples below: `/usr/bin/fzf\n/usr/local/bin/fuzzy-finder\n/home/user/projects/fuzzy/finder.go\n/home/user/projects/foo/zap/bar.go\n/opt/fuzzy-filter-tool/bin/fzf\n/var/log/fuzzy.log\n/etc/config/fzf.conf\nsrc/foo/zebra/filter.c\nsrc/fuzzy/algorithm/finder.c\nlib/fuzzy-matching/fzf-core.so\n`. On that corpus, both `--exact --filter=fzf` and the extended-search query `--filter="'fzf"` emit `/usr/bin/fzf\n/etc/config/fzf.conf\n/opt/fuzzy-filter-tool/bin/fzf\nlib/fuzzy-matching/fzf-core.so\n` in exactly that order.

## Spec 7

Case handling has three modes. Smart case is the default and is also selected by `--smart-case`: a query containing no uppercase letter matches case-insensitively, while a query containing uppercase letters matches case-sensitively. `-i`/`--ignore-case` always folds case and `+i`/`--no-ignore-case` always preserves it. Case behavior applies to fuzzy and exact operators and Unicode text.

Case folding changes which characters can match but does not introduce a preference for a particular capitalization. Given `FooBar\nfoobar\nFOOBAR\nFoObAr\nfoo_bar\nFOO_BAR\n`, both the default lowercase query `--filter=foo` and `--ignore-case --filter=FOO` emit all six records in that same order.

By default, Latin letters in candidates are normalized for an unaccented query, so an unaccented query such as `cafe` matches both `cafe` and `café`; original candidate bytes remain the output. This normalization is directional: accents present in the query remain significant. Given `a\ná\nA\nÁ\n`, query `a` emits all four records, while query `á` emits only `á\nÁ\n`. Likewise, input `café\ncafe\n` with `--filter=café` emits exactly `café\n`. `--literal` disables candidate normalization, so `cafe` does not match `café`. Unicode code points, emoji, CJK, Korean, RTL text, and combining sequences are accepted without corruption. Search and truncation operate on characters/display cells rather than splitting UTF-8 byte sequences.

## Spec 8

Extended search is enabled by default. Unescaped spaces separate AND terms. A plain term is fuzzy (or contiguous exact when global `--exact` is active); a leading single quote makes that term exact; `^term` is an exact prefix; `term$` is an exact suffix; `^term$` is a whole-candidate exact match. `!term`, `!^term`, and `!term$` negate exact-substring, prefix, and suffix conditions, while `!'term` negates a fuzzy match for `term`. Negative conditions used without a positive term do not receive a matcher score: surviving records remain in input order. All terms in an AND expression must hold.

A term quoted with a single quote at both ends is an exact-boundary match: the exact occurrence must begin and end at word boundaries. Underscores also count as boundaries, though underscore-adjacent matches receive lower scores than other boundary types. For input `app\napple\nthe app` (with or without a final LF), `--filter="'app'"` emits exactly `app\nthe app\n`; the ordinary leading-quote form `'app` remains an unanchored exact-substring search.

An isolated `|` joins the immediately adjacent terms into one OR chain; other space-separated terms remain AND conditions on that chain. Thus `ap | ch` accepts candidates matching either alternative, while `fzf | 'fuzzy 'finder` means (`fzf` OR exact-substring `fuzzy`) AND exact-substring `finder`—it does not mean `fzf` OR (`fuzzy` AND `finder`). `ap !apple` means fuzzy `ap` AND not containing `apple`; `^/usr 'bin !local` means starts with `/usr`, contains `bin`, and does not contain `local`; and `apple | !banana` accepts `apple` or any item not containing `banana`. More than two alternatives and alternatives containing exact/negative operators are supported.

On the ten-record corpus in Spec 6, `--filter="fzf | 'fuzzy 'finder"` emits exactly `/home/user/projects/fuzzy/finder.go\n/usr/local/bin/fuzzy-finder\nsrc/fuzzy/algorithm/finder.c\n`. Negative-only queries on that corpus demonstrate both filtering and stable order: `!fuzzy` emits `/usr/bin/fzf\n/home/user/projects/foo/zap/bar.go\n/etc/config/fzf.conf\nsrc/foo/zebra/filter.c\n`; `!^/usr` emits `/home/user/projects/fuzzy/finder.go\n/home/user/projects/foo/zap/bar.go\n/opt/fuzzy-filter-tool/bin/fzf\n/var/log/fuzzy.log\n/etc/config/fzf.conf\nsrc/foo/zebra/filter.c\nsrc/fuzzy/algorithm/finder.c\nlib/fuzzy-matching/fzf-core.so\n`; `!.go$` emits `/usr/bin/fzf\n/usr/local/bin/fuzzy-finder\n/opt/fuzzy-filter-tool/bin/fzf\n/var/log/fuzzy.log\n/etc/config/fzf.conf\nsrc/foo/zebra/filter.c\nsrc/fuzzy/algorithm/finder.c\nlib/fuzzy-matching/fzf-core.so\n`; and `!'fzf` emits `/home/user/projects/foo/zap/bar.go\n/var/log/fuzzy.log\n`.

A backslash immediately before a space prevents that space from separating extended-search terms; the backslash is removed from the resulting term. Backslash does not generally escape the other operator metacharacters and is retained as searchable text before them. In particular, filtering `a b$c\na bx c\n` with the single argument `--filter=a\ b\$c` produces no output and exits 1; the backslash before `$` is not discarded to make this query match `a b$c`. Punctuation such as `.`, `*`, `+`, `?`, brackets, braces, parentheses, quotes, apostrophes, and slashes is literal candidate content unless it is one of the operators in a syntactically operative position. `+x`/`--no-extended` disables term/operator parsing and treats the complete query as one matcher pattern.

## Spec 9

Unless `+s`/`--no-sort` is active, matched candidates are sorted by descending matcher score and then by configured tie breakers. `--sort` re-enables sorting. `--no-sort` preserves input order regardless of query; with streaming filter input it may emit in that order. `--tac` reverses the input sequence before searching, and combines predictably with `--no-sort`.

`--tail=N` limits the retained candidate set to the final N input records whenever output waits for buffered input, including ordinary sorted filter mode and filter mode with `--sync`; N must be positive. Matching and ordering are then applied only to that retained set. Thus input records `line0` through `line99` with `--filter=line --tail=10` emit exactly `line90\nline91\nline92\nline93\nline94\nline95\nline96\nline97\nline98\nline99\n`, and input `one\ntwo\nthree\nfour\n` with `--sync --tail=3 --no-sort --filter=` emits exactly `two\nthree\nfour\n`. The exception is unsynchronized streaming filter output under `--no-sort`: already-emitted records are not retracted, so the same four-record input with `--tail=2 --no-sort --filter=` and no `--sync` emits all four records, each LF-terminated, in input order.

`--scheme=default`, `path`, and `history` select scoring bonuses suitable for general text, path components, and command-history text. Path scoring rewards matches at separators/basenames. History scoring preserves input recency order when the match quality is otherwise the same: filtering `git commit -m "first"\ngit push origin main\ngit pull\ngit commit -m "second"\ngit status\n` with query `git` and `--scheme=history` emits those five records in that same order. Any other scheme exits 2 with empty stdout and exactly `invalid scoring scheme: VALUE (expected: default|path|history)\n` on stderr; for example `--scheme=invalid --filter=test` substitutes `invalid` for `VALUE`.

`--tiebreak` accepts at most three distinct comma-separated criteria from `length`, `chunk`, `pathname`, `begin`, `end`, and `index`. They are applied in stated order: shorter candidate length; the shorter whitespace-delimited chunk containing the match; pathname-specific match placement; earlier match start; a match ending closer to the end of the candidate; and original input index. `pathname` does not mean shallower path first: with input `/usr/bin/apple\n/home/user/apple\n/opt/apple\n`, `--filter=apple --tiebreak=pathname` emits `/usr/bin/apple\n/home/user/apple\n/opt/apple\n`. `index` must be last. With input `apple\nbanana\ncherry\ndate\neggplant\nfig\ngrape\n` and query `a`, `--tiebreak=end` emits `apple\nbanana\neggplant\ngrape\ndate\n`, while `--tiebreak=chunk` emits `apple\ndate\ngrape\nbanana\neggplant\n`. Invalid, excessive, or misplaced criteria are errors containing, respectively, `invalid sort criterion`, `at most 3 tiebreaks are allowed`, or `index should be the last criterion`. A duplicate names the duplicated criterion: `--tiebreak=length,length --filter=test` exits 2 with empty stdout and exactly `duplicate sort criteria: length\n` on stderr.

The matcher score is applied before these tie breakers, and its exact ordering is observable. For input `xoxxxxxoxx\nxoxxxxxox\nxxoxxxoxx\nxxxoxoxxx\nxxxxoxox\n  xxoxoxxx\n` and query `oo`, the default output is `xxxxoxox\n  xxoxoxxx\nxxxoxoxxx\nxxoxxxoxx\nxoxxxxxox\nxoxxxxxoxx\n`; `--tiebreak=index` emits `xxxoxoxxx\nxxxxoxox\n  xxoxoxxx\nxxoxxxoxx\nxoxxxxxoxx\nxoxxxxxox\n`; `--tiebreak=begin` emits `  xxoxoxxx\nxxxoxoxxx\nxxxxoxox\nxxoxxxoxx\nxoxxxxxoxx\nxoxxxxxox\n`; and `--tiebreak=begin,length` emits `  xxoxoxxx\nxxxoxoxxx\nxxxxoxox\nxxoxxxoxx\nxoxxxxxox\nxoxxxxxoxx\n`.

For input `xoxxxxxxxx\nxxoxxxxxxx\nxxxoxxxxxx\nxxxxoxxxx\nxxxxxoxxx\n  xxxxoxxx\n` and query `o`, default sorting emits `  xxxxoxxx\nxxxxoxxxx\nxxxxxoxxx\nxoxxxxxxxx\nxxoxxxxxxx\nxxxoxxxxxx\n`, while `--tiebreak=end` emits `xxxxxoxxx\n  xxxxoxxx\nxxxxoxxxx\nxxxoxxxxxx\nxxoxxxxxxx\nxoxxxxxxxx\n`. For input `1 foobarbaz ba\n2 foobar baz\n3 foo barbaz\n`, query `o` with `--tiebreak=chunk` emits `3 foo barbaz\n2 foobar baz\n1 foobarbaz ba\n`.

Default scoring also determines these orders. Input `foo bar\nfoo/bar\nfooBar\nfoo_bar\nfoobar\n` with `--filter=fb` emits those five records in exactly that order. Input `no spaces\n  leading spaces\ntrailing spaces  \nmultiple   spaces   inside\n` with `--filter=spaces` likewise emits those four records in input order, preserving every leading, trailing, and repeated space. For a long-line case, let A be 10,000 ASCII `a` characters followed by `_apple`, B be 10,000 ASCII `b` characters followed by `_banana`, and C be 10,000 ASCII `c` characters followed by `_apple`. Input `A\nB\nC\n` with `--filter=apple` emits `A\nC\n`; neither record is truncated, and their input order is retained.

## Spec 10

`-d`/`--delimiter` defines a field-separating regular expression. Literal one- and multi-character delimiters (`:`, `::`, comma, tab, `|`) and regular expressions such as `[,:]` and `[0-9]+` are supported. Empty fields from adjacent, leading, or trailing separators are significant and keep their index. Without `--delimiter`, fields use AWK-style whitespace tokenization: runs of spaces/tabs separate fields and leading/trailing whitespace is handled as AWK would.

Field expressions used by `--nth`, `--with-nth`, `--accept-nth`, and token placeholders are comma-separated selectors. A positive N is one-based from the start; a negative N counts back from the end (`-1` is last). Zero is invalid (`--nth=0` reports `invalid format: 0`). Inclusive ranges are `A..B`, `A..`, `..B`, and `..`; negative endpoints work. Multiple selectors preserve selector order and may repeat/reorder fields when producing transformed text. For `--nth` matching, however, comma-separated selectors remain distinct searchable chunks rather than being concatenated into a new string; a range such as `2..3` is one chunk. Out-of-range fields contribute nothing rather than crashing. Invalid selector syntax is rejected.

## Spec 11

`-n`/`--nth=EXPRS` restricts the text searched and scored to the selected field chunks while retaining the original record for normal output. Noncontiguous selectors jointly form the search scope, but a single fuzzy term cannot span two comma-separated selectors. For input `aa:bb:cc:dd\n`, `-d: --nth=2..3,1,-1 --filter=bbcc` matches and emits the original record, whereas the same invocation with `--filter=bbccaa` exits 1 with no output. For input `John:Doe:30:Engineer\nBob:Johnson:35:Manager\nAlice:Williams:28:Developer\nFrank:Miller:27:Developer\n`, `-d: --nth=1,4 --exact --filter=er` emits `John:Doe:30:Engineer\nBob:Johnson:35:Manager\nFrank:Miller:27:Developer\nAlice:Williams:28:Developer\n` in that order.

Scoring and tie resolution use the selected search text, not the unselected fields. For input `apple:red:fruit\ngrape:purple:fruit\nbanana:yellow:fruit\ncarrot:orange:vegetable\n`, `--delimiter=: --nth=3 --filter=fruit` exits 0 with empty stderr and emits exactly `apple:red:fruit\ngrape:purple:fruit\nbanana:yellow:fruit\n`.

`--with-nth=EXPRS` transforms presentation and search text, but batch filter acceptance still prints the original record unless `--accept-nth` is also used. `--accept-nth=EXPRS` transforms the accepted output itself. AWK-style tokenization preserves the separator run following a selected field when there is one; it does not synthesize a separator where the selected pieces have none. Consequently input `a b` with `--accept-nth=1,2` prints `a b\n`, while `--accept-nth=2,1` prints `ba\n`. More specifically, for input `a b c\nd e f\n` and query `a`, `--accept-nth=1..2` emits `a b\n` and `--accept-nth=1,3` emits `a c\n`. For input `1 apple red\n2 banana yellow\n3 cherry red\n`, `--with-nth=2.. --accept-nth=1,2 --filter=red` emits `1 apple\n3 cherry\n`. With explicit delimiters, selections preserve the appropriate token text/delimiter layout as fzf field transformation does.

Template forms are supported for `--with-nth`/`--accept-nth` using `{n}`, numbered field placeholders such as `{1}` and `{1..3}`, and mixtures of literal text with those placeholders. The action-command placeholders `{}` and `{q}` are not placeholders in these field templates. Thus `--accept-nth={1}:{2} --filter=foo` on `foo bar\n` emits `foo:bar\n`, while `--accept-nth={q}:{} --filter=foo` exits 2 with empty stdout and exactly `template should include at least 1 placeholder: {q}:{}\n` on stderr. `--nth` has no template form. ANSI state associated with selected fields must remain well formed for terminal presentation, with no color leaking from omitted fields.

An argument that is neither a field expression nor a template containing a placeholder is rejected. Specifically, `--with-nth=invalid --filter=test` exits 2 with empty stdout and exactly `template should include at least 1 placeholder: invalid\n` on stderr.

## Spec 12

`--ansi` enables ANSI/control-sequence parsing. Matching, field selection, width measurement, and batch output use visible text with ANSI sequences removed; e.g. `ESC[31mfooESC[m` matches `foo` and filter output is `foo\n`. Without `--ansi`, escape bytes remain ordinary searchable/output bytes and are preserved.

Without `--ansi`, those bytes also participate in official scoring. Let `ESC` denote the single byte `0x1b`. Input `ESC[38;2;255;0;0mrgb redESC[0m\nESC[38;2;0;0;255mrgb blueESC[0m\nESC[38;2;0;255;0mrgb greenESC[0m\nESC[48;2;255;255;0mrgb yellow bgESC[0m\n` with `--filter=gb` exits 0 with empty stderr and emits the records, preserving every escape sequence, in the order blue, red, green, then yellow-background. More explicitly, stdout is `ESC[38;2;0;0;255mrgb blueESC[0m\nESC[38;2;255;0;0mrgb redESC[0m\nESC[38;2;0;255;0mrgb greenESC[0m\nESC[48;2;255;255;0mrgb yellow bgESC[0m\n`.

Malformed escape bytes are likewise deterministic when ANSI parsing is not enabled. Input `ESC[38;5mMissing color paramESC[0m\nESC[incomplete escape\nESC[99mInvalid SGR codeESC[0m\nESC[38;2;255incomplete rgbESC[0m\nnormal text ESC[31mred ESC[32mgreenESC[0m back to normal\n` with `--filter=m` exits 0 with empty stderr and emits those five records in exactly that input order, preserving all bytes.

The parser recognizes SGR basic/bright foreground and background colors, 256-color `38/48;5;N`, RGB `38/48;2;R;G;B`, default colors, combined parameters, bold/dim/italic/blink/reverse/strikethrough, selective resets 22–29, underline styles `4:N`, underline colors `58;5` and `58;2` plus reset 59, and full reset. It recognizes OSC 8 hyperlinks terminated by BEL or ST; CSI cursor/screen/erase sequences including `K`/`0K`; ESC parenthesis/string forms; shift-in/out; and backspace. These controls can affect subsequent visible text rather than merely being deleted in isolation. In particular, input bytes `a ESC[2K b ESC(0 c 0x0f d 0x08 e LF` with `--ansi --filter=` emit exactly `abe\n`; `--ansi --filter=abcde` on the same input exits 1 with no output. Malformed, incomplete, empty, repeated-separator, unknown, or out-of-range sequences are handled deterministically without crash or partial garbage. Terminal rendering preserves valid style spans, including multiline style state and a final reset at truncation, while batch `--ansi` output is clean plain text.

## Spec 13

`-q`/`--query=STR` supplies the initial interactive query. `--print-query` prepends the final query to normal selection/filter output, using the current output delimiter. It prints the query even when there are no matches; the exit status remains 1 in batch no-match cases. `--no-print-query` disables it.

`-1`/`--select-1` causes an interactive invocation to accept automatically only when exactly one match exists; it does not auto-accept multiple matches. `-0`/`--exit-0` exits immediately when no match exists. The corresponding negative forms are `+1`/`--no-select-1` and `+0`/`--no-exit-0`, and they undo the positive option. In filter mode, neither positive option suppresses the complete match list: one match exits 0 and prints it, multiple matches print all, zero matches exits 1. Combining both yields auto-accept for one, immediate no-selection for zero, and interaction for multiple. `--expect=k1,k2` makes the completing key name an output record before the accepted candidate; Enter not named in the list yields an empty key record as fzf does. With `--print-query`, order is query, expected key, then candidate(s). An empty key list is invalid: invocation with `--expect=` and `--filter=test` exits 2 with empty stdout and exactly `key names required\n` on stderr.

Filter-mode ordering is unchanged by `--select-1`. For input `apple\nbanana\ncherry\ndate\neggplant\nfig\ngrape\n`, `--select-1 --filter=a` exits 0 and emits exactly `apple\ndate\ngrape\nbanana\neggplant\n`.

Outside filter mode, `--select-1` still requires interaction whenever its result set is not exactly one item. With piped input `apple\nbanana\napricot\n` and no controlling terminal, both `--select-1 --query=a` and bare `--select-1` exit 2, write nothing to stdout, and write exactly `inappropriate ioctl for device\n` to stderr; neither invocation auto-selects one of the multiple matches.

## Spec 14

Configuration is loaded before CLI parsing. `FZF_DEFAULT_OPTS_FILE`, when nonempty, names a file whose contents are parsed as shell words. `FZF_DEFAULT_OPTS`, when nonempty, is parsed the same way and is applied after the file. Explicit CLI arguments are applied last. Thus precedence is file < options string < CLI, and later values override earlier counterparts. Quoting and escaped spaces follow shell-word parsing; this quoting only groups an option argument and is removed before the query's extended-search parser runs. Consequently `FZF_DEFAULT_OPTS='--exact --filter=two\ words'` supplies the query `two words`, whose space is then an AND-term separator: input `two words\ntwo-other-words\n` emits both records in that order. Malformed quoting is an exit-2 error prefixed with `$FZF_DEFAULT_OPTS:`. A missing/unreadable defaults file is an exit-2 error prefixed with `$FZF_DEFAULT_OPTS_FILE:` even for `--help`. Errors originating in the options string identify `$FZF_DEFAULT_OPTS`.

When stdin is a terminal, `FZF_DEFAULT_COMMAND` supplies candidate input; when stdin is piped it is ignored. With neither piped input nor a default command, directory walking supplies candidates. `FZF_API_KEY` is the key used by listen-server authentication where applicable. Empty option environment variables have no effect.

## Spec 15

`--history=FILE` opens or creates a query-history file on startup, including in filter mode. A newly created file has mode 0600 and filter mode leaves it empty. Interactive acceptance appends the nonempty current query as one newline-terminated entry; abort/cancel and empty queries do not write. Unicode, spaces, and ordinary special characters are retained. Newlines in a query are represented without corrupting the one-entry-per-line file format. Existing entries persist, duplicates are allowed, and every saved file ends in newline.

`--history-size=N` defaults to 1000 and must be positive. Once the limit is exceeded, remove oldest entries and retain newest entries. Up/down history actions navigate previously stored queries. Creation of a nonexistent history path precedes the history-size positivity check: when `--history=FILE --history-size=0 --filter=test` names a nonexistent `FILE`, the program creates it with mode 0600 and empty contents, then exits 2 with empty stdout and exactly `history max must be a positive integer\n` on stderr. Invalid history paths are command-line errors: they exit 2 with empty stdout and prefix the underlying filesystem operation with `invalid history file: `. With empty stdin, `--history=/dev/null/invalid --filter=''` prints exactly `invalid history file: open /dev/null/invalid: not a directory\n`. If `FILE` itself is a directory, stderr is exactly `invalid history file: read FILE: is a directory\n`, with `FILE` replaced by the supplied path. Negative history sizes are likewise rejected with `history max must be a positive integer`.

## Spec 16

When candidate input is not supplied by a pipe/default command, the built-in walker recursively enumerates configured roots. `--walker` is a comma list containing at least one of `file` or `dir`, optionally `follow` and/or `hidden`; defaults are `file,follow,hidden`. `hidden` or `follow` alone is invalid, and unknown words are invalid. Specifically, `--walker=hidden --filter=test` exits 2 with empty stdout and exactly `at least one of 'file' or 'dir' should be specified\n` on stderr. `--walker-root=DIR` is repeatable and defaults to `.`. `--walker-skip=a,b` skips directories by name and defaults to `.git,node_modules`. `file` emits files; `dir` emits directory paths with a trailing slash, so selecting a root child named `unique-directory` emits `unique-directory/\n`. `hidden` includes dot entries, and `follow` follows symlinks. Walker settings are parsed but do not replace actual piped stdin.

## Spec 17

The CLI accepts the display/layout controls listed in the normative help, including their `--no-*` counterparts: `--height`, `--min-height`, `--layout`, `--style`, `--border`, section borders/labels/label positions, `--margin`, `--padding`, `--info`, `--info-command`, `--no-info-command`, `--prompt`, `--ghost`, `--separator`, `--pointer`, `--marker`, `--marker-multi-line`, `--ellipsis`, `--gutter`, `--gutter-raw`, `--tabstop`, `--scrollbar`, `--gap`, `--gap-line`, `--highlight-line`, `--cycle`, `--wrap`, `--wrap-sign`, `--no-multi-line`, `--raw`, `--track`, `--keep-right`, `--scroll-off`, `--no-hscroll`, `--hscroll-off`, `--freeze-left`, `--freeze-right`, and `--jump-labels`. These remain syntactically valid in filter mode and ordinarily do not alter batch records.

Layouts are `default`, `reverse`, and `reverse-list`; styles are `default`, `minimal`, and `full[:border-style]`. Border styles are `rounded`, `sharp`, `bold`, `block`, `thinblock`, `double`, `horizontal`, `vertical`, `top`, `bottom`, `left`, `right`, `line`, and `none`; `noborder`/`border-none` aliases apply where documented. Labels are literal Unicode strings and positions accept signed columns or `center`, optionally `:bottom` where applicable.

The valid `--info` forms are listed in Spec 24. Any other value is a parse error; `--info=invalid --filter=test` exits 2 with empty stdout and exactly `invalid info style (expected: default|right|hidden|inline[-right][:PREFIX])\n` on stderr.

## Spec 18

Sizes and box spacing are validated consistently. `--height` accepts nonnegative lines, a negative terminal-height offset, `0`, 0–100 percent, and adaptive `~N`/`~N%`; adaptive and negative forms cannot be combined. A percentage over 100 reports `height too large (max: 100%)`; nonnumbers report `not a valid integer`; `--height=~-5 --filter=test` and `--height=~-1 --filter=test` each exit 2 with empty stdout and exactly `negative(-) height is not compatible with adaptive(~) height\n` on stderr. `--min-height=N[+]` is nonnegative integer only. The plus form allows automatic growth for decorations. Each of `--min-height=-1`, `--min-height=abc`, and `--min-height=20%`, when combined with `--filter=test`, exits 2 with empty stdout and exactly `minimum height must be a non-negative integer\n` on stderr.

Margin/padding accept CSS-like one, two, three, or four comma-separated values: all; vertical,horizontal; top,horizontal,bottom; or top,right,bottom,left. Values are nonnegative cells or percentages and may be mixed. A per-side percentage must be at most 49 because a single value is applied to opposing sides; `50%` reports `margin too large (max: 49%)` or `padding too large (max: 49%)`. More than four, negative, or nonnumeric components are errors. With `--filter=test`, `--margin=1,2,3,4,5` produces exactly `invalid margin: 1,2,3,4,5\n`, `--padding=1,2,3,4,5` produces exactly `invalid padding: 1,2,3,4,5\n`, and `--margin=abc` produces exactly `not a valid integer: abc\n`; all three exit 2 with empty stdout. `tabstop` and `tail` must be positive; specifically, `--tail=0 --filter=test` exits 2 with empty stdout and exactly `number of items to keep must be a positive integer\n` on stderr, while both `--tabstop=0 --filter=test` and `--tabstop=-5 --filter=test` exit 2 with empty stdout and exactly `tab stop must be a positive integer\n` on stderr. Header lines, preview header lines, scroll offsets, horizontal offsets, and frozen fields must be nonnegative; jump labels cannot be empty. Specifically, `--jump-labels= --filter=test` exits 2 with empty stdout and exactly `empty jump labels\n` on stderr. The tested negative forms exit 2 with empty stdout and the following exact stderr: `--header-lines=-1` produces `header lines must be a non-negative integer\n`; `--hscroll-off=-1` produces `hscroll offset must be a non-negative integer\n`; `--scroll-off=-1` produces `scroll offset must be a non-negative integer\n`; and `--freeze-left=-1` produces `number of fields to freeze must be a non-negative integer\n` (each invocation also includes `--filter=test`).

## Spec 19

`--color` accepts a case-insensitive base theme `dark`, `light`, `base16`/`16`, or `bw`/`no`, optionally followed by comma-separated component specifications. The bare `--color`, `--color=`, and `--no-color` disable coloring; in particular, input `test\n` with `--color --filter=test` emits `test\n`, exits 0, and has empty stderr. Component values are case-insensitive named basic and bright colors (including both `gray` and `grey`), ANSI palette indices `-1` through 255, or `#RRGGBB` with case-insensitive hex. `-1` is the default-color sentinel; values below -1 or above 255 and malformed hex are rejected.

The color components are `ghost`, `disabled`, `fg`, `bg`, `list-fg`, `list-bg`, `preview-fg`, `preview-bg`, `alt-bg`, `selected-fg`, `selected-bg`, `nomatch`, `gutter`, `alt-gutter`, `hl`, `selected-hl`, `border`, `preview-border`, `separator`, `scrollbar`, `preview-scrollbar`, `label`, `list-label`, `list-border`, `preview-label`, `prompt`, `input-bg`, `input-border`, `input-label`, `header-border`, `header-label`, `footer-border`, `footer-label`, `spinner`, `info`, `pointer`, `marker`, `header`, `header-fg`, `header-bg`, `footer`, `footer-fg`, `footer-bg`, and `gap-line`. `query`, `input`, and `input-fg` are aliases; so are `current-fg`/`fg+`, `current-bg`/`bg+`, and `current-hl`/`hl+`. Each of these names accepts a color and remains valid in filter mode. Thus `--color=query:9,disabled:10` is valid (and with input `test\nother\n`, `--filter=test` emits `test\n`, exits 0, and has empty stderr).

Attributes following a color are `bold`/`strong`, `dim`, `italic`, `blink`, underline variants, `reverse`, `strikethrough`, `regular`, and `strip`; several may be combined. In particular, with input `test\n`, `--color=fg:red:blink --filter=test` exits 0, emits exactly `test\n`, and has empty stderr. The `nth` component accepts attributes only, not a color. `--color=nth:red --filter=test` exits 2 with empty stdout and exactly `only ANSI attributes are allowed for 'nth' (regular, bold, underline, reverse, dim, italic, strikethrough)\n` on stderr. Whitespace surrounding comma-separated specifications is ignored and empty members such as the middle member of `dark,,fg:red` are skipped. Unknown components/attributes, missing component colors, malformed values, and invalid base themes produce exit 2. For the tested malformed values, attribute, and invalid component, stderr identifies the complete member: observed exact lines are `invalid color specification: fg:999\n`, `invalid color specification: fg:256\n`, `invalid color specification: fg:-2\n`, `invalid color specification: fg:-5\n`, `invalid color specification: fg:#gggggg\n`, `invalid color specification: fg:#12345\n`, `invalid color specification: fg:#1234567\n`, `invalid color specification: fg:ff0000\n`, `invalid color specification: fg:red:invalid-attr\n`, and `invalid color specification: invalid-component:red\n`. These cases have empty stdout and exit 2. `--no-bold` suppresses bold without disabling other coloring.

## Spec 20

Without `--filter`, the program owns the controlling terminal while reading candidate data from the original stdin. It paints an interactive finder showing a query prompt (default `> `), a match/total counter such as `3/3`, and the matching candidate list. Initially the first ranked item is current. Typing inserts text at the cursor, recomputes matches, count, ranking, and highlight promptly, and keeps the TUI alive for keys with no binding. Enter accepts; Escape, Ctrl-C, and Ctrl-G abort without printing a candidate and return terminal state cleanly.

Default layout places the input/info area and list in official fzf order; reverse and reverse-list rearrange them according to their names. `--height` uses an inline region rather than fullscreen. The program must restore cursor visibility, screen contents/mode, and terminal settings on every exit. It must work under the harness-provided tmux PTY at sizes including 80x24, 100x30, and 120x40.

## Spec 21

Interactive query editing is Unicode aware. Printable text inserts at the cursor. Left/right and Ctrl-B/Ctrl-F move by character; Home/Ctrl-A goes to start and End/Ctrl-E to end. Backspace/Ctrl-H deletes the previous character and Delete deletes the current one. Ctrl-U clears/discards the line, Ctrl-K kills from cursor to end, and Ctrl-W/Unix-word-rubout deletes the preceding whitespace-delimited word. Backward-word and forward-word actions move across words, with `--filepath-word` additionally treating path separators as boundaries; yank restores killed text where bound. Editing a middle substring must preserve the rest of the query and update filtering.

Up/down, Ctrl-P/Ctrl-N, and arrow bindings move the current result in screen direction; PageUp/PageDown and half-page actions move by viewport-sized increments; first/last go to endpoints. In the default bottom-up layout, the initial first-ranked item is at the lower endpoint: Down/Ctrl-N clamps there, while Up/Ctrl-P moves to the second-ranked item. Thus on `apple\nbanana\ncherry`, sending CSI Down then Enter emits `apple\n`, while CSI Up then Enter emits `banana\n`. `--cycle` wraps navigation, otherwise endpoints clamp. Function keys F1–F12 and modified arrows/keys are decoded and can be bound. When unbound they do not crash or insert escape-sequence garbage.

## Spec 22

`-m`/`--multi[=MAX]` enables selection marking. Omitted maximum or `0` means unlimited; a positive maximum enforces that cap. Tab toggles the current item then moves down; Shift-Tab toggles and moves up. Direction is the screen direction described in Spec 21. Consequently, from the initial lower endpoint in the default layout, two Tabs toggle `apple` on and back off and Enter emits only `apple\n`; two Shift-Tabs mark `apple` and `banana`, and Enter emits `apple\nbanana\n`. Explicit `select`, `deselect`, `toggle`, `select-all`, `deselect-all`, and `toggle-all` actions manipulate marks. Marks persist when filtering temporarily hides their candidates. Accepting with any marked candidates emits all marked records in selection/input order; otherwise it emits the current candidate. Filter mode continues to emit all matches. Custom `--marker` changes the marker. `--marker-multi-line` must have total display width 0, 3, or 6; other widths fail with `invalid total marker width: N`.

## Spec 23

Long-line rendering measures terminal cells: ordinary characters are width 1, combining marks width 0, CJK/wide characters and ordinary emoji use their terminal widths, tabs advance to the next `--tabstop` boundary (default 8), and ANSI escapes have width 0. Without wrap, overflow is truncated using `--ellipsis` (default `··`) without splitting a wide/combining character, and active ANSI style is reset. `--keep-right`, horizontal scrolling, `--no-hscroll`, and `--hscroll-off` govern which end/match context remains visible. With `--wrap`, records occupy multiple screen rows prefixed by `--wrap-sign`; `--no-multi-line` flattens NUL-delimited multiline records.

Vertical scrolling keeps the current item visible and honors `--scroll-off`. A scrollbar appears only when content exceeds the viewport, moves proportionally as the current page changes, works in reverse layout and with borders, uses the configured Unicode character(s), uses an ASCII-compatible glyph under `--no-unicode`, and disappears with `--no-scrollbar` or `--scrollbar=`. Empty/very small viewports and empty lines render without panics.

## Spec 24

Static and section UI options compose. `--header=STR` adds literal header text; repeated headers accumulate. `--header-lines=N` removes the first N input records from the searchable list and displays them as headers; N beyond input length yields no searchable candidates. `--header-first` places headers before input. Header-line text can have a distinct `--header-lines-border`. `--footer`, input/list/header/footer borders, labels, and positions render in their respective regions. `--info` supports `default`, `right`, `hidden`, `inline[:PREFIX]`, and `inline-right[:PREFIX]`; `--no-info` hides it. `--info-command=COMMAND` and the separate-operand form `--info-command COMMAND` supply a command that generates the info line, while `--no-info-command` disables that command. These forms remain valid in filter mode: with piped empty input, `--filter '' --info-command 'echo custom'` has empty stdout and stderr and exits 1. Separator, ghost text, gap count/line, margins, padding, and style presets affect geometry without changing underlying data.

ANSI header content is interpreted when ANSI mode is enabled. Border geometry uses the official glyph sets for rounded, sharp/line, bold, block, thinblock, double, horizontal, vertical, and side-only forms, including correct Unicode cell widths and intersections. Color themes/components apply to their corresponding regions.

## Spec 25

`--preview=COMMAND` runs the configured shell command for the current item and displays its output in a preview region. `--preview-window` accepts positions `right`, `left`, `up`/`top`, and `down`/`bottom`, optional absolute/percentage size, `wrap`/`nowrap`, `cycle`/`nocycle`, `follow`/`nofollow`, `info`/`noinfo`, `hidden`/`nohidden`, `border-STYLE`, `noborder`/`border-none`, scrolling offsets, `~HEADER_LINES`, `default`, and valid combinations. The standalone compatibility tokens `border`, `rounded`, and `sharp` are also accepted. Preview percentage sizes from `0%` through `99%` are accepted; both `--preview-window=100%` and `--preview-window=101%` exit 2 with empty stdout and exactly `window size too large (max: 99%)\n` on stderr. Bad header counts or unknown tokens are errors. `--preview-border` is the border shorthand; preview label and label position apply to this region.

Preview runs initially unless hidden, refreshes when current item/query changes, and can be toggled. Nonzero or missing preview commands show an error in the preview without terminating the finder. Preview scrolling, wrap, fixed header lines, and position changes update the region. Stale preview processes/output must not overwrite a newer current preview.

## Spec 26

`--bind=BINDINGS` parses comma-separated `KEY:ACTION` bindings; multiple keys may share an action, and actions joined by `+` execute left-to-right. Parenthesized command/action arguments may contain spaces, commas, plus signs, nested delimiter forms, and empty commands where the action permits them. A binding without an action, an empty key, an unknown key/action, missing targets for unbind/rebind/toggle-bind, nonprintable `put`, or an invalid nested preview option is rejected. With `--filter=test`, the following invocations exit 2 with empty stdout and the exact stated stderr: `--bind=ctrl-a` gives `bind action not specified: ctrl-a\n`; both `--bind=:accept` and `--bind=:abort` give `key name required\n`; `--bind=invalid-key:abort` gives `unsupported key: invalid-key\n`; `--bind=ctrl-a:unbind()` gives `unbind target required\n`; `--bind=ctrl-a:rebind()` gives `rebind target required\n`; `--bind=ctrl-a:toggle-bind()` gives `toggle-bind target required\n`; and `--bind=ctrl-a:put` gives `unable to put non-printable character\n`. Repeated binds augment/override the current map.

Command-taking transform actions additionally accept a colon form, `KEY:ACTION:COMMAND`, rather than requiring parentheses. This applies to `transform`, `bg-transform`, and their label targets, including `transform-list-label` and `bg-transform-list-label`. For example, with input `line1\nline2\nline3\n`, each of `--filter '' --bind 'ctrl-a:transform:echo'`, `--filter '' --bind 'ctrl-a:bg-transform:echo'`, and `--filter '' --bind 'ctrl-a:bg-transform-list-label:echo'` is valid, exits 0, has empty stderr, and emits the three input records exactly once.

Accepted key names include printable characters, Enter/Escape/Backspace/Delete/Home/End/Insert, arrows, PageUp/PageDown, Tab/Shift-Tab, F1–F12, mouse clicks/wheel/scroll, and valid Ctrl/Alt/Shift combinations used by terminal protocols. The accepted compatibility spellings include `pgup`, `pgdn`, `page-up`, `page-down`, `btab`, `shift-tab`, `enter`, `return`, `esc`, `space`, `bspace`, and `backspace`. Accepted event triggers include startup/load/result/change/focus/one/zero and the other events documented by the help/manual. Navigation, editing, selection, display, preview, termination, reload, transform, change-*, unbind/rebind/toggle-bind, put, ignore, and execute action families must parse in filter mode even when they cannot fire there.

## Spec 27

Actions mutate live state as their names imply. Tested core actions include accept/abort/close, up/down/first/last/page/half-page, query movement/deletion, toggle/select/deselect, toggle-sort, toggle-wrap, toggle-header, toggle-preview, refresh-preview, change-query, clear-query, change-prompt, change-preview, reload, transform-query, transform-border-label, execute, execute-silent, and become. `close` is state-dependent: when the preview is visible it hides that preview and leaves the finder active; when no preview is visible it aborts the finder without selection output. `reload(COMMAND)` replaces candidate input and refilters. If its child command fails, the finder remains active and displays `[Command failed: COMMAND]` in the info line; for `reload(invalid_cmd_xyz)`, that text is exactly `[Command failed: invalid_cmd_xyz]`. `change-preview(COMMAND)` changes subsequent preview generation. Transform actions use command stdout as the new target value; command failure is nonfatal. Toggle actions can be applied repeatedly and return to their prior state.

`execute` temporarily runs a child command and returns; `execute-silent` runs without leaving the UI; rapid invocations remain safe. `become` replaces/exits the finder into its child command. A failed child does not corrupt the terminal; an execute-silent failure is ignored except where an action explicitly exposes an error.

## Spec 28

Commands for preview/execute/reload/transform are started through the shell configured by `--with-shell` (values such as `sh`, `/bin/sh`, `bash`, `/bin/bash` are valid). Without `--with-shell`, a nonempty `SHELL` environment value is the command shell; if `SHELL` is unset or empty, the fallback is `sh`. Shell diagnostics are therefore those of that selected shell. In particular, with `SHELL=/bin/bash`, input `line1\nline2\nline3\n`, and `--preview invalid_command_xyz`, the preview displays exactly `/bin/bash: line 1: invalid_command_xyz: command not found`; the missing preview command does not terminate the finder, whose count remains `3/3`.

Placeholders are shell-quoted substitutions: `{}` is current original item; `{q}` current query; `{n}` zero-based original item index; `{1}` or `{A..B}` selected item fields; `{+}` all marked items or the current item when none are marked; `{+f}` a temporary newline file holding those items; and `{fzf:action}` the most recently completed action name. Multiple placeholders in one command are independently expanded. Items containing spaces, apostrophes, and other shell metacharacters must arrive as one safe argument rather than being reinterpreted.

For example, on first item `apple\tred\tfruit` with tab delimiter, `{2}` expands to `red`; on the first candidate `{n}` expands to `0`; and after selecting four space-containing records, `{+}` supplies all four. Temporary placeholder files live long enough for the child and are then cleaned up.

## Spec 29

`--listen=PORT` or `--listen=ADDR:PORT` starts an HTTP control server alongside the interactive finder; a `.sock` value selects a Unix-domain socket. GET `/` returns JSON state with at least `query`, `matches`, `matchCount`, `totalCount`, `current`, `reading`, and `progress`. After all piped input is read, `reading` is false and `progress` is 100. Each match object contains at least its visible `text`. GET query parameters `limit` and `offset` return the corresponding result slice.

POST `/` takes a plain action expression and applies it to the live finder. `change-query(apple)` updates query/results, `clear-query` restores the empty query, and successive requests retain state. A valid action returns HTTP 200. Unknown action `invalid-action-xyz` returns 400 with body `unknown action: invalid-action-xyz\n`; an empty body returns 400 with `invalid content length\n`. The listener remains responsive while the terminal is active and shuts down with the finder.

## Spec 30

`--tmux[=OPTS]` requests a harness-provided tmux popup only in interactive mode inside tmux. Valid positions are `center`, `top`/`up`, `bottom`/`down`, `left`, and `right`; sizes may be absolute or percentages up to 100. `border-native` is accepted alone or with position/sizes. Default is `center,50%`. The parser accepts three comma components after the position even when the last is numeric: with input `x\n`, `--tmux=center,1,2,3 --filter=` exits 0 and emits `x\n`. A fifth total component is too many: `--tmux=center,1,2,3,4 --filter=` exits 2 with an `invalid tmux option` diagnostic. Bad positions, nonnumeric sizes in the validated size slots, and oversized percentages likewise produce `invalid tmux option` errors. In particular, `--tmux=invalid --filter=test` exits 2 with empty stdout and exactly `invalid tmux option: invalid (expected: [center|top|bottom|left|right][,SIZE[%]][,SIZE[%][,border-native]])\n` on stderr. `--no-tmux` disables it. Between `--height` and `--tmux`, the later option selects the display mode.

The popup invocation uses `tmux display-popup` with position/width/height arguments. Normal mode requests tmux's no-border flag (`-B`); `border-native` omits `-B`. Working directory is retained and values containing apostrophes are safely quoted. Environment variables, including arbitrary caller values, are exported into a generated proxy script; it explicitly neutralizes `FZF_DEFAULT_COMMAND` and `FZF_DEFAULT_OPTS` and reinvokes this executable with `--proxy-script`, `--no-tmux`, `--no-height`, and `--no-force-tty-in`. For piped input it creates `/tmp/fzf-proxy-input-*` and `/tmp/fzf-proxy-output-*` as actual FIFOs before invoking tmux and connects data/output through them. Invocation with `/dev/null` still generates the popup script without hanging.

## Spec 31

Option validation happens even when an option has no observable effect in filter mode. Missing required operands (`--delimiter`, `--query`, `--preview`, `--history`, etc.), unknown options/actions, and malformed values exit 2. Stderr identifies the offending option/value. In addition to errors specified above: invalid scheme lists `default|path|history`; invalid layout lists `default / reverse / reverse-list`; invalid info names the supported default/right/hidden/inline forms; invalid border lists supported styles; negative header-lines says they must be non-negative; nonpositive tabstop says it must be positive; negative scroll/hscroll/freeze values say non-negative; invalid preview token says `invalid preview window option`; and unknown `--unknown` prints exactly `unknown option: --unknown\n` with empty stdout.

Options with optional arguments accept their bare forms with documented defaults, including `--border`, `--multi`, `--gap`, `--gap-line`, `--scrollbar`, `--color`, and `--tmux`. Positive and negative aliases (`--ansi`/`--no-ansi`, `--sort`/`--no-sort`, headers/footers/borders/labels/info/preview/scrollbar variants) are accepted and the last occurrence controls. Compatibility aliases `--reverse`, `--inline-info`, `--no-inline-info`, short `-1`, `+1`, `-0`, `+0`, `-m`, `-e`, `+e`, `-i`, `+i`, `+s`, and attached short values such as `-fQUERY`, `-qQUERY`, `-dSTR`, and `-nEXPR` are parsed.

The compatibility option `--toggle-sort=KEY` is equivalent to binding one key to `toggle-sort`; exactly one key is allowed, and a comma-separated list fails with `multiple keys specified`.

## Spec 32

The implementation must be robust and externally deterministic. Candidate text is decoded as UTF-8; each malformed input byte is replaced by U+FFFD in output. For example, `good\ninvalid-` followed by bytes `FF FE` and then `-byte`, filtered with the empty query and `--no-sort`, emits `good\ninvalid-` followed by UTF-8 bytes `EF BF BD EF BF BD` and then `-byte\n`. Apart from that decoding, ANSI stripping, output record termination, and accept-field transformation, candidate content is retained. It supports Unicode and arbitrary long records without truncating batch output, processes large streams within ordinary five-second test timeouts, and never emits debug/coverage text. Concurrent history/server/TUI invocations use isolated state. Temporary scripts, placeholder files, sockets, and proxy FIFOs are uniquely named and cleaned up when their owning invocation finishes normally.

Signals and terminal exits are graceful: accepting returns 0, no-match filter returns 1, user abort returns the normal fzf abort status without selection output, and parse errors return 2. Child-command failures, empty preview content, rapid actions, changing result sets, and end-of-input do not crash the process. All observable behavior must agree with the fixed help/shell payloads and the option semantics in this document; implementation details are unrestricted.
