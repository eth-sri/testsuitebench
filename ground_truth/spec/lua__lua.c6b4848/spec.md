# Clarified specification for `executable`

The artifact is one executable file named exactly `executable`. It is a standalone Lua 5.5.1 command-line interpreter. This document defines the observable command-line, language, runtime, and library behavior required of it. “Error” below means a Lua error: it is catchable by `pcall`/`xpcall` inside a program, but if it escapes the top-level chunk the process reports it and normally exits unsuccessfully; Spec 5 defines the distinct status behavior of automatically consumed stdin.

## Spec 1

`executable` must be directly runnable and implement the invocation form `executable [options] [script [args]]`. It is an interpreter, not a subcommand program: words such as `help`, `add`, `remove`, and `list` in the script position are filenames and normally fail with a file-open diagnostic. It opens the base, package, coroutine, string, UTF-8, table, math, I/O, OS, and debug libraries by default. A successful ordinary run exits with status 0. Except for the automatic-stdin case in Spec 5, a command-line, load, syntax, or unhandled runtime error exits with status 1. `os.exit` can deliberately choose another status. Normal output is written to stdout; option diagnostics, load failures, uncaught errors, tracebacks, and warnings are written to stderr. Empty valid input, comments only, an empty script, and an ignored top-level return value produce no output.

The implementation must be robust enough for large programs, tables, strings, argument/result lists, deep nested closures and coroutines, and stress runs. It must report controlled “stack overflow”, “too many results”, syntax, or allocation errors instead of crashing or hanging. Text I/O is UTF-8-clean and preserves arbitrary non-NUL Unicode text. Lua strings themselves are byte strings and may contain NUL and invalid UTF-8.

## Spec 2

Recognized options are exactly `-e stat`, `-i`, `-l mod`, `-l g=mod`, `-v`, `-E`, `-W`, `--`, and `-`. Options are scanned left-to-right only before the script position. `-eSTAT` and `-lMOD` are accepted as concatenated forms; `-e=STAT` treats `=STAT` as the Lua source (and therefore normally raises a Lua syntax error). In the separated `-e stat` form, a following token whose first character is `-` is treated as a missing argument rather than as `stat`, even when that token would be valid Lua source. For example, `-e` followed by a source token beginning `--[=[` exits 1 with the standard `'-e' needs argument` diagnostic and usage; concatenating that same source directly to `-e` executes it. Other options may not be combined: for example `-iv`, `-vi`, `-vv`, `-Ex`, `-x`, `---`, `--foo`, `-h`, and `--help` are unrecognized. `--` ends option scanning; the next token, even a lone `-`, is the literal script filename. Thus `executable -- -` attempts to open a file named `-`; it does not read stdin, and when that file is absent it exits 1 with `cannot open -: No such file or directory`. In contrast, a lone `-` encountered as an option ends option scanning and selects stdin as the script. Once a script is selected, every later token is a script argument, not another option. Only the first positional script is executed.

For an unrecognized option, write `<program>: unrecognized option '<token>'` followed by the usage block below to stderr and exit 1. A bare `-e` or `-l` similarly writes `<program>: '-e' needs argument` or `<program>: '-l' needs argument`, then the same block. `<program>` is the actual `argv[0]` spelling/path used to invoke the executable.

```text
usage: <program> [options] [script [args]]
Available options are:
  -e stat   execute string 'stat'
  -i        enter interactive mode after executing 'script'
  -l mod    require library 'mod' into global 'mod'
  -l g=mod  require library 'mod' into global 'g'
  -v        show version information
  -E        ignore environment variables
  -W        turn warnings on
  --        stop handling options
  -         stop handling options and execute stdin
```

The block ends in a newline and contains no ANSI escapes. `-h` and `--help` are merely invalid options and return 1; apart from the echoed invalid token their outputs are the same. The option list is validated before version or command-line actions produce output. If a later option is invalid or lacks its argument, earlier `-v` and `-e` actions are suppressed. In particular, `executable -E -v -h` exits 1 with empty stdout and emits the invalid-option diagnostic and usage on stderr; it does not emit the version line first.

## Spec 3

If one or more separate `-v` options occur and the complete option scan succeeds, the invocation writes exactly one copy of this line to stdout and does not terminate option processing:

```text
Lua 5.5.1  Copyright (C) 1994-2026 Lua.org, PUC-Rio
```

There is one terminating newline and no stderr output on a version-only run. The version line is emitted before executable option actions even if `-v` occurs after them syntactically: `-e "io.write('ok')" -v` writes the version line followed by `ok`. Additional separate `-v` options produce no additional copy; `-v -e "io.write('ok')" -v` likewise writes one version line followed by `ok`. Later `-e`, `-l`, or script actions still run. The predefined string `_VERSION` is `Lua 5.5` (language compatibility version, without patch number).

## Spec 4

Each successfully parsed `-e stat` compiles `stat` as a chunk named `(command line)` and executes it in left-to-right option order. The separated-form restriction for a dash-prefixed `stat` is specified in Spec 2 and is applied before compilation. Multiple chunks share the same global environment, so assignments in one are visible in later `-e` chunks and in the script. Chunk return values are discarded. A syntax/runtime error stops all later options and the script.

Each `-l mod` performs the equivalent of `globalName = require(mod)` at that point. With `-l g=mod`, `globalName` is `g`; without `=`, it is the module name with any suffix beginning at the first hyphen removed (so requiring `mymodule-v1` installs the result as global `mymodule`). The full, unstripped name is passed to `require`. Multiple `-l` options work and interleave correctly with `-e`. Missing or faulty modules abort with status 1 and the normal module-search/error traceback.

`-W` enables the warning system before subsequent work. `-E` selects ignore-environment mode for the whole invocation even when encountered among other options. `-i` requests the interactive session described later, after all option chunks and any script finish.

## Spec 5

If a script filename is present, load and execute that file. A first line beginning with `#` (including a Unix `#!` line) is ignored while retaining correct following line numbers. A missing file exits 1 and writes `<program>: cannot open <filename>: <operating-system reason>`, normally ending in `No such file or directory`. For syntax/runtime diagnostics and traceback frames, a filename of at most 59 bytes is shown in full, but a longer filename is shortened to a 59-byte source identifier consisting of `...` followed by its final 56 bytes. This shortening does not disturb source line accounting: an error on the line after a shebang is reported at line 2. A top-level script return does not print values or determine process status.

If stdin was selected by the `-` option, read one non-interactive chunk from stdin and name it `stdin`; a `-` selected as the positional filename after `--` is instead opened literally as specified above. If there is no script and neither `-e`, `-l`, nor `-v` supplied work requiring a script, non-terminal stdin is likewise read and executed as a single chunk. A trailing `--` with no following filename does not suppress this automatic-stdin behavior: piping `io.write('ignored')` to `executable -E --` writes `ignored` and exits 0. EOF/empty stdin succeeds silently. Syntax/runtime errors from stdin use `stdin:<line>` in diagnostics. The two stdin paths differ in process status on an error: explicitly selecting stdin with `-` exits 1, while an error in stdin consumed automatically because no script/action was supplied is diagnosed on stderr but the process exits 0. For example, piping `error('stdinbad')` to `executable -E` reports `stdin:1: stdinbad`, produces no stdout, and exits 0.

Before initialization or option chunks execute, create global table `arg`. For a real script, `arg[0]` is its exact filename and `arg[1]...arg[n]` are the following tokens verbatim; `#arg` is `n`. Earlier raw command-line entries occupy consecutive negative indices, with the interpreter spelling immediately before `arg[0]` when no options intervene (for example a plain script has `arg[-1] = argv[0]`). When command-line actions are supplied without a script, `arg[0]` is `argv[0]`, `arg[-1]` is nil, and every original token after `argv[0]` occupies the corresponding positive index; therefore `#arg` is the number of those tokens, including options and their operands. For `executable -E -e <source>`, `#arg` is 3 and `arg[1]`, `arg[2]`, and `arg[3]` are `-E`, `-e`, and `<source>`, respectively. Script arguments are also passed as the variable arguments of the main script chunk. Shell-looking text, spaces, dollar signs, and option-looking arguments are never rewritten.

## Spec 6

Interactive mode is entered when `-i` is present, after initialization, all `-e`/`-l` actions, and any script. It writes the exact version line from Spec 3, then uses `_PROMPT` or `"> "` for a primary prompt and `_PROMPT2` or `">> "` for continuation lines. It reads and evaluates successive input units until EOF or `os.exit`. It first tries `return <line>` and, if that is not a complete expression, treats input as statements. There is no special leading-`=` expression shorthand: input `= x+1` reports `stdin:1: unexpected symbol near '='`, prints no expression value, and the REPL continues with another primary prompt. An incomplete construct (such as a function body awaiting `end`) continues across lines with the secondary prompt. Returned expression values are printed using `print` conventions. Errors are reported but the REPL continues. Globals established by prior options/scripts remain visible. EOF after the prompt exits 0. With no `-i`, piped stdin is batch input and has no banner or prompts.

## Spec 7

Unless `-E` is used, initialization checks `LUA_INIT_5_5` first and falls back to `LUA_INIT`. If selected content begins with `@`, execute the remainder as a filename; otherwise compile it as a chunk named after the selected environment variable. Thus an inline error from `LUA_INIT_5_5` is attributed to `LUA_INIT_5_5:<line>`, while one from the fallback is attributed to `LUA_INIT:<line>`. Initialization happens before all command-line `-e`/`-l` actions and the script, in the same global state and with `arg` already present. A missing init file, syntax error, or runtime error aborts before later work and is attributed to that filename or environment-variable name.

The package paths are initialized, in priority order, from `LUA_PATH_5_5`, then `LUA_PATH`, then the default; and analogously from `LUA_CPATH_5_5`, then `LUA_CPATH`, then the default. Within an environment value, `;;` is replaced by the complete default path. `-E` ignores all these Lua-specific environment variables and uses defaults, but ordinary process environment variables remain available through `os.getenv`. The default Lua path is exactly `/usr/local/share/lua/5.5/?.lua;/usr/local/share/lua/5.5/?/init.lua;/usr/local/lib/lua/5.5/?.lua;/usr/local/lib/lua/5.5/?/init.lua;./?.lua;./?/init.lua`. The default C path is exactly `/usr/local/lib/lua/5.5/?.so;/usr/local/lib/lua/5.5/loadall.so;./?.so`.

## Spec 8

An uncaught compile/load/runtime error writes a diagnostic prefixed by `<program>: `. Runtime diagnostics identify source and line and are followed, when a stack exists, by `stack traceback:` and tab-indented frames. Frames distinguish `[C]`, `in global 'name'`, `in local 'name'`, `in function ...`, `in main chunk`, and a final `[C]: in ?` as appropriate. A command-line `error('boom')` therefore starts with `<program>: (command line):1: boom`. A non-string top-level error object is rendered descriptively, for example `error{}` reports `error object is a table`. Script errors preserve stdout already written, suppress later statements, and go to stderr. Calling a nil local identifies it: a local `x` called on line 2 reports `attempt to call a nil value (local 'x')` at that source and line.

Syntax diagnostics use Lua's exact token display conventions. End of input is written as `<eof>`, not `'eof'`: an unfinished `return 1 +` reports `unexpected symbol near <eof>`, including when compiled by `load` with a custom chunk name or read from stdin. An unfinished function parameter list reports `<name> or '...' expected near <eof>`. The malformed source `syntax error here!`, whether in a file or a `-e` chunk, reports `syntax error near 'error'`. Other syntax diagnostics likewise mention the offending or expected token and accurate line. Calling non-functions, indexing nil, invalid table keys, arithmetic/comparison type errors, recursion overflow, and invalid API arguments produce descriptive Lua errors. Standard-library argument failures use the canonical `bad argument #<n> to '<called-name>' (<detail>)` form; the called name is the name known at that call site.

`-W` enables warnings and is equivalent to issuing the warning control message `@on`. `warn(s1,...)` accepts strings and numbers, converts numbers to their ordinary string form, concatenates the pieces without separators, and emits `Lua warning: <message>\n` to stderr when enabled. Thus `warn('a',3)` succeeds and, when warnings are enabled, emits exactly `Lua warning: a3\n`; a boolean piece instead raises the normal `string expected` argument error. A single-argument message starting with `@` is a control message: `@on` and `@off` toggle emission; `@allow` makes control-looking text allowable according to Lua's warning protocol. Control messages themselves are not ordinary output. Errors raised by `__gc` finalizers are converted to warnings instead of aborting the process and are visible when warnings are enabled.

## Spec 9

Source is parsed as Lua 5.5 syntax. ASCII whitespace and `--` line comments are ignored; `--[=*[ ... ]=*]` are long comments. Identifiers use ASCII letters, digits, and underscore and cannot start with a digit. Reserved words are `and break do else elseif end false for function global goto if in local nil not or repeat return then true until while`. Punctuation/operators include `+ - * / // % ^ # & | ~ << >> == ~= <= >= < > = ( ) { } [ ] :: ; : , . .. ...`.

Short strings use either quote style and support `\a \b \f \n \r \t \v \\ \" \'`, escaped newline, `\z` followed by skipped whitespace, `\xXX`, decimal `\ddd` (up to three digits, byte range), and `\u{hexadecimal-value}` encoded with Lua's extended UTF-8 encoding. `\z` skips actual whitespace characters in the source immediately after it; a following two-character escape such as `\n` is not source whitespace and is then interpreted normally. Consequently `"A\x42\067\u{1F642}\z   \nX"` has length 9 and bytes `41 42 43 F0 9F 99 82 0A 58`, including the newline byte produced by `\n`. A `\u` value may be any integer from 0 through `0x7FFFFFFF`, not only a Unicode scalar: `\u{110000}` produces bytes `F4 90 80 80`, and `\u{7FFFFFFF}` occupies six bytes. `\u{80000000}` fails with `UTF-8 value too large`. Long strings use `[=*[ ... ]=*]`, may span lines, and ignore an immediate initial newline. Long delimiters nest only when their equals counts differ. Strings handle at least tens of thousands of bytes and embedded NUL.

Decimal integers/floats, decimal exponents, hexadecimal integers, and hexadecimal floating literals with binary `p` exponents are accepted, including boundary-sized 64-bit integers. Malformed tokens and unfinished constructs are syntax errors with accurate lines. Source may contain UTF-8 bytes inside strings/comments; identifiers remain the defined ASCII form.

## Spec 10

Runtime values have types `nil`, `boolean`, `number`, `string`, `function`, `userdata`, `thread`, and `table`; `type` returns those strings. Numbers have two subtypes: signed 64-bit two's-complement integers (`-9223372036854775808` through `9223372036854775807`) and IEEE-754 binary64 floats. Numeric operations preserve integer type when defined as integer operations and otherwise use float. Tables, functions, threads, and userdata have identity; strings compare by bytes; nil is the absence of a table field. Only `false` and `nil` are false in conditions—zero and empty string are true.

`tostring` prints nil/booleans literally and integers in decimal. Finite floats use Lua's canonical compact `%g`-style decimal conversion: use up to 15 significant digits when that text converts back to the same binary64 value, and extend to 17 significant digits when needed for round-tripping. Consequently the relevant exact spellings include `3.2`, `3.14`, and `3.14159`, while `math.pi` is `3.1415926535897931`; redundant tails such as `3.1400000000000001` are not emitted. Large magnitudes use exponent notation where this conversion selects it, so `1e308` prints exactly `1e+308`. Integral floats retain a visible floating form when printed without an exponent, such as `3.0` and `25000000000.0`; special values use `inf`, `-inf`, and the specified operation's `nan` spelling. `print(...)` applies this conversion, separates values with one tab, ends with one newline, and prints only a newline for no arguments. `io.write` and file-handle `write` use the same number conversion, with no separators or automatic newline.

## Spec 11

Variables are lexical locals, declared globals, or fields of the current `_ENV`; `_G` refers to the initial global environment. Blocks create scopes; locals shadow outer names; closures capture live variables (upvalues), not snapshots, and retain/mutate them after the defining call returns. Parallel assignment evaluates expressions before stores, adjusts result counts with nil, and handles overlapping lvalues correctly. An undefined ordinary global reads as nil.

`local` declarations may use `<const>` (read-only after initialization) and `<close>` (closed on scope exit). To-be-closed values must have a `__close` metamethod and close in reverse declaration order on return, break, goto, error, coroutine close, and a state-closing `os.exit`; the method receives the value and current error object, and close errors propagate according to Lua error unwinding rules.

Lua 5.5 also accepts `global` declarations: `global name`, `global name = value`, `global function name...`, optional `<const>`, and `global [<const>] *`. Without an explicit global declaration a chunk behaves as if it began with `global *`. Once a narrower declaration is used in a scope, undeclared bare global references are compile errors there. Initialized global declarations error if the target already has a non-nil value; uninitialized declarations leave its value unchanged. Global restrictions are lexical/syntactic and do not prevent explicit `_ENV.x` access. Numeric and generic `for` control variables are read-only.

## Spec 12

Arithmetic supports `+ - * / // % ^` and unary `-`; `/` is floating division, including IEEE infinity/NaN on zero, while `//` floors toward negative infinity and `%` satisfies `a - (a // b) * b`. Integer `+ - *` and unary minus wrap modulo 2^64; exponentiation is floating. Numeric strings are coerced for arithmetic where Lua permits it; incompatible operands error. Concatenation `..` joins strings and numbers. Length `#` returns string byte length or a valid table border. Bitwise `& | ~ << >>` and unary `~` operate on integers; exactly integral floats can convert, shifts are logical on the 64-bit representation, oversized shifts yield zero, and negative shift counts reverse direction.

Equality compares type/value or identity and can use `__eq`; numeric integer/float equality is mathematical when exactly comparable. Ordering works numerically across number subtypes, lexicographically for strings under the C locale, or via `__lt`/`__le`; incompatible values error. `and` and `or` short-circuit and return operands, while `not` returns a boolean. Precedence/associativity are standard Lua: `or`, `and`, comparisons, `|`, `~`, `&`, shifts, `..` (right associative), `+ -`, `* / // %`, unary, then `^` (right associative, binding beyond unary in the Lua manner).

## Spec 13

Statements include assignment, calls, empty `;`, `do...end`, `if/elseif/else/end`, `while`, `repeat...until`, numeric and generic `for`, `break`, labels `::name::`, `goto name`, declarations, function declarations, and `return`. Numeric `for i=a,b[,step]` evaluates controls once and iterates inclusively with positive or negative steps without overflowing at integer boundaries. Generic `for` uses iterator/state/control/closing values and repeatedly calls the iterator. `repeat` tests after its body and keeps body locals in scope for the test. `break`, `return`, and `goto` close exited `<close>` scopes. A goto cannot jump into the scope of a local, and duplicate/undefined labels are errors. A label at the end of a block is treated as outside the scope of locals declared in that block, so `goto x; local a; ::x::` is accepted and runs silently. This exception depends on the label's position, not on whether the local is used: `goto x; local a; ::x:: io.write("ok")` fails with `<goto x> at line 1 jumps into the scope of 'a'`, even though the statement after the label does not reference `a`.

## Spec 14

Functions are first-class closures. Definitions support ordinary parameters, method syntax (`obj:m(a)` is `obj.m(obj,a)` with one evaluation of `obj`), anonymous functions, recursive local functions, and proper tail calls. Missing fixed arguments become nil and excess arguments are discarded unless variadic. Calls and returns support multiple values. A function call or `...` in the last position of an expression list contributes all results; elsewhere or in parentheses it contributes one. Assignments/declarations pad or truncate to their target count. A function reaching its end returns no values.

Variadic syntax is `...` and, in Lua 5.5, optionally `...name`. Extra arguments form a vararg table with integer keys and `n` equal to the true count including nils. An optional name is a read-only local referring to that table; the `...` expression expands entries 1 through `n`. `select('#',...)` returns the count; numeric `select(i,...)` returns values from `i` onward, with negative indices from the end and invalid zero/out-of-range-low indices erroring. Argument and result lists are preserved when the containing function fits the compiler's 255-register limit. This is a compilation limit, not a promise that 1,000 separately written argument expressions compile: a main chunk defining `f(...)` and calling `f(1,2,...,1000)` fails at compile time with `too many registers (limit is 255) in main function near '254'`.

## Spec 15

Tables are heterogeneous associative arrays. Constructors support list fields, `name=value`, `[expr]=value`, commas/semicolons, nested constructors, and full expansion of a final multivalue list field. Positive list fields start at key 1. Any non-nil, non-NaN value can be a key; assigning nil removes a key. `t.x` means `t['x']`. A sequence is a table with integer keys 1 through a border; `#t` returns a border, with deterministic conventional results for ordinary dense arrays.

`next(t[,k])` returns a next key/value or nil and supports continuing from a returned key; invalid continuation keys error. A non-table first argument such as `next(42)` raises `bad argument #1 to 'next' (table expected, got number)`. `pairs` normally returns `next,t,nil` but honors `__pairs`. `ipairs` yields `(1,t[1]), (2,t[2]), ...` and stops at the first nil. Every ordinary `ipairs` call returns the same built-in iterator function object, so `select(1,ipairs{}) == select(1,ipairs{})` is true. `rawget`, `rawset`, `rawlen`, and `rawequal` bypass metamethods. Iteration works over large tables while respecting the rule that arbitrary insertion/removal during traversal need not have a stable order. Weak tables use metatable `__mode` values `k`, `v`, or `kv` and allow collectible keys/values to disappear.

## Spec 16

Tables and userdata can have metatables; `setmetatable(t,mt-or-nil)` sets/removes one and returns `t`, while `getmetatable` returns it unless its `__metatable` field protects it, in which case that field is returned and replacement errors. `setmetatable("string", {})` raises `bad argument #1 to 'setmetatable' (table expected, got string)`. The debug versions bypass protection and can operate on other value types. Strings share a type metatable that supplies string methods.

Implement metamethod dispatch for `__index`, `__newindex`, `__call`, `__tostring`, `__name`, `__len`, `__eq`, `__lt`, `__le`, `__concat`, `__close`, `__gc`, and all arithmetic/bitwise names (`__add`, `__sub`, `__mul`, `__div`, `__idiv`, `__mod`, `__pow`, `__unm`, `__band`, `__bor`, `__bxor`, `__shl`, `__shr`, `__bnot`). `__index`/`__newindex` may be tables or functions and chain normally. Binary operators try the appropriate operand metatable in Lua order. Calls may follow a chain of at most 15 `__call` values, prepending each called object to the arguments. Metamethod lookup itself is raw. Changes to metatables take effect on later operations.

## Spec 17

The base library is installed globally and contains `_G`, `_VERSION`, `assert`, `collectgarbage`, `dofile`, `error`, `getmetatable`, `ipairs`, `load`, `loadfile`, `next`, `pairs`, `pcall`, `print`, `rawequal`, `rawget`, `rawlen`, `rawset`, `require`, `select`, `setmetatable`, `tonumber`, `tostring`, `type`, `warn`, and `xpcall`.

`assert(v,...)` returns all arguments if `v` is truthy, otherwise errors with the supplied message or `assertion failed!`. `error(object[,level])` raises that exact object, adding source/line to string objects according to level (0 adds none; 1 is caller; higher selects an outer caller); a nil error object, including from `error()` or `error(nil)`, is replaced exactly by the string `<no error object>`. `pcall(f,...)` returns `true` plus all results or `false,errorObject`. `xpcall(f,handler,...)` invokes the handler with the original error and returns `false,handlerResult`; both accept arguments for `f`. Protected calls catch ordinary Lua/runtime errors without terminating the process.

`tonumber(x[,base])` converts numeric values or whitespace/sign-bearing numeric strings; base is 2..36 and accepts case-insensitive digits, returning nil on invalid text. Without base it accepts Lua decimal/hex forms and selects integer where representable. `tostring` honors `__tostring`; its result can be a string or number. A numeric result is accepted and converted to its textual form, so a `__tostring` method returning integer `4` makes `tostring` return the string `4`; a boolean, table, function, or nil result raises `'__tostring' must return a string`. `type()` raises `bad argument #1 to 'type' (value expected)`. Raw functions validate their operand types and bypass metatables; representative exact failures are `bad argument #1 to 'rawlen' (table or string expected, got number)` for `rawlen(42)` and `bad argument #1 to 'rawset' (table expected, got number)` for a numeric first argument.

## Spec 18

`load(chunk[,chunkname[,mode[,env]]])` accepts a source string or a reader function returning successive string pieces. It returns a compiled function, or `nil,errorMessage` on syntax/format failure. Default chunk name is the source string for string input and `=(load)` for readers. An explicit plain chunk name (one beginning with neither `=` nor `@`) is rendered as a decorated string-chunk identifier in diagnostics. For example, `load('return 1 +','custom')` returns an error beginning `[string "custom"]:1:` and ending `unexpected symbol near <eof>`, while `load('return +','mine')` returns `[string "mine"]:1: unexpected symbol near '+'`; neither contains the raw substring `custom:1:` or `mine:1:`. Mode `t`, `b`, or `bt`/`tb` restricts text/binary input. An explicit environment becomes the loaded chunk's first `_ENV` upvalue. Reader termination is nil or empty string.

`loadfile([filename[,mode[,env]]])` behaves similarly for a file (stdin if filename absent), including text/binary mode enforcement and shebang skipping. `dofile([filename])` loads and executes the file/stdin, propagating errors and returning all chunk results. `string.dump(function[,strip])` returns nonempty Lua 5.5 precompiled bytecode; dumped Lua functions can be written in binary mode, reloaded by `load`/`loadfile`, and behave equivalently (with debug data optionally stripped). Malformed, truncated, wrong-version, or mode-forbidden binary chunks fail safely. Bytecode is the native Lua 5.5.1 format rather than a textual serialization.

## Spec 19

`collectgarbage` supports `collect`, `stop`, `restart`, `count`, `step`, `isrunning`, `incremental`, `generational`, and `param`. `count` returns current memory in KiB with a fractional part such that multiplying by 1024 gives the byte count; `step` performs bounded work and reports whether a relevant cycle finished. Stop/restart affect automatic collection. `incremental` and `generational` switch modes and return the previous mode; major work remains incremental. A fresh process starts in generational mode: its first `collectgarbage('generational')` returns `generational`, and a following `collectgarbage('incremental')` also returns `generational`. `param` gets/sets integer parameters `minormul`, `majorminor`, `minormajor`, `pause`, `stepmul`, and `stepsize` and returns the previous effective value. Parameter storage has limited precision, so the new effective value is a deterministic representable approximation rather than necessarily the requested integer. In a fresh process, the respective values are `20`, `50`, `68`, `250`, `200`, and `9600`; setting each to its old value plus one reads back `21`, `50`, `68`, `250`, `200`, and `9600`. Setting `pause` to `100001` succeeds, returns its previous value `250`, and reads back as `99200`; it is not rejected by a 100000 upper-bound check. Full collection runs finalizers and clears eligible weak references. Finalizers run at most once per marked object, in reverse marking order where applicable, and failures become warnings. Both collector modes must preserve all live objects and handle cycles, weak tables, closures, and to-be-closed resources under stress.

## Spec 20

The `coroutine` table provides `create`, `resume`, `yield`, `running`, `status`, `isyieldable`, `wrap`, and `close`. `create(f)` returns an unstarted thread. At an ordinary Lua call site, a non-function passed as its first argument raises `bad argument #1 to 'create' (function expected, got <type>)`. `resume(co,args...)` starts it with args or continues after a yield; on success it returns `true` plus yielded/final values, and on error `false,errorObject` without unwinding the inspectable coroutine stack. At ordinary Lua call sites, passing a non-thread as the first argument to `resume` or `status` raises, respectively, `bad argument #1 to 'resume' (thread expected, got <type>)` or `bad argument #1 to 'status' (thread expected, got <type>)`; as specified in Spec 8, passing the C function directly to another caller can give the argument error its registered qualified name. Values of every type, nils, and long value lists cross both directions unchanged. `yield(values...)` suspends at any Lua-call depth and later returns the next resume arguments; yielding from the main/outside coroutine errors.

Statuses are `suspended` before start/at yield, `running` for self, `normal` while it is active but has resumed another coroutine, and `dead` after return/error/close. `running()` returns current thread plus whether it is main. `isyieldable([co])` defaults to current and is false for main/non-yieldable C contexts. `wrap(f)` returns a resuming function that omits resume's success boolean and raises/then closes on failure. Resuming a dead coroutine errors through `resume`'s false result or propagates through a wrapper.

`close([co])` defaults to current. It closes suspended/dead/current non-main coroutines and pending `<close>` variables, making them dead; non-current close returns true or `false,error`. Calling `coroutine.close()` on the main thread raises exactly `cannot close main thread` (with the Lua call-site source and line when called from a Lua function). Closing a normal coroutine errors. Closing a running non-main coroutine does not return to it; its resumer receives the close result. Coroutine stacks, hooks, locals, errors, nested statuses, and closure state remain isolated.

## Spec 21

The `package` table provides `config`, `cpath`, `loaded`, `loadlib`, `path`, `preload`, `searchers`, and `searchpath`; global `require` uses it. `require(name)` first returns `package.loaded[name]` if truthy. Otherwise it consults searchers in order: `package.preload`, Lua files found via `package.path`, and supported native libraries via `package.cpath` (including the all-in-one loader). It invokes the first loader with module name and loader data, stores a non-nil result in `package.loaded[name]`, or stores true if the loader returned nil and did not set it, and returns the module plus loader data. Subsequent requires are cached.

Path templates are semicolon-separated; each `?` is replaced with the module name after dots become directory separators. `searchpath(name,path[,sep[,rep]])` returns the found filename or nil plus a newline-delimited account of attempted paths. If no searcher succeeds, `require` errors with `module '<name>' not found:` and all search messages. If user code replaces `package.path` with a non-string such as a table, the Lua-file searcher fails with exactly `'package.path' must be a string`. `package.preload` custom loaders and current-directory `.lua` modules work. `package.loadlib(fullPath,symbol)` exposes supported native dynamic loading and returns a function or `nil,error[,where]`; symbol `*` loads globally without returning an initializer.

## Spec 22

The `string` table is also available through the string metatable so `s:method(...)` works. It provides `byte`, `char`, `dump`, `find`, `format`, `gmatch`, `gsub`, `len`, `lower`, `match`, `pack`, `packsize`, `rep`, `reverse`, `sub`, and `upper`. Indices are 1-based bytes; negative indices count from the end and are normalized/clamped conventionally. `len`/`#` count bytes. `sub(s,i[,j])` returns the inclusive slice (empty for an inverted range). `byte(s[,i[,j]])` returns each byte as integers; `char(...)` constructs bytes and rejects values outside 0..255. `reverse` reverses bytes. `lower`/`upper` follow the current C locale. All preserve embedded NUL.

`rep(s,n[,sep])` returns n copies joined by `sep`, returns empty for nonpositive n, and detects size overflow. `find` returns start/end plus captures, or nil; its optional fourth `plain=true` disables patterns. `match` returns captures or the matched substring. `gmatch` iterates non-overlapping matches. `gsub(s,pattern,repl[,n])` returns the replaced string and substitution count; replacement may be a string (`%0` whole match, `%1`.. captures, `%%` percent), table (first capture/match key), or function (captures/match arguments). A numeric function-replacement result is converted to its normal textual number representation and used; for example, replacing each word in `hello world` with the length returned by a function produces `5 5`. A nil or false replacement retains the original text.

`string.char` range failures retain canonical argument attribution: a direct protected call `pcall(string.char,256)` returns false and `bad argument #1 to 'string.char' (value out of range)`.

## Spec 23

Lua patterns are byte-oriented (not regular-expression syntax). Ordinary bytes match themselves; `.` matches any byte; `%a %c %d %g %l %p %s %u %w %x %z` and uppercase complements implement character classes. Bracket classes support listed bytes, ranges, leading `^`, escaped magic characters, and classes. Pattern items accept `*`/`+` greedy repetition, `-` non-greedy repetition, and `?` optional. `^` anchors only at pattern start and `$` only at end. Parentheses capture substrings, `()` captures the current byte position, `%1`..`%9` back-reference captures, `%bxy` matches balanced x/y, and `%f[set]` is a frontier assertion. Magic characters are `^$()%.[]*+-?` and `%` escapes them.

Matching and substitution handle empty matches without infinite loops, anchored substitutions, embedded NUL, large subjects, nested/balanced patterns, and greedy/non-greedy behavior. Malformed classes/captures, invalid capture references, excessive captures, or pattern recursion beyond the supported bound raise descriptive errors rather than crash.

## Spec 24

`string.format(fmt,...)` implements `%%`, `%c`, `%d`, `%i`, `%o`, `%u`, `%x`, `%X`, `%e`, `%E`, `%f`, `%g`, `%G`, `%a`, `%A`, `%q`, `%s`, and `%p`, with legal flags, width, and precision. Uppercase `%F` is not supported: `string.format('%F',math.huge)` raises `invalid conversion '%F' to 'format'`. Integer conversions use 64-bit values and support sign, alternate prefixes, left alignment, spaces, and zero padding. Floating conversions follow C-locale conventions and handle infinities, NaNs, scientific/hexadecimal notation, width, and precision. `%q` emits a valid Lua literal representation, escaping control bytes, quotes, backslashes, newlines, and embedded NUL; a newline in a quoted string is represented by a backslash followed by the actual newline. Thus formatting `line1\nline2` with `%q` produces two output lines, the first ending in `line1\` and the second containing `line2"`, rather than using `\010`. Non-finite numeric values get loadable expressions. `%s` rejects a string containing an embedded NUL even when a precision would truncate at or before it: `pcall(string.format,'%.3s','a\0bc')` returns false and `bad argument #2 to 'string.format' (string contains zeros)`. `%p` gives a pointer-like identity representation for non-nil values, but `string.format("%p",nil)` is exactly `(null)`. Missing/wrong arguments or invalid formats error.

## Spec 25

`string.pack`, `string.unpack`, and `string.packsize` implement Lua binary format strings: whitespace/comments; endian controls `< > =`; maximum alignment `!n`; padding `x` and alignment `Xop`; signed/unsigned integers `b B h H l L j J T i[n] I[n]`; floats `f d n`; fixed strings `cN`; length-prefixed strings `s[n]`; and zero-terminated `z`. They honor native sizes where implied, explicit sizes, alignment, sign extension, overflow checks, and endian order. `pack` concatenates binary fields. `unpack(fmt,s[,pos])` returns decoded fields followed by the next 1-based byte position and accepts negative initial position. `packsize` returns fixed size and errors for variable-length formats. Invalid options, out-of-range values, missing terminators/data, excessive alignment, and integer overflow raise errors.

## Spec 26

The `table` table provides `concat`, `create`, `insert`, `move`, `pack`, `remove`, `sort`, and `unpack`. `create(nseq[,nrec])` returns an empty table with those nonnegative preallocation hints. `concat(list[,sep[,i[,j]]])` joins string/number elements from inclusive i..j (defaults 1..#list), returns empty when i>j, and errors on holes/nonconvertible values. `insert(list,[pos,]value)` defaults to #list+1 and shifts upward. `remove(list[,pos])` defaults to #list, shifts down, returns removed value, and validates bounds. These use normal indexing and length behavior, so appropriate `__index`, `__newindex`, and `__len` effects are visible.

`move(a1,f,e,t[,a2])` copies the inclusive range safely even when source/destination overlap, defaults a2=a1, returns a2, and does nothing for f>e. `pack(...)` preserves nil count in field `n`; `unpack(list[,i[,j]])` returns inclusive values and errors before overflowing the result stack. `sort(list[,comp])` sorts 1..#list in place using `<` or a comparator defining a strict weak order; it supports large lists and all permutations, is not required to be stable, and detects sufficiently inconsistent comparators with `invalid order function for sorting`. Position/argument/result errors are descriptive.

## Spec 27

The `math` table contains IEEE/64-bit constants `pi`, `huge`, `maxinteger=9223372036854775807`, and `mininteger=-9223372036854775808`, and functions `abs`, `acos`, `asin`, `atan`, `ceil`, `cos`, `deg`, `exp`, `floor`, `fmod`, `frexp`, `ldexp`, `log`, `max`, `min`, `modf`, `rad`, `random`, `randomseed`, `sin`, `sqrt`, `tan`, `tointeger`, `type`, and `ult`. Trigonometric arguments/results are radians; two-argument `atan(y,x)` chooses the quadrant; `log(x[,base])`, exponentials, roots, and domain/special values follow binary64/libm behavior. `deg`/`rad` use full-precision pi. `frexp(x)` returns m,e with x=m*2^e (zero gives 0,0); `ldexp(m,e)` computes that product.

`abs`, `fmod`, `min`, and `max` preserve integer results when applicable; two's-complement `abs(mininteger)` remains mininteger. `fmod` truncates the quotient toward zero and its result follows the dividend sign; a direct protected call with an integer zero divisor, `pcall(math.fmod,1,0)`, returns false and `bad argument #2 to 'math.fmod' (zero)`. With `nan = 0/0`, the exact results printed by `math.min(nan,5)`, `math.max(nan,5)`, and `math.min(5,nan)` are, in order, `-nan`, `-nan`, and `5`. `floor`, `ceil`, and integral part of `modf` return integer when representable. `tointeger` returns an exact integer conversion or nil. `type` returns `integer`, `float`, or nil. `ult` compares integer bit patterns unsigned.

`random()` returns a float in [0,1); `random(n)` an integer in [1,n], except n=0 requests the full integer range; `random(m,n)` is inclusive and errors for an empty interval. `randomseed([x[,y]])` seeds deterministically and returns the seeds used; no arguments use fresh system entropy. Resetting identical seeds reproduces the exact sequence. In particular, after `randomseed(12345)`, two `random()` calls, then `random(10)`, then `random(5,15)` yield `0.87460442174732167`, `0.40364110609593384`, `7`, and `15`; reseeding repeats the sequence. After `randomseed(42)`, the first `random(0)` is `-1276290044721465627`.

## Spec 28

The `io` table exposes `stdin`, `stdout`, `stderr`, `close`, `flush`, `input`, `lines`, `open`, `output`, `popen`, `read`, `tmpfile`, `type`, and `write`. The three standard streams are open file handles. `input([file-or-name])` and `output([file-or-name])` get/set defaults. Top-level `read`, `write`, `lines`, `flush`, and `close` operate on defaults. `io.type(x)` returns `file` for an open handle, `closed file` for a closed handle, and nil otherwise. `io.write` returns the output handle on success and accepts multiple strings/numbers; operational failures return nil/error information where defined rather than corrupting state.

`open(name[,mode])` supports `r`, `w`, `a`, optional `+`, and optional `b`; write truncates, append writes at end, plus modes permit both directions, and binary mode preserves bytes/CRLF. A direct protected call with an invalid second argument, `pcall(io.open,name,'invalid')`, returns false and exactly `bad argument #2 to 'io.open' (invalid mode)`; OS open failures return `nil,message,errno`. `tmpfile` returns an open temporary handle. `popen(command[,mode])` connects a handle to a shell command for reading or writing, and closing it returns the process status triple. Several files can be open simultaneously and abandoned files are eventually closed.

## Spec 29

File handles implement `close`, `flush`, `lines`, `read`, `seek`, `setvbuf`, `write`, and a descriptive `tostring`. Calling a retrieved method without its receiver, such as `io.stdin.read()`, raises `bad argument #1 to 'read' (FILE* expected, got no value)`. Double close and operations on a closed file report failure/error without a crash. In particular, `f:write(...)` after closing `f` raises `attempt to use a closed file`; the caught error string includes the Lua call-site source and line, for example `(command line):4: attempt to use a closed file`. `write(...)` returns the handle; `flush` commits buffered data. `setvbuf` accepts `no`, `full`, and `line` plus optional size. `seek([whence[,offset]])` uses `set`, `cur`, or `end` (defaults `cur`,0), returns the absolute byte position, supports seeking past EOF, and reports invalid/negative resulting seeks through normal OS failure behavior.

`read` accepts one or more formats and returns one result each until failure: `n`/`*n` parses a Lua-compatible number (including hex); `a`/`*a` reads the remainder (empty string at EOF); `l`/`*l` reads a line without newline; `L`/`*L` retains newline; integer 0 tests availability; positive integers read up to that many bytes. At EOF a non-`a` read returns nil. `lines([formats...])` iterates reads; `io.lines(filename,...)` opens and automatically closes its file on exhaustion or error, while `file:lines` does not assume ownership. Mixed formats, empty files, no-final-newline lines, large files, Unicode bytes, read/write synchronization, and EOF transitions behave consistently with C stdio.

## Spec 30

The `os` table provides `clock`, `date`, `difftime`, `execute`, `exit`, `getenv`, `remove`, `rename`, `setlocale`, `time`, and `tmpname`. `getenv(name)` returns the exact environment string or nil. `remove` and `rename` perform host filesystem operations and return true on success or `nil,message,errno`; files and directories follow host permissions/semantics. `tmpname` returns a unique usable temporary pathname beginning exactly with `/tmp/lua_`; on this Unix target it creates/reserves that file before returning. `clock` returns numeric process CPU seconds and is nondecreasing for performed work.

`execute([command])` with no command reports shell availability. With a command it uses the host shell, allowing pipes, redirections, and `&&`; child output remains attached to the executable's streams. It returns `true,'exit',0` for success, `nil,'exit',code` for a normal nonzero exit (127 for an unavailable shell command in the target environment), and the appropriate nil/signal status for signal termination.

`exit([code[,close]])` immediately terminates: omitted or true means status 0, false means status 1, and an integer is used as process status. Statements after it do not run. If `close` is true, close the Lua state first, running pending `<close>` and finalization behavior; otherwise immediate process termination need not finalize Lua resources.

## Spec 31

`time()` returns current Unix-style local calendar time as a number. `time(table)` requires `year`, `month`, and `day`; defaults `hour=12`, `min=0`, `sec=0`, accepts optional `isdst`, normalizes calendar overflow through host `mktime`, updates normalized fields, and returns timestamp or nil on unrepresentable time. `difftime(t2,t1)` always returns the Lua float subtype, even when both inputs and their difference are integral. Thus differences of 50, -50, and zero print as `50.0`, `-50.0`, and `0.0`, respectively.

`date([format[,time]])` defaults to `%c` and current time. A leading `!` selects UTC; otherwise use local time. `*t` returns a table containing integer `year,month,day,hour,min,sec,wday,yday` and boolean `isdst`, with Sunday=1 and Jan 1 yday=1. Other formats use host `strftime` behavior and include `%a %A %b %B %c %d %H %I %j %m %M %p %S %U %w %W %x %X %y %Y %z %%`; unsupported conversions error. Under the test's C locale and UTC setting, timestamp 0 is 1970-01-01 00:00:00, Thursday (`wday=5`, `yday=1`).

`setlocale([locale[,category]])` queries/sets host locale. Categories are `all`, `collate`, `ctype`, `monetary`, `numeric`, and `time`; nil queries; unavailable locale returns nil. The C locale is supported and returns `C` on query. Numeric parsing/formatting required by Lua remains correct across locale changes.

## Spec 32

The `utf8` table provides `char`, `charpattern`, `codes`, `codepoint`, `len`, and Lua-5.5 `offset`. Positions are 1-based byte indices and negative positions count from the end. Strict decoding accepts only well-formed, shortest-form UTF-8 scalar values through U+10FFFF and rejects surrogates. Where a `lax` parameter exists, it permits encoded values through 0x7FFFFFFF including surrogates, but still rejects malformed/overlong encodings.

`char(codepoints...)` encodes and concatenates integer values from 0 through `0x7FFFFFFF` using Lua's extended UTF-8 encoding, including zero, surrogates, and values above U+10FFFF. Thus `utf8.char(0x110000)` returns the four bytes `F4 90 80 80`, and `utf8.char(0x7FFFFFFF)` returns six bytes; a direct protected call for `-1` or `0x80000000` returns false and `bad argument #1 to 'utf8.char' (value out of range)`. `codes(s[,lax])` iterates byte-position/codepoint pairs and validates incrementally: it yields every valid prefix pair before encountering a later malformed sequence, then that iterator call raises the exact error object `invalid UTF-8 code`. For example, iterating `"A\255"` first yields byte position 1 and code point 65, and the next iterator call errors. An invalid first byte errors before yielding anything. `codepoint(s[,i[,j[,lax]]])` returns code points whose encodings begin in the inclusive byte range and errors on invalid sequences/bounds or excessive result count. `len(s[,i[,j[,lax]]])` counts characters; invalid input returns `nil,firstBadByte` rather than raising. `charpattern` is the byte pattern `[\0-\x7F\xC2-\xFD][\x80-\xBF]*`.

`offset(s,n[,i])` returns the first and last byte of the selected character. Positive n counts from i (default 1), negative n backward (default #s+1), and n=0 finds the character containing byte i. The one-past-end sentinel has both bounds equal to `#s+1`: for the eight-byte string `A€🙂`, `utf8.offset(s,4)` returns `9,9`. A character not present returns only nil. Invalid bounds/starting in a continuation byte where disallowed raises an error.

## Spec 33

The `debug` table provides at least `debug`, `gethook`, `getinfo`, `getlocal`, `getmetatable`, `getregistry`, `getupvalue`, `getuservalue`, `sethook`, `setlocal`, `setmetatable`, `setupvalue`, `setuservalue`, `traceback`, `upvalueid`, and `upvaluejoin`. Optional first thread arguments inspect a suspended coroutine instead of current thread.

`getinfo(function-or-level[,what])` returns nil for an invalid level and otherwise a table selected by letters: `S` supplies `source,short_src,linedefined,lastlinedefined,what`; `l` currentline; `u` `nups,nparams,isvararg`; `n` `name,namewhat`; `t` `istailcall`; `r` transfer fields; `L` valid-lines table; and `f` the function. C functions report `[C]`, `what='C'`, line fields -1, zero fixed params/upvalues as applicable. Invalid selector letters error. Stack levels, tail calls, main chunks, and coroutine stacks are identified correctly.

`getlocal([thread,]level,index)` returns local name/value, nil for invalid index, and supports negative indices for varargs; when passed a function instead of a level it returns parameter/local names without values. `setlocal` changes and returns the name or nil for an invalid local index at a valid level, but an invalid stack level raises `bad argument #1 to 'debug.setlocal' (level out of range)`. `getupvalue(f,n)` returns name/value for a valid index and returns no values for an invalid index. `setupvalue` changes a valid upvalue and returns its name; for an invalid index it likewise returns no values. Thus `select('#', debug.getupvalue(f,invalidIndex))` and `select('#', debug.setupvalue(f,invalidIndex,value))` both return 0, while passing the zero-result `getupvalue` call directly as the only argument to `tostring` raises `bad argument #1 to 'tostring' (value expected)`. Upvalue names, nested scope ordering, differing value types, and closure isolation are preserved. For a valid Lua upvalue, `upvalueid` returns a value whose Lua type is exactly `userdata`; it is a stable identity token, and closures sharing an upvalue have equal tokens. An out-of-range upvalue index passed to `upvalueid` returns nil rather than raising or inventing a token. `upvaluejoin(f1,n1,f2,n2)` makes Lua closures share storage and rejects unsuitable C functions/indices.

## Spec 34

`debug.traceback([thread,][message[,level]])` returns message plus a formatted `stack traceback:` without raising. Nil message acts as an empty message; a non-string/non-number message is returned unchanged. Level controls omitted frames and level 0 includes the current call. Deep traces may abbreviate middle frames but retain useful top/bottom frames and source/line/function information.

`sethook([thread,]hook,mask[,count])` installs per-thread debug hooks; mask characters are `c` (call), `r` (return/tail return), and `l` (line), and positive count generates `count` events. Nil hook removes it. With a hook installed, `gethook([thread])` returns hook, normalized mask, and count in that order. When no hook is installed it returns exactly one value, nil: `select('#',debug.gethook())` is `1`, and variables receiving possible mask and count results are also nil. Hooks receive event name and line where applicable, do not recursively trigger themselves, can be combined/removed, and are isolated between main thread and coroutines. Invalid masks/types error. Registry/metatable functions expose actual runtime objects: in particular, `debug.getregistry()._LOADED` is the same table as `package.loaded`. Debug metatable setters bypass `__metatable`. Uservalue access on non-userdata returns nil (and a false/absence indication as applicable), while setting it on non-userdata errors.

## Spec 35

The interpreter must correctly execute comprehensive Lua programs combining all prior features: lexical scope/upvalues, tail calls and ordinary recursion, varargs and multiple returns, every operator and metamethod, constructors and iteration, goto with close semantics, coroutines, protected errors, binary chunks, pattern matching, sort, pack/unpack, UTF-8 validation, filesystem/process/time functions, debug inspection/hooks, weak tables/finalizers, and incremental/generational collection. Observable assertions in such programs must hold regardless of optimization. Resource pressure may yield a catchable/descriptive memory error but must not corrupt later state. Infinite ordinary recursion must terminate with a stack-overflow error. Large valid generated programs and tables (including thousands of elements and many constants/instructions) must run when memory is available.

Platform-dependent operations are evaluated on a Unix-like host with a shell, standard C library, 64-bit integers, binary64 floats, and normally the C locale/UTC test environment. Results may vary only where the relevant specs explicitly delegate to the host (OS error wording beyond required substrings, filesystem permissions, CPU time, current date/time, locale availability, non-nil pointer addresses, NaN signs not fixed for a particular operation above, and unstable ordering of unrelated table keys). This variability does not apply to `%p` for nil or to the `math.min`/`math.max` NaN cases specified above. All deterministic language, CLI, and library behavior—including tabs/newlines, status codes, version text, fixed-seed PRNG output, diagnostics, and binary-safe string/file operations—must match the requirements above.
