# Executable behavioral specification

The required artifact is a POSIX executable file named exactly `executable`. It is a standalone LuaJIT-compatible command-line interpreter targeting the host Linux/x86-64 environment. Unless a requirement below deliberately permits variation (for example, addresses and current timestamps), behavior is observable through process arguments, environment, stdin, stdout, stderr, exit status, files created by the program, and Lua code executed by it.

## Spec 1

The executable shall implement the Lua 5.1 language and runtime model together with the LuaJIT 2.1 extensions described in the later sections. Source input is an arbitrary byte string; ordinary source is parsed as Lua, while LuaJIT bytecode produced by this executable is auto-detected and loaded. Empty, whitespace-only, and comment-only chunks are successful no-ops. A script whose first line begins with `#!` ignores that first line.

All chunks in one invocation share one Lua state and global environment. The runtime must handle programs with large strings and tables, sparse and deeply nested tables, many closures, deep but reasonable recursion, large output, and loops ranging into hundreds of thousands of iterations within a five-second test timeout. Whether code is interpreted or machine-compiled must not change its results.

## Spec 2

`-h` and `--help` are equivalent, take precedence over later arguments, write nothing to stdout, write the following text to stderr with a final newline, and exit 1. In the first line, `PROGRAM` is the actual spelling/path used to invoke the executable (normally `/workspace/executable` or `./executable`):

```text
usage: PROGRAM [options]... [script [args]...].
Available options are:
  -e chunk  Execute string 'chunk'.
  -l name   Require library 'name'.
  -b ...    Save or list bytecode.
  -j cmd    Perform LuaJIT control command.
  -O[opt]   Control LuaJIT optimizations.
  -i        Enter interactive mode after executing 'script'.
  -v        Show version information.
  -E        Ignore environment variables.
  --        Stop handling options.
  -         Execute stdin and stop handling options.
```

There are no ANSI escapes. An unknown option, or a missing operand for `-e`, `-l`, or `-j`, likewise prints this usage to stderr and exits 1. `-i` and `-v` reject attached trailing text such as `-itail`. In contrast, `-E` accepts and ignores attached trailing text: with stdin at EOF, `-Etail` exits 0 with empty stdout and stderr, just as `-E` does. Once `--` or the stdin marker `-` is encountered, later strings are never interpreted as options.

## Spec 3

`-v` writes a single newline-terminated version/copyright line to stdout, writes nothing to stderr, and normally exits 0. It starts with `LuaJIT 2.1.`, contains a further decimal build/release component, `Copyright`, a four-digit 20xx year, `Mike Pall`, and `https://luajit.org`. Unlike help, version display does not terminate option processing: `-v -e 'print("x")'` prints the version before `x`.

`-e chunk` and the joined form `-echunk` compile and execute `chunk` immediately, in command-line order. Multiple chunks preserve globals but not lexical locals. Chunk return values are ignored and not printed. `-l name` and `-lname` perform `require(name)` at that point in the same state. Options and a subsequent script therefore execute strictly left-to-right, with all preprocessing chunks/library loads before the script. Missing modules are fatal.

## Spec 4

The first non-option operand is the script name; every later operand is a script argument, even if it begins with `-`. A lone `-` in the option position selects stdin as the script and stops option parsing. `--` stops option parsing and makes its following operand the script name. Thus `-- -h` attempts to open a file literally named `-h`, and `- -v` executes stdin with `-v` as an argument. A missing file produces a nonzero status and a stderr message containing `cannot open NAME` plus the host error such as `No such file or directory`; prior `-e` output remains emitted.

Before preprocessing chunks run, create global table `arg`. For a file script, `arg[0]` is the script operand and `arg[1]...` are following operands. For stdin, following operands begin at `arg[1]`. Earlier raw command-line operands occupy consecutive negative indices exactly as in the Lua standalone convention: the item immediately before the script is `arg[-1]`, the prior item `arg[-2]`, and so on; this includes `-e`, its chunk text, `--`, and the invoked executable name as applicable. In an invocation `-e x=1 -e y=2 script.lua first second`, the observable tail is `arg[-2] == "-e"`, `arg[-1] == "y=2"`, `arg[0] == "script.lua"`, `arg[1] == "first"`, and `arg[2] == "second"`. The table also exists for invocations consisting only of `-e` chunks.

## Spec 5

With no explicit chunk or script, read and execute stdin. If stdin is at EOF, exit successfully without usage output. `-i` selects interactive mode but writes its newline-terminated LuaJIT version/copyright banner to stdout **before** executing any requested `-e` chunks or script. Only after those chunks finish does it write the JIT status line containing `JIT:` and `ON` or `OFF`, display a `> ` prompt, and begin reading interactive input. Thus `-i -e 'print("chunk")'` with stdin at EOF orders the banner, `chunk`, the JIT status line, and the prompt; `-i -e 'os.exit()'` exits 0 after the banner and never reaches the status line or prompt. Interactive input executes statements, supports expression entry in the usual Lua REPL manner, and shares state with earlier chunks. EOF exits 0. Without `-i`, piped stdin is batch input and prints no banner or prompt.

`print` writes its converted arguments separated by tab bytes and then newline. `io.write` does not add separators or a newline. stdout and stderr remain strictly separate, support arbitrary binary bytes including NUL, and preserve UTF-8 bytes unchanged. Explicit flushes make pending output observable.

## Spec 6

Unless `-E` has appeared, process `LUA_INIT` before command-line chunks: a value beginning with `@` names a source file to run, otherwise the value itself is a Lua chunk. Its side effects/output precede all option chunks. Failure to open an `@file`, syntax failure, or runtime failure is fatal. `-E` suppresses `LUA_INIT` completely and marks the Lua state as ignoring Lua-related environment configuration.

Lua code reads process variables through `os.getenv`; absent names return `nil`, present empty variables return `""`. `LUA_PATH` controls Lua module templates and `LUA_CPATH` controls native-module templates. A double semicolon in either expands the implementation defaults. Lua cannot directly mutate its parent process environment merely by assigning Lua globals; any suite-provided environment values must remain accessible.

## Spec 7

Source supports Lua tokens and grammar: identifiers; decimal, hexadecimal, and binary numerals, decimal exponents, and hexadecimal fractional/exponent forms; quoted strings with standard escapes (`\a\b\f\n\r\t\v`, escaped slash/quotes, decimal byte escapes and `\xHH`) and `\u{HEX}` Unicode escapes encoded as UTF-8 (for example, `\u{1F600}` produces bytes `f0 9f 98 80`); long bracket strings/comments with arbitrary `=` nesting levels; line and block comments; and LuaJIT integer suffixes `LL`/`ULL` (case-insensitive) plus imaginary `i`/`I` C-data numeric literals. Strings are byte sequences and may contain NUL.

Statements include assignment and local declaration (including multiple assignment), calls, `do`, `if/elseif/else`, `while`, `repeat/until`, numeric and generic `for`, `break`, `return`, function definitions/method syntax, and LuaJIT's `goto`/label extension. Expressions include literals, varargs, anonymous functions, table constructors (list, record, and computed fields, with trailing separators), indexing, calls, method calls, concatenation, length, arithmetic, comparison, and boolean operators. Precedence and associativity follow Lua: exponentiation and concatenation associate right; exponentiation binds tighter than unary minus; then multiplicative, additive, concatenation, comparison, `and`, and `or`. Malformed tokens, strings, numerals, tables, blocks, captures, or excess locals produce compilation errors rather than crashes.

## Spec 8

Values comprise `nil`, booleans, double-precision numbers, byte strings, tables, functions, userdata, coroutine threads, and FFI cdata. Only `nil` and `false` are false. Arithmetic coerces numeric strings where Lua 5.1 permits; concatenation coerces strings and numbers; invalid operands use LuaJIT's operation-specific type errors. In particular, `local x=nil; print(x+5)` fails with `attempt to perform arithmetic on local 'x' (a nil value)`, `local x=nil; print(x..'string')` fails with `attempt to concatenate local 'x' (a nil value)`, and multiplying a local string reports `attempt to perform arithmetic on local 'x' (a string value)`. `/ 0` follows floating-point behavior (`inf`, `-inf`, or `nan` as appropriate), while invalid modulo operations raise or produce the LuaJIT-defined numeric result. Equality works across primitive values and by identity for reference values unless a shared `__eq` applies; ordering numbers/strings works directly and otherwise uses metamethods or errors.

Functions are first-class, variadic, recursive, and support tail calls. Arguments and return values follow Lua's adjustment rules: the final call/vararg in a list can expand to multiple values; other positions collapse to one; missing values become nil; excess arguments are ignored unless captured. Closures capture live lexical cells, so sibling closures share the same upvalue and loop/block upvalues are closed at the correct time. Locals shadow globals and remain chunk-local. Each function has a mutable Lua 5.1 environment used for global lookup.

## Spec 9

Tables support arbitrary non-nil keys except NaN, mixed array/hash contents, growth/rehashing, and identity. `#t` implements the Lua sequence boundary behavior; `next` traverses every present key without promising hash order, `pairs` uses it, and `ipairs` yields integer keys starting at 1 and stops at the first nil. Invalid continuation keys and invalid table arguments raise errors.

Normal access/assignment invokes `__index` and `__newindex` (each may be a function or delegation table); `rawget`, `rawset`, and `rawequal` bypass metamethods. Implement `__add`, `__sub`, `__mul`, `__div`, `__mod`, `__pow`, `__unm`, `__concat`, `__eq`, `__lt`, `__le`, `__call`, `__tostring`, `__mode`, and finalizer behavior on eligible objects. For an ordinary table, `#` uses its raw sequence boundary and ignores a table `__len`; likewise base `pairs`/`ipairs` may use their raw Lua 5.1 iteration and ignore table `__pairs`/`__ipairs`. (`__len` on userdata/cdata and `__pairs`/`__ipairs` on cdata are supported through their registered metatypes.) Equality metamethods require compatible/shared metamethods; `<=` uses `__le`, or the negation of reversed `__lt` when no `__le` exists. Metamethod errors propagate. `__metatable` hides/protects the real metatable; `setmetatable` rejects changes to protected tables. Weak-key, weak-value, and fully weak tables release unreachable entries after collection.

## Spec 10

Provide the standard global/base facilities `_G`, `_VERSION`, `assert`, `collectgarbage`, `dofile`, `error`, `gcinfo`, `getfenv`, `getmetatable`, `ipairs`, `load`, `loadfile`, `loadstring`, `module`, `newproxy`, `next`, `pairs`, `pcall`, `print`, `rawequal`, `rawget`, `rawset`, `select`, `setfenv`, `setmetatable`, `tonumber`, `tostring`, `type`, and `unpack`.

`type` returns exactly the lower-case type labels, including `thread`, `userdata`, and `cdata`. `tonumber` accepts whitespace/signs, decimal, binary, exponent, hex, and hexadecimal-float syntax; with an explicit integral base 2 through 36 it parses valid digits and otherwise returns nil, while invalid bases raise. `tostring` uses `__tostring`, prints integers without `.0`, preserves LuaJIT's useful floating precision, renders booleans/nil literally, and gives a type plus identity/address form for tables, functions, threads, userdata, and cdata. Its numeric rendering includes `tostring(3.14159265359) == "3.14159265359"`, `tostring(1e20) == "1e+20"`, and `tostring(1e-10) == "1e-10"`; the fixed/exponent transition includes `1e13` as `10000000000000`, `1e14` as `1e+14`, `1e-4` as `0.0001`, and `1e-5` as `1e-05`. `print` resolves and calls the current global `tostring` for each value. `assert` returns all its arguments when the first is truthy and otherwise raises its optional message (default `assertion failed!`). `error(message, level)` accepts non-string messages and controls location decoration; level zero adds none.

`select("#",...)` returns the exact vararg count including nil values. A positive numeric index returns that suffix (an index beyond the count returns no values); a negative index counts from the end; zero or a too-negative index raises `index out of range`. `unpack(t[,i[,j]])` returns every indexed value in the inclusive range, preserving nil holes, and rejects ranges too large for the stack with `too many results to unpack`. `rawset` returns its table; extra arguments to base functions are ignored where their fixed arity permits.

## Spec 11

`pcall(f, ...)` invokes with arguments and returns `true` plus all results, or `false` plus the caught error object. `xpcall(f, handler, ...)` does the same but transforms an error through `handler`; handler errors and nested protected calls remain contained according to Lua semantics. Unprotected runtime errors exit nonzero, write no fabricated stdout, and write a useful stderr diagnostic followed by `stack traceback:` with source/chunk names, line numbers, and call frames. Command-line source is named `(command line)`; file errors identify the file and line. Syntax errors similarly include location and a nearby token. Stack overflow is detected and reported instead of hanging or corrupting memory.

`load` accepts a string or a reader function called repeatedly until it returns nil; string pieces are concatenated. A numeric reader result is accepted and converted to its string representation: a reader returning `"return "`, then `123`, then nil loads a function which returns the number 123. Consequently, a reader that always returns `123` never supplies the terminating nil and `load` continues calling it rather than returning. A non-nil reader result that is neither a string nor a number, such as a boolean or table, makes `load` return `nil` plus the message `reader function must return a string`; it does not throw. `loadstring` is its string-compatible form. Compilation failure likewise returns `nil, message` without throwing. With no explicit chunk name, a string source is identified in errors as `[string "SOURCE"]` (using LuaJIT's truncation rules for long sources): for example, `load("local x = ")` returns the message `[string "local x = "]:1: unexpected symbol near '<eof>'`, and a function from `loadstring("error('loaded error')")` reports `[string "error('loaded error')"]:1: loaded error` when called. The parser uses LuaJIT grammar names, so `loadstring("function ()")` returns a message containing `'<name>' expected near '('`. A supplied chunk name is used in diagnostics.

The accepted signature is `load(source[, chunkname[, mode[, env]]])`. When the fourth argument is supplied, it becomes the loaded function's environment: with `env={x=10}` the result of `load("return x * 2", "chunk", "t", env)()` is 20. `loadfile` returns a function or `nil, message`; `dofile` throws on failure and returns all chunk results on success. Text and this executable's dumped bytecode are loadable, including binary chunks from `string.dump`; mode `t` accepts only text, `b` only bytecode, and `bt`/`tb` either. Function environments are accessible/changeable by function or valid stack level. `setfenv(-5,{})` is a programmer error whose message contains `bad argument #1 to 'setfenv' (invalid level)`; attempts to change a non-settable C-function environment also error. `newproxy(true)` creates userdata with a new metatable, passing an existing proxy shares its metatable, and false/no argument creates an unshared proxy.

## Spec 12

The `coroutine` library provides `create`, `resume`, `yield`, `status`, `running`, `wrap`, and `isyieldable`. Created coroutines start `suspended`; while executing they are `running`, after yielding they return to `suspended`, and after return/error they are `dead`. `resume` transfers its supplied values into initial parameters or the suspended `yield`, and returns `true` plus yielded/final values; errors return `false` plus the error rather than terminating the process. Resuming a running/dead value and passing non-threads errors appropriately. `wrap` exposes the same transfers through a function but propagates coroutine errors. Yield outside a yieldable coroutine errors. `isyieldable()` is false on the main thread and true while an ordinary resumable coroutine is running.

`collectgarbage` supports `collect`, `stop`, `restart`, `count`, `step`, `setpause`, `setstepmul`, and `isrunning`. Count/gcinfo report numeric memory use in KiB; `isrunning` returns a boolean, and tuning modes return their prior numeric setting. Finalizers run safely, cyclic structures are reclaimed, and collection honors weak tables and FFI/buffer finalizers.

## Spec 13

The `string` library supplies byte-oriented `len`, `byte`, `char`, `sub`, `rep` (including optional separator), `reverse`, `lower`, `upper`, `find`, `match`, `gmatch`, `gsub`, `format`, and `dump`. Strings share a metatable whose `__index` is the string library, enabling method syntax such as `s:sub(2)`. Indices are one-based; negative indices count back from the end; ranges clamp to the string and inverted/out-of-range ranges are empty. `byte(s,i,j)` returns each byte in an ordinary-sized range, or no values when empty, but limits the number of return values: `string.byte(string.rep("a",10000),1,10000)` raises the catchable error `string slice too long`. `char` accepts byte values and rejects invalid ones; an unprotected `string.char(256)` exits 1 and its stderr diagnostic contains exactly `bad argument #1 to 'char' (invalid value)` before the traceback. Case conversion affects ASCII letters and leaves other bytes intact. Negative/zero repetition yields the empty string. `dump(function[,mode])` yields loadable bytecode; `true` or a mode string containing `s` strips debug information, and a string containing `d` requests byte-for-byte deterministic output for identical functions.

Pattern matching implements Lua patterns, not regular expressions: `.`, anchors `^`/`$`, classes `%a %c %d %g %l %p %s %u %w %x %z` and uppercase complements, bracket ranges/negation/escapes, greedy `*`/`+`, optional `?`, non-greedy `-`, captures and nested captures, position capture `()`, numbered backreferences, balanced `%bxy`, and frontier `%f[set]`. `find` supports start index and plain-search mode. Iterators advance after empty matches. Malformed patterns/captures raise descriptive errors and pathological patterns fail as “too complex” instead of hanging. In particular, protected `string.match` calls report `invalid pattern capture` for pattern `)`, `malformed pattern (missing ']')` for pattern `[`, and `invalid capture index` for the `%5` backreference when no fifth capture exists.

## Spec 14

`gsub` returns the replaced string and replacement count, observes a maximum count, and accepts string/number, function, or table replacements. `%0` is the whole match, `%1` etc. select captures, `%%` is literal `%`, and `%` before a non-digit follows LuaJIT replacement rules. A function/table result of nil or false preserves the original match; a returned string or number replaces it; unsupported returned/replacement types error. Empty-pattern replacement makes progress.

`string.format` implements `%%`, `%s`, `%q`, `%c`, signed/unsigned decimal, octal, lower/upper integer hex, fixed, exponent, general floating, and lower/upper hexadecimal-floating formats `%a` and `%A`, with width, precision, left justification, sign/space, alternate form, and zero padding. For example, formatting 3.14 with `%a` and `%A` produces `0x1.91eb851eb851fp+1` and `0X1.91EB851EB851FP+1`. Numeric conversion and special values use LuaJIT-compatible text (`inf`, `-inf`, `nan`, and signed zero where applicable). It validates argument counts/types and format syntax.

## Spec 15

The `table` library provides `concat`, `insert`, `remove`, `sort`, `maxn`, `getn`, `foreach`, `foreachi`, and `move`. Also provide loadable modules `table.new` and `table.clear`: `require("table.new")(array_capacity,hash_capacity)` returns an empty ordinary table with capacity reserved. Negative capacities are accepted rather than rejected: `require("table.new")(-1,0)` returns an empty ordinary table. `require("table.clear")(t)` deletes every array and hash entry in place and rejects a non-table argument. Compatibility functions `pack` and `table.unpack` may also be exposed and, if present, must work normally. `insert` appends or inserts at a valid one-based position while shifting later values. `remove` defaults to the last sequence item, shifts following values, and returns the removed value (nil for an empty/out-of-range removal as appropriate). `concat` defaults to an empty separator and supports explicit start/end; it accepts strings and numbers, but an included nil or other unsupported value errors. Specifically, `table.concat({1,2,3}, ",", 1, 4)` exits 1 with a diagnostic containing `invalid value (nil) at index 4 in table for 'concat'`. `sort` is in-place, accepts an optional strict comparator, handles duplicates/empty/large arrays, and propagates comparator errors.

`maxn` returns the greatest numeric key or zero for none; `getn` reflects the executable's chosen sequence boundary. That boundary is fixed for the following sparse cases. For `{10,20,nil,40}`, `table.getn` returns 4. Inserting nil at position 2 into `{10,20,30}` makes indexed reads yield `1=10, 2=nil, 3=20, 4=30`, and `#t` is 4. Removing position 2 from `{10,20,nil,40,50}` returns 20 and shifts the later populated entries to produce `1=10, 3=40, 4=50`. `foreachi` visits consecutive integer entries until nil and `foreach` visits all entries; either stops and returns the callback's first non-nil result. `move(a,f,e,t[,dest])` copies an inclusive range safely even when source/destination overlap and returns the destination. Auxiliary-library argument diagnostics use the canonical prefix: for example, `table.insert("not a table",1)` fails with `bad argument #1 to 'insert' (table expected, got string)`.

## Spec 16

The `math` library exposes constants `pi` and positive infinity `huge`, and functions `abs`, `floor`, `ceil`, `sqrt`, `min`, `max`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `sinh`, `cosh`, `tanh`, `exp`, `log` (optional base argument), `log10`, `pow`, `fmod`, `deg`, `rad`, `frexp`, `ldexp`, `modf`, `random`, and `randomseed`. They use host double precision and conventional libm results: invalid real domains produce NaN, overflow infinity, underflow zero; floor/ceil preserve infinities/NaN; `frexp(x)` returns fraction and exponent, `modf` integral and fractional parts with signs, and `fmod` has dividend-sign semantics.

Arguments accept Lua numeric coercions and otherwise raise indexed type errors; `min`/`max` require at least one argument. Their reduction is equivalent to starting with the last argument and scanning earlier arguments right-to-left, replacing the candidate only on a true `<` or `>` comparison. Consequently an earlier NaN is ignored but a final NaN remains NaN: `min(5,0/0,3)` is 3, while `min(3,1,0/0)` is NaN. Random with no arguments is in `[0,1)`, with `u` is an integer in `[1,u]`, and with `l,u` is in that inclusive range. Re-seeding with the same explicit seed reproduces LuaJIT's sequence; specifically, after `math.randomseed(12345)`, the first no-argument `math.random()` renders as `0.35797374661876`. A no-argument seed, if supported, is secure/nonconstant.

## Spec 17

The `io` library provides `stdin`, `stdout`, `stderr`, `open`, `close`, `input`, `output`, `read`, `write`, `flush`, `lines`, `type`, `tmpfile`, and `popen`, and file methods `close`, `flush`, `lines`, `read`, `seek`, `setvbuf`, and `write`. Open supports `r`, `w`, `a`, their `+` variants, and optional `b`; `w` truncates and `a` appends. Successful writes are a packaged-runtime difference from the usual Lua 5.1 chaining convention: both `file:write(...)` and `io.write(...)` return the boolean `true`, not the file handle or current output handle. Other successful operations return the file/true as appropriate; ordinary filesystem failures return `nil, message[,errno]`. An invalid `io.open` mode is also an operational failure tuple rather than a thrown argument error: `print(io.open("test.txt","invalid_mode"))` prints `nil\ttest.txt: Invalid argument\t22` and exits 0. Invalid argument types still error. Reading, writing, flushing, seeking, or iterating a closed file raises a message containing `attempt to use a closed file`. Closing a standard stream returns `nil, "cannot close standard file"` rather than closing it.

Reads support `*l` (line without newline), `*L` (with newline), `*a` (all remaining bytes), `*n` (number), and nonnegative byte counts, including zero. Multiple formats return multiple values in order; EOF returns nil when no data can be produced. An unsupported format is a programmer error with the canonical message `bad argument #1 to 'read' (invalid format)`. Files preserve binary/NUL data. `lines` returns an iterator, accepts read formats, automatically closes a file it opened at EOF, and does not close stdin. `seek` supports `set`, `cur`, and `end` with default current/zero and returns the absolute position. Buffer modes are `no`, `full`, and `line`. `input`/`output` accept filenames or handles and return/set defaults. `popen` supports read and write pipes and reports command closure status. Temporary files are usable and are cleaned up normally. `tostring` of an open file handle has the form `file (0xADDRESS)`; after closing that same handle it is exactly `file (closed)`.

## Spec 18

The `os` library provides `clock`, `time`, `difftime`, `date`, `getenv`, `execute`, `tmpname`, `remove`, `rename`, `setlocale`, and `exit`. `clock` is nonnegative CPU time and advances under computation. `time()` returns an epoch timestamp; with a table it requires year/month/day, accepts hour/min/sec/isdst, defaults the omitted hour to 12 and minute/second to 0, normalizes through the host calendar, and errors when any required field is absent. `difftime(a,b)` returns `a-b`.

`date([format[,time]])` supports normal `strftime` conversions, literal text and `%%`; a leading `!` uses UTC; `*t` returns a table containing year, month, day, hour, min, sec, wday, yday, and isdst. Empty format returns empty. `execute` invokes a shell command, permits a no-argument availability query, and returns LuaJIT/POSIX status results. `tmpname` returns distinct usable paths. `remove` and `rename` affect host files and return success or `nil,error[,errno]`. Locale setting/query supports categories `all` and `numeric`; in the supplied environment `os.setlocale(nil,"numeric")` returns the string `C`.

`os.exit()`/`os.exit(true)` exit 0, `os.exit(false)` exits nonzero, and a numeric argument becomes the process status (e.g. 3 or 5). Output already written remains visible.

## Spec 19

The package system exposes `package.loaded`, `preload`, `path`, `cpath`, `loaders` (also `searchers` if offered), `config`, `loadlib`, `searchpath`, and `seeall`, plus global `require` and `module`. On Linux, `package.config` is five newline-separated settings beginning with directory separator `/`, path separator `;`, substitution marker `?`, executable-directory marker `!`, and ignore marker `-`. With no `LUA_PATH` override, `package.path` is exactly `./?.lua;/usr/local/share/luajit-2.1/?.lua;/usr/local/share/lua/5.1/?.lua;/usr/local/share/lua/5.1/?/init.lua`.

`require(name)` first returns any truthy `package.loaded[name]`, detects loops/previous failed loads, then invokes loaders in order: preload, Lua file, C library, all-in-one C library. Lua templates are tried left-to-right, replace `?` with the module name after converting dots to `/`, and accumulate `no file ...` diagnostics. A loader receives the module name. Its first result is cached; nil/no result becomes `true`; false is a legitimate module result but does not provide a truthy cache. Only the first of multiple returns is used. Modules execute once while cached, preserve global side effects, are case-sensitive, and reload after their cache entry is cleared. Searchers may be user-added and may return a loader or diagnostic string. A numeric searcher result is stringified and accumulated too: if a prepended searcher returns `12345`, failed `require("test")` begins its detail with `module 'test' not found:12345` before the ordinary loader diagnostics. Other invalid searcher results are handled according to LuaJIT behavior. Missing, syntax-failing, runtime-failing, and circular modules raise detailed errors and tracebacks.

`package.searchpath(name,path[,sep[,rep]])` performs the same template search and returns a found path or `nil` plus accumulated error; empty templates/separators and multiple `?` substitutions work. `module(name,...)` creates/reuses a named module table and environment, and `package.seeall` gives it `_G` fallback. `-l` uses this exact machinery and preserves command-line order.

## Spec 20

The `debug` library provides `getinfo`, `getlocal`, `setlocal`, `getupvalue`, `setupvalue`, `upvalueid`, `upvaluejoin`, `traceback`, `getmetatable`, `setmetatable`, `getregistry`, `getfenv`, `setfenv`, `sethook`, and `gethook`. Stack levels and function arguments are accepted where appropriate. `getinfo` option letters populate the standard source (`S`), line (`l`), name (`n`), upvalue/parameter (`u`), and function (`f`) fields and distinguish Lua from C functions; invalid levels return nil and invalid option letters error. Local/upvalue getters return name,value, while setters mutate the live cell and return its name. A valid frame/function with an out-of-range local or ordinary getter upvalue slot returns nil. By contrast, a nonexistent stack frame passed to `debug.getlocal` or `debug.setlocal` throws an argument error containing `level out of range`, and an out-of-range index passed to `debug.upvalueid` throws an argument error containing `index out of range`. Varargs and cross-frame locals are introspectable where LuaJIT exposes them.

Hooks support masks for call, return/tail-return, and line plus an instruction-count interval. The callback receives the event and line where relevant; `gethook` reports the installed hook/mask/count, and setting nil removes it. `traceback([thread,][message[,level]])` respects level. With a non-nil message it returns a string containing that message and `stack traceback:` frames; when the message argument is nil, `debug.traceback(nil,1)` returns nil rather than a traceback string. Registry and raw metatable access return actual internal objects; debug metatable operations may alter primitive/cdata metatables. Upvalue IDs compare shared cells; `upvaluejoin` makes two Lua closures share a cell and rejects C functions or invalid indexes.

## Spec 21

Provide global `bit` and `require("bit")` with `tobit`, `tohex`, `bnot`, `band`, `bor`, `bxor`, `lshift`, `rshift`, `arshift`, `rol`, `ror`, and `bswap`. For ordinary Lua numbers, convert to signed 32-bit two's-complement integers. Bitwise operations accept multiple operands; one operand is an identity, and shifts/rotations mask the distance modulo 32, so negative and very large distances wrap. `rshift` is logical, `arshift` sign-extending, rotations wrap bits, and `bswap` reverses four bytes. Results display as signed 32-bit numbers.

`tohex(x[,n])` returns the low `abs(n)` hex digits, zero-padded; default width is 8, negative width selects uppercase, zero width is empty, and width is clipped to exactly 254 digits. Missing/invalid operands raise argument errors.

For fractional ordinary Lua numbers, the integer conversion used by `tobit` rounds to nearest with ties to even before applying signed 32-bit wrapping: examples include `0.5 -> 0`, `1.5 -> 2`, `2.5 -> 2`, `-1.5 -> -2`, `1.49 -> 1`, and `1.51 -> 2`. When the value is 64-bit integer cdata, operations use all 64 bits, default `tohex` width is 16, shift/rotation distances are modulo 64, `bswap` reverses eight bytes, and the result remains signed or unsigned 64-bit cdata as dictated by the first cdata operand. Smaller integer cdata are sign/zero extended correctly; mixed number/cdata operations and cdata shift counts are accepted. Structs/pointers are rejected where not convertible, and attempting to pass a struct to `bit.tobit` produces a catchable argument error containing `cannot convert`.

## Spec 22

Provide `require("ffi")` and global-compatible FFI behavior for the native x86-64 System V ABI. `ffi.cdef` parses repeated C declarations including fixed-width and standard integer types, signed/unsigned and long-long forms, float/double, `_Bool`, pointers/references, arrays and multidimensional arrays, variable-length arrays (`[?]` and flexible members), functions/function pointers/callbacks, typedef chains, forward/self-referential structs, nested/anonymous structs and unions, enums, bitfields including zero-width separators, `const`/`volatile`, alignment/packing attributes and pragmas, and common calling-convention annotations. Syntax errors and incomplete/unknown types are reported safely.

`ffi.typeof` returns a reusable callable ctype; `ffi.new` allocates zero-initialized cdata and accepts positional/scalar and nested table initializers, partial initialization, VLA element counts, arrays of pointers/structs, and multidimensional layouts. Arrays are zero-indexed. Struct/union fields and pointer dereference/indexing are readable/writable, unions overlap, native padding/alignment applies (`char` 1, `int` 4, `double` and pointers 8), packed objects reduce alignment, 16-byte vectors have size/alignment 16, and `double complex`/`complex` has size 16. Const fields reject writes. Missing members raise an error. Pointer addition/subtraction scales by element size; pointer difference, references alias rather than copy their referent, comparisons, NULL/nil semantics, casts among numeric/pointer types, signed/unsigned reinterpretation, integer cdata arithmetic, complex-value construction/storage, and 64-bit literal arithmetic work. This does not imply arithmetic between complex cdata and ordinary Lua numbers: `2i` has type `cdata`, but `2i * 2` fails with `attempt to perform arithmetic on 'complex' and 'number'`.

## Spec 23

The FFI API includes `ffi.cast`, `metatype`, `gc`, `sizeof`, `alignof`, `offsetof`, `istype`, `typeinfo`, `errno`, `string`, `copy`, `fill`, `load`, `abi`, `os`, `arch`, and `C`. `sizeof` supports types, cdata, arrays and VLAs; incomplete types yield nil. `offsetof` returns byte offset and, for bitfields, bit position/size; a non-aggregate query yields nil. `istype` compares compatible types. Internal `typeinfo(valid_numeric_id)` returns a metadata table and returns nil for an unknown/out-of-range ID. `metatype` is limited to eligible aggregate/complex/vector types, installs indexing/call/arithmetic/comparison/tostring/pairs behavior, and cannot be replaced once protected. `ffi.gc` attaches/removes finalizers only on eligible cdata.

`ffi.string(ptr)` stops at NUL; an explicit length copies exactly that many bytes including embedded NUL. `ffi.copy(dst,src,len)` copies raw bytes, while copying a Lua string without length includes its terminator. `ffi.fill(dst,len[,byte])` defaults to zero. `ffi.errno()` reads the saved native errno; `ffi.errno(n)` sets it and returns the prior value. `ffi.C` resolves declared process/libc symbols and enum constants; `ffi.load` loads named shared libraries and yields an indexable library object. At minimum native calls used for `abs`, allocation/free, memory/string routines, and failing system calls work. Function pointers and Lua callbacks are callable. `ffi.abi` answers platform traits and `ffi.os`/`ffi.arch` identify the host. Cdata tostring includes its ctype and value in stable LuaJIT form; invalid types, members, casts, and finalizers raise catchable errors and never crash. A missing required type argument, such as calling `ffi.typeof()` with no arguments, is a catchable error whose message contains `C type expected, got no value`.

## Spec 24

Provide `require("string.buffer")`. `buffer.new([size[,options]])` and `buffer.new([options])` return an empty userdata buffer; size is capacity, not content length, and invalid/negative sizes error. `#buf` is unread byte count and `tostring(buf)`/`buf:tostring()` returns unread contents without consuming them. `put(...)` appends byte strings, numbers, and objects with valid `__tostring`, without separators; `putf` uses `string.format`; `set` replaces content by retaining a safe copy-on-write reference to a string or cdata region. These mutators return the buffer for chaining. `reset` empties for reuse; `free` releases storage safely while leaving the object reusable.

`get()` consumes and returns all data; `get(n1,...)` returns and consumes successive prefixes; `skip(n)` consumes up to n bytes, including safely beyond the end. Zero is valid and negative lengths error. `reserve(n)` returns an FFI pointer plus available capacity; `commit(n)` adds n externally written/reserved bytes and rejects committing beyond the reservation; `ref()` returns pointer and unread length. `putcdata(ptr,len)` and pointer-based `set` copy exact bytes and validate cdata types. Self-insertion errors. Concatenation among buffer/string/number works without unexpectedly consuming content.

The module and buffer both implement `encode`/`decode` serialization. Round trips preserve nil, booleans, finite/special numbers, strings including binary/Unicode bytes, arrays, hash tables, mixed tables within the nesting limit, and empty tables. Repeated encode/decode cycles and multiple serialized objects in one buffer work; decoding consumes one object and leaves following data. The nesting boundary is deterministic: a root table followed by 99 successive child-table links can be encoded, decoded, and re-encoded through ten cycles, whereas 100 successive child-table links make `encode` raise `too deep to serialize`. Circular references, unsupported objects, incomplete encodings, and malformed encodings likewise raise rather than hanging. `buffer.new` options `dict` (an array of common string keys) and `metatable` (an array of recognized table metatables) are honored consistently by encoder and decoder; the buffer metatable itself is protected.

## Spec 25

Provide global `jit` and modules `jit.opt`, `jit.util`, `jit.profile`. JIT compilation is on by default. At the default optimization level, `jit.status()` returns, in order, the leading boolean followed by exactly `SSE3`, `SSE4.1`, `BMI2`, `fold`, `cse`, `dce`, `fwd`, `dse`, `narrow`, `loop`, `abc`, `sink`, and `fuse`. Consequently default `print(jit.status())` writes these tab-separated values with leading `true`, and a global `jit.off()` changes only that leading value to `false`. `jit.on`, `jit.off`, and `jit.flush` operate globally with no argument and accept a Lua function (or `true`) plus recursive/all-prototype boolean forms; invalid arguments error. The special call `jit.off(true,true)` targets all prototypes rather than global enablement, so an immediate `jit.status()` still begins with `true` and retains the default ordered suffixes. The operations may be repeatedly toggled. Flush clears all traces, a function's traces, or a numeric trace without changing program results.

Expose writable `jit.version`, whose initial string begins `LuaJIT 2.1.`, plus numeric `jit.version_num` and strings `jit.os` and `jit.arch`. Assigning `jit.version = "changed"` succeeds and a later read returns `changed`. Calling `jit.security` with each supported mode `prng`, `strhash`, or `mcode` returns the numeric integer `1` in this executable; absent/unknown modes are rejected. `jit.attach(callback,event)` installs and removes JIT event callbacks.

`jit.opt.start(...)` accepts one-digit numeric levels 0 through 9, `+flag`, `-flag`, bare flag names, and numeric parameters such as `hotloop`, `hotexit`, `maxtrace`, `maxrecord`, and `sizemcode`; separate arguments apply left-to-right. A comma-separated control string is not split: `jit.opt.start("2,+fold,-cse,hotexit=10")` raises `unknown or malformed optimization flag '2,+fold,-cse,hotexit=10'`. Malformed names/numbers and negative values error. Levels select the ordered `jit.status()` suffixes as follows: level 0 has only `SSE3`, `SSE4.1`, `BMI2`; level 1 adds `fold`, `cse`, `dce`; level 2 additionally has `narrow`, `loop`; and levels 3 through 9 have the complete default list above. Thus `jit.opt.start(0)` removes `fold` and `cse`, while `jit.opt.start(2,"hotloop=20")` includes `narrow`. `jit.util` exposes function metadata/bytecode/constants/upvalue names and trace introspection; querying a nonexistent trace returns nil, while invalid arguments error. It also exposes `ircalladdr(id)`: `ircalladdr(1)` returns a Lua `number`, while a non-number argument throws a message beginning `bad argument #1 to 'ircalladdr'` (for a string, the remainder is `(number expected, got string)`). Hot numeric/table/string/closure/FFI loops must compute identically when JIT is on or off. `jit.profile.start(mode,callback)` and `stop` support repeated profiling sessions without disrupting execution. `jit.profile.dumpstack(format[,depth])` requires a string as its first argument and returns a string; `dumpstack("f",16)` succeeds, while `dumpstack(nil,"f",16)` raises a diagnostic containing `bad argument #1 to 'dumpstack' (string expected, got nil)`.

## Spec 26

Command-line JIT control accepts `-jcmd`, `-j cmd`, and `-jcmd=arg,...`. `on`, `off`, and `flush` invoke the corresponding `jit` operation; other names load `jit.NAME` and call its `start` function. Unknown commands exit 1 and write `PROGRAM: unknown luaJIT command or jit.* modules not installed` plus a newline to stderr and nothing to stdout. `-jon` makes the first result of `jit.status()` true and `-joff` makes it false; both retain the complete ordered status-string list specified above. Verbose/dump/profile extension commands may emit their normal diagnostic streams but must not change program semantics.

Optimization options accept `-O`, the one-digit levels `-O0` through `-O9`, `-O+flag`, `-O-flag`, bare optimization names, `-Oparameter=value`, comma-separated settings, and repeated flags; default `-O` selects level 3 and later settings override earlier ones. Levels 0, 1, and 2 produce the respective ordered `jit.status()` suffixes specified in Spec 25, while levels 3 through 9 produce the complete default suffix list. In particular, `-O4 -e "print('never')"` exits 0 and prints `never` plus a newline. Valid controls still execute later chunks/scripts. Malformed forms such as `-O?`, `-O=`, `-O--`, an unknown flag, a malformed number, a negative level, or a multi-digit level exit nonzero. For example, `-Oinvalid` exits 1 and writes `PROGRAM: unknown or malformed optimization flag 'invalid'` plus a newline to stderr, and `-O10` analogously names `10`.

## Spec 27

Although the help text advertises `-b ...`, this packaged executable does not install the external `jit.bcsave`/bytecode-tool modules and therefore cannot list or save bytecode through `-b`. Every `-b` spelling is rejected, including `-bl -e "print('test')"`, `-bs -e "print('test')" output.out`, `-be "print(1)"`, separate `-b -e "print(1)"`, stdin/stdout operands `-b - -`, joined deterministic mode `-bd -e "print(1)"`, and `-bg no.lua`. Each exits 1, writes nothing to stdout, and writes exactly `PROGRAM: unknown luaJIT command or jit.* modules not installed` plus a newline to stderr. It must not fabricate a listing, output bytecode, or create the requested output file. This does not affect in-process `string.dump` and bytecode loading required by Specs 1, 11, and 13.

## Spec 28

Error and boundary behavior is part of the interface. Every library validates required arguments and distinguishes ordinary operational failure tuples from programmer type/arity errors. Error messages need not contain stable memory addresses, but must name the relevant argument/function/type or bad option/member and include the stable phrases required above. Examples include attempts to index nil, call numbers/tables, perform arithmetic/length/comparison on incompatible types, use nil/NaN table keys, mutate const/protected values, read/write closed files, load missing modules/files, and use dead/running coroutines. Protected calls must be able to inspect these errors as Lua strings or original non-string error objects.

Lexer/parser failures from top-level `-e` or file compilation write one newline-terminated diagnostic to stderr and do **not** append `stack traceback:`. The diagnostic begins `PROGRAM: SOURCE:LINE:`, where command-line source is `(command line)`. A file source uses its passed filename only when it fits LuaJIT's chunk-name display limit. The displayed source is at most 59 bytes; an overlong filename is represented by `...` followed by its final 56 bytes. For example, the 61-byte filename `/workspace/eval/case-db6d20121995473b92fba2da089c1603/bad.lua` is displayed as `...space/eval/case-db6d20121995473b92fba2da089c1603/bad.lua`. The following observed command-line cases fix the canonical parser text:

- `syntax error` produces the message body `'=' expected near 'error'`.
- `local x =` produces `unexpected symbol near '<eof>'`.
- `function foo(` produces `<name> or '...' expected near '<eof>'`.
- `local x = "unfinished` produces `unfinished string near '<eof>'`.
- `local x = [[unfinished` produces `unfinished long string near '<eof>'`.
- `if true then print("x")` produces `'end' expected near '<eof>'`.
- `for i=1,10 print(i) end` produces `'do' expected near 'print'`.
- `local x = 0x` produces `malformed number near '0x'`, and `local x = 1.2.3` produces `malformed number near '1.2.3'`.
- `local s = 'test\q'` produces `invalid escape sequence near ''test'`.

The same canonical parser wording and no-traceback policy apply to file chunks, with the displayed file source described above and the line replacing `(command line):1`. For example, a file ending on line 5 inside an `if` opened at line 2 reports `'end' expected (to close 'if' at line 2) near '<eof>'`. By contrast, an unprotected runtime failure writes its diagnostic followed by `stack traceback:` and frames, as specified in Spec 11. Compilation errors returned by `load`/`loadstring` remain return values rather than process-level stderr, also as specified in Spec 11.

All successful ordinary chunks exit 0, syntax/runtime/load errors exit nonzero (normally 1), and only `os.exit` deliberately selects another status. The implementation must not special-case source text or filenames: equivalent programs supplied by `-e`, stdin, source files, loaded modules, reader functions, or generated bytecode have the same language and library behavior.
